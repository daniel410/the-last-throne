## 1. 기본 진입은 가방 하나, 기능은 필요한 순간에 안내한다

2026-10-27 사용자 요청으로 간소화를 반영한다. 9슬롯과 기존 무기·방어구·액세서리/리셋권 판매 정책은 유지한다. 기존 v1의 모든 기능을 펼친 화면은 이전 검토 자료이며 v2를 현재 콘셉트로 사용한다.

- 기본 메뉴 진입은 **가방 하나**다. 기본 화면은 장비/소모품/재료 목록과 선택 아이템의 짧은 비교·장착에 집중한다.
- 현재 캐릭터·9슬롯은 ‘장비 보기’로 펼친다. 유물은 기존 해금 규칙에 따르고, 간소화 때문에 임의 레벨 조건을 추가하지 않는다.
- 무기·방어구·보조·유물은 호환 슬롯을 자동 지정한다. 장신구만 장신구1/2 교체 대상을 선택한다. 좋은 장비 자동 장착은 하지 않는다.
- 첫 비교는 주요 변화와 요구 조건만 보여 주고 전체 옵션/귀속 설명은 ‘상세 보기’, 잠금/검색/정렬/대량 판매는 ‘정리’ 보조 메뉴에 둔다. 불가 이유·판매 보호는 숨기지 않는다.
- 창고는 거점 보관함에서 연다. 가방 화면에서 창고 이동과 수령 대기를 상시 펼치지 않는다. 수령 대기는 미수령 항목이 있을 때만 배지로 표시하고 눌러 목록을 연다.
- 모바일은 목록 → 선택 상세 → 뒤로 흐름, 창고는 가방/창고 탭 전환을 사용한다. PC의 비교 패널을 좁은 화면에 축소해 모두 표시하지 않는다.

60/120칸은 검토용 제안이며 실제 저장/기기 수용 전 확정하지 않는다. TD의 타워/영웅 인벤토리와 RPG 창고를 합치지 않는다. Diamonds/Coins는 지갑이며 칸을 차지하지 않는다. 핵/이름/증거 같은 이야기 진행은 저널/퀘스트 상태에 저장하고 일반 장비와 섞어 판매하지 않는다. 스토리지 용량 판매는 이번에 추가하지 않았다.

가방은 ‘지금 영웅이 들고 있는 것’,창고는 ‘RPG 계정이 거점에 보관하는 것’,수령 대기는 ‘아직 가방/창고로 옮기지 않은 확정 지급분’이다. 수령 대기 수량을 일반 창고 점유 칸으로 표시하지 않는다. 구매 시 자동 장착/리셋권 자동 소비를 하지 않는다.

## 3. 장착·비교·해제 흐름

1. 가방/영웅 장비 탭에서 아이템을 선택한다. 한 번 선택은 상세 열기이며 자동 장착이 아니다.
2. 고정 슬롯은 자동 지정하고 선택 장비의 주요 능력치 변화와 요구 조건을 먼저 보여 준다. ‘상세 보기’를 열면 현재 장비와 전체 옵션·귀속·고유 효과의 득실을 확인한다. 장신구는 교체 대상을 고른 뒤 비교한다.
3. 불가 조건은 ‘Lv5 필요’,‘기사 전용’,‘같은 고유그룹 이미 장착’,‘전투 중 변경 불가’처럼 구체적으로 표시한다. 색 외에 문구/표식을 함께 쓴다.
4. ‘장착’을 확인하면 서버가 현재 소유/위치·요구 조건·슬롯 충돌·계정/캐릭터·전투 상태·아이템 버전을 다시 검증한다.
5. 선택 아이템을 슬롯으로 옮기고 이전 장비를 가방으로 되돌리는 교환을 하나의 논리 거래로 확정한다. 가방 안 아이템을 교체하므로 가방이 꽉 찼어도 교환으로 자리가 유지되면 가능하다.
6. 해제만 할 때는 가방에1칸이 필요하다. 공간이 없으면 이유를 알리고 기존 장착 상태를 유지한다. 계정 창고에서 직접 장착하는 기능은 초기안에서 제외하고 먼저 가방으로 꺼낸다.

장착 중복 요청/연속 클릭은 같은 요청ID를 재사용하거나 최신 버전을 검증한다. 클라이언트 미리보기는 실제 공격력/HP를 바꾸지 않고 저장 성공 후 표시를 확정한다. 장비가 사라지거나 한 인스턴스가 슬롯과 가방에 동시에 존재하지 않아야 한다. 전투 중 변경은 막되 조회/비교는 허용하고 협동 세계를 정지하지 않는다. 고유 능력 발동 중 교체·쿨다운/HP 회복 악용은 거점/전투 상태 검사와 자원 보존으로 막는다.

장신구2개를 비교할 때 교체 대상 슬롯을 먼저 고르게 한다. ‘자동으로 더 좋은 장비’는 초기안에서 제외한다. 총 전투력 숫자 하나보다 물리/마법 공격·방어·HP·속도/치명타·고유 효과의 득실을 보여 주고 실제 계산식을 연결한다. 이미지의+42/120 같은 수치는 예시이며 카탈로그 장비의 확정 성능으로 쓰지 않는다.

## 4. 가방 화면/정리/잠금

상단은 가방 점유/용량과 장비 보기,가운데는 장비/소모품/재료 필터와 카드 그리드,선택 상세에는 주요 비교와 큰 장착 버튼을 둔다. 전체 옵션은 상세 보기,검색/정렬/잠금/선택 판매는 정리 보조 메뉴에 둔다. 창고는 거점 보관함으로 진입하고 미수령 보상은 항목이 있을 때만 배지로 표시한다. 판매는 실제 판매NPC/허용 거점에서만 활성화한다. 전투 중 보관함 이동 버튼은 비활성 상태/이유를 보여 준다.

장비는 인스턴스1개당1칸,회복/리셋권 등 소모품은 동일 종류·귀속/상태일 때99개까지1칸,일반 재료는999개까지1칸을 제안한다. 강화/옵션/귀속이 다른 아이템은 합치지 않는다. 정렬은 표시 순서 변경이며 실제 소유 위치/수량을 바꾸지 않는다. 필터는 숨긴 아이템 수와 점유를 혼동시키지 않는다.

잠금은 판매/분해의 실수 방지 표식이다. 계정 귀속/장착 제한과 다른 개념이다. 잠겨 있어도 장착/해제/창고 이동은 가능하고,대량 판매 후보에서는 제외한다. 신규/장착됨/잠김/요구 미충족/계정 귀속을 서로 다른 문구/배지로 표시한다. 같은 그림의 아이템이라도 instanceId가 다르면 개별 선택한다.

초기 판매 대상은 일반 획득 장비/재료 중 잠기지 않은 미장착·비퀘스트·비유료 품목이다. 판매 전 수량·총Coins·포함 목록을 확인하며 취소는 무변경이다. 유료 아이템/퀘스트 진행·기본 무기 보호 대상/장착품은 판매 후보에서 제외한다. 분해/되사기 가격/기간은 별도 작업이며 구현 전 약속하지 않는다. 서버가 선택 전체를 재검사하고 상태가 바뀌면 최신 목록을 다시 확인하게 한다. 판매가는 아이템 경제표가 정해진 뒤 연결하며 현재 성장표의 총유입에 임의 판매 수익을 더하지 않는다.

## 5. 계정 창고·귀속·아이템 이동

거점의 기존 상자/상점/보관 담당NPC를 통해 같은 저장소를 연다. 왼쪽 현재 영웅 가방,오른쪽 계정 창고,선택 후 넣기/꺼내기 버튼을 둔다. 장비는 1개로 자동 처리하고 스택 품목에만 수량 선택을 연다. 수령 대기는 배지로 접고 필요할 때 별도 목록을 연다. 실제 이동은 버튼 확인/탭으로 가능해야 하고 드래그는 선택 편의 기능이다. 모바일은 가방/창고 탭을 전환하며 선택과 수량을 유지한다.

계정 귀속은 같은 계정의 호환 영웅으로 이동 가능하되 다른 이용자와 거래 불가라는 뜻이다. 클래스 불일치 장비도 창고에는 보관 가능하다. 캐릭터 귀속 아이템이 있다면 원소유 영웅만 꺼낼 수 있고 카드에 별도 표시한다. 계정 공용 수량을 캐릭터 저장본마다 복제하지 않는다. 지급→보관→꺼내기→장착은 같은 instanceId/보관 위치를 추적한다.

재료/소모품 이동은 양의 정수·원본 보유량·대상 스택 여유를 검사한다. 공간이 부족하면 전체 이동을 취소하거나 실제 가능한 수량을 새로 확인받고 조용히 일부만 옮기지 않는다. 두 캐릭터/서버가 동시에 같은 아이템을 꺼내도 한 쪽만 확정한다. 요청ID/아이템 버전/논리 거래 기록으로 동시 이동·재접속 중 중복 복사를 막는다. 구체 DataStore 스키마/원자적 커밋 구조는 구현 사양에서 정한다.

## 6. 가방 가득 참·수령 대기·유료 지급

유료 구매는 서버 영수증으로 계정 지급 기록에 먼저 확정한다. 가방/창고가 가득 차면 **수령 대기**에 남기고 자동 삭제/임의 장착/자동 판매하지 않는다. 이 카탈로그의 대기 구매품에는 자동 만료를 두지 않는다. 일반 퀘스트/전투 보상도 공간 때문에 소실되지 않게 대기 지급으로 보존하되 XP/Coins 수령 기록과 아이템 수령 위치를 분리한다.

수령 대기는 장비를 사용/장착/판매하는 공간이 아니다. 거점에서 가방 또는 창고의 유효 공간으로 받아야 사용 가능하다. 대상 공간·품목·수량과 귀속을 확인하고 성공 시에만 pending grant를 claimed 상태로 바꾼다. ‘모두 받기’는 가능한 확정 항목/남은 항목을 명시하고 일부 수령을 전체 수령처럼 표시하지 않는다. 공간이 없으면 그대로 보존한다. 저장 장애/중복 영수증/재접속은 동일 구매ID/지급ID로 재처리한다.

스탯/스킬 리셋권은 창고/가방/수령 대기 중의 위치가 달라도 보유 자격을 명확히 한다. 초기안은 수령 대기에서는 사용 불가,가방/계정 창고의 지급 확정 권은 거점에서 선택 캐릭터에 사용 가능하다. 확인 전 예상 반환P를 보여주고 아이템1개 소비와 투자분 반환을 같은 논리 거래로 확정한다. 대상 투자0·취소·오류에는 소모하지 않는다. 신규 포인트 배분/장착 변경에 리셋권을 소비하지 않는다.

창고 용량 확장/만료/추가 유료 슬롯은 이번에 확정하지 않는다. 가득 찼다는 이유로 강제 결제창을 띄우지 않는다. 게임 내 실제 상품/권리/지급 코드는 별도 구현 전이며 현재는 기획/콘셉트다.

## 7. 프롤로그·파티·기기별 안내

DS-01은 지급된 기본 무기의 장착됨 표식만 보여 준다. DS-02는 가방 열기→장비 선택→주요 비교→장착 방법만 간편 안내하고, 실제 장착은 선택 행동이다. 9슬롯 전체·잠금/귀속·창고·수령 대기를 한 번에 설명하지 않는다. 잠금은 보관할 장비를 얻었을 때, 창고는 거점 보관함 첫 이용 때, 수령 대기는 실제 미수령 보상이 발생했을 때 짧게 안내한다. 해제/판매/이동/포인트 소비/구매는 튜토리얼 성공 조건이 아니다. DS-04 후 Lv5 유료 장비는 선택 상점 안내이며 Deepwood 입장 조건이 아니다.

플레이어1~4인 각자 인벤토리/계정 권리를 사용한다. 호스트의 장착/보관/초회 수령으로 다른 사람의 데이터를 바꾸지 않는다. 같은 계정의 공유 창고와 다른 이용자의 파티 분배를 혼동하지 않는다. 파티 전리품의 기여/재합류 계약은 성장 문서를 따르고 막타 독점을 요구하지 않는다.
