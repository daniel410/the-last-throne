# 몬스터·보스 공격 패턴·효과·특성 개선 계획

2026-11-05 · TLT-005/027/050/057/061~065/084 · DIR/PLAN/DES · **리뷰·계획 작성 완료 / 모든 신규 패턴은 제안 / 구현·플레이 수용 미완료**

## 1. 목표와 범위

사용자가 보고한 단순한 전투를 개선한다. 적을 알아보고 대응 방법을 선택하며, 잘 대응하면 분명한 공격 기회를 얻도록 만든다. 기준은 소스 `8f488a2bbbd3b77cd9518614b907329e592f1a77`·게임0.75.12와 다섯 에픽의 실제 출현49종(일반27·보스22)이다. [소스 진단·외부 조사](../research/2026-11-05-enemy-pattern-review.md)를 근거로 한다. 이번 작업은 문서만 변경하며 수치·런타임·VERSION·자산·게시를 변경하지 않는다.

현재 핵심 문제는 공통 부채꼴 판정,1→1→2 반복 선택, 동일 추격, 원거리 적의 실제 투사체 부재, 공통 원형 바닥 위험, 공통 공격 VFX다. 이미 구현된 슬라임 분열·자세 붕괴·블록/회피·보호막/기둥·보스 단계·설원 진정 처리는 활용한다. 이 문서는 새 패턴 도입 승인이나 실전 재미 검증을 대신하지 않는다.

유지 계약:

- Deepwood→Frozen Vale→Ember Caldera→Gloamwood→Haunted Graveyard의 본편과 안정ID·퀘스트·보상 정본을 보존한다. 일반27/보스22 분류를 유지한다. DeathKnight를 새 보스로 바꾸지 않는다.
- 일반 웨이브가 끝난 뒤 보스1명만 등장한다. **보스전 중 추가 몬스터/무한 증원 없음.** 영혼·알·토템은 제안상 비보상 위험 장치/투사체이며 몬스터 처치 수·XP·아이템·웨이브를 만들지 않는다. 공격 가능한 장치 도입은 별도 소유/완료 검사를 요구한다.
- 네 클래스 솔로, Selene 미동행, 구매0, 선택 보스 미완료로 필수 공략 가능. 탱커·힐러·특정 원소·동시 발판·강제 점프를 필수로 하지 않는다. 블록·회피·스프린트에 Stamina/새 쿨다운을 추가하지 않는다.
- 인간1~4명, 현재 AI는 파티 전체 최대1명이고 Selene도 포함한다. AI는 별도 의무 표적/퍼즐 인원으로 세지 않는다. 4인+AI 실제 기기 수용은 후속이다.
- 기존 최신 피해·HP·이동/공격 빈도 보정을 임의 취소하지 않는다. 초기 비교는 같은 수치로 수행하고, 패턴별 피해 분배·반격 하한이 필요하면 PLAN 검토와 별도 원정 버전으로 도입한다.
- 설원 보스의 현재10% 진정·비살상 완료 경로와 KingShaman/Veyr 기둥의 순차 솔로 조작을 보존한다. 서사와 충돌하는 강제 처치/영구 구속을 넣지 않는다.

## 2. 공통 전투 문법

공통 역할6종을 만든다: 무리 압박, 측면 기동, 중량 돌파, 거리 유지 사격, 지원 연결, 바닥 제어. 한 적은 주역할1개와 보조 특성1개부터 시작한다. 모든 적에게 이동기·장판·상태 이상을 동시에 주지 않는다.

공통 판정6종은 `cone`, `line`, `circle`, `ring`, `projectile`, `trail`이다. 돌진은 line의 이동/벽 충돌 변형이고 부채탄은 projectile 묶음이다. 타격은 모양·지속·방어 가능 여부를 함께 정의한다. 투사체를 예쁘게 표시하고 판정은 즉시 부채꼴로 남겨 두지 않는다.

| 단계 | 플레이어가 읽을 정보 | 제작 기준·초기 시험값 |
| --- | --- | --- |
| 준비 | 어깨·무기·지팡이·몸통의 고유 자세 | 일반 특수기0.8~1.2초, 보스 강공격1.2~1.8초의 충분한 예고부터 실험. 기존 기술의 예고를 일괄 덮어쓰지 않음 |
| 방향/지점 고정 | 윤곽이 멈추고 짧은 표시가 확정됨 | 특수기의 마지막0.30~0.45초 방향/지점 고정 시험. 이후 목표를 따라 즉시 꺾지 않음 |
| 발동 | 실제 경로·위험 면과 일치한 타격 | 연타는 타격마다 서버 시각·판정·피격 키가 따로 있음. 후속타를 사전 표시 |
| 회수 | 무기 회수·과열·몸통 노출 | 보스 강공격 성공 회피 뒤1.0~1.5초 반격 후보. 기존 속도 보정 후 최종 시간을 측정하고 일반 기본 공격과 별도 예산으로 결정 |
| 복귀 | 다음 행동 선택이 시작됨 | 거리·시야·HP단계·직전 패턴·사용 대기시간·동시 위험 수에 따라 선택 |

위 시간은 모두 시험 제안이며 프레임/지연/모바일 관측 후 확정한다. 기존 BossCombatTuning이 recovery를 다시 줄여 약속한 반격 하한을 없애지 않도록 패턴 최종 회수 시간을 한 곳에서 계산한다. 필요 시 강공격에 `minRecovery`를 도입하되 기존 기본 공격 빈도 계약과 영향 차이를 기록한다.

초기 선택 규칙: 새 보스의 첫 순환은 기본기→고유기→강공격으로 학습시킨다. 이후 유효 후보 중 가중 선택하되 강공격 연속 금지, 이동기 후 즉시 무예고 광역 금지, 같은 고유기 연속2회 이하. 멀어진 적에게는 예고 있는 접근/사격을 사용하고 영구 도주·순간이동 추적·회피 입력을 읽는 반응은 넣지 않는다. 변경할 표적은 예고 시작에 정하고 고정 이후 갈아타지 않는다.

## 5. 효과·특성·가독성 계약

효과는 **준비 동작→위험 윤곽→발동 접점→잔류 여부→반격 상태**의 정보를 전달한다. 공격마다 장식 입자를 늘리는 방식으로 끝내지 않는다.

| 정보 | 시각·음향 제안 | 판정/접근성 기준 |
| --- | --- | --- |
| 막을 수 있는 공격 | 현재 황금 경고 유지+방패 모양/짧은 금속 준비음 | 색 외의 모양과 영문 표시 유지 |
| 방어 불가 | 현재 붉은 경고+깨진 방패 모양/상승 준비음 | 회피·이동 안전 경로 필요. 모든 강공격을 방어 불가로 만들지 않음 |
| 범위·발동 시점 | 외곽선+안쪽 채움 진행, 고리는 빈 중심을 명시 | 서버 shape와 동일 크기/방향, 경사에 접지. 유효한 벽/층을 관통하지 않음 |

영문 가칭 키: `EnemyAttack.Blockable = "BLOCK OR DODGE"`, `EnemyAttack.Unblockable = "DODGE OR MOVE"`, `EnemyAttack.Ground = "MOVE OUT"`, `EnemyState.Exposed = "OPENING"`, `EnemyMechanic.BreakLink = "BREAK THE LINK"`. 반복 설명창보다 짧은 전투 안내를 우선한다. 새 아이콘/패널을 만들 때 TD 공통 룩앤필과 원본 아이콘 적합성을 확인한다. 이번에는 UI/이미지 미리보기를 제작하지 않는다.

상태 이상 초기 후보: Slow는 이동만20~30% 감소·최대2초·비중첩/갱신 상한, Burn/Poison은 최대3초·같은 계열 강한1개만·주기 피해 예산 포함. 실제 수치는 제안이며 첫 원형은 상태 이상 없이 공간 패턴부터 평가한다. Freeze·장시간 Root·Silence·실명·피해 반사·클래스별 속성 면역은 보류한다. 피격 경직 연쇄로 조작이 봉쇄되지 않도록 면역 유예를 공통 설계한다. 정화는 도움이 되되 필수 해법이 아니다.

PixelFX 기존 자산20종과 공유 레지스트리/지역 모션을 우선 재사용하되 신규 패턴에 맞는 소켓·원소·시각 길이를 ART가 확인한다. 이번 소스 리뷰는 신규 자산의 현재 해시·사용권·게시 ACL·기기 적합성을 승인한 감사가 아니다. 도입 전 원본/파생ID·해시·권한·메모리·LOD 기록을 남긴다. Gloamwood 임시 모델은 전신 이동/바닥 예고 원형까지 검증하고 최종 다관절 동작은 모델 교체 게이트로 분리한다.

### 5.2. 플레이어 피격·방어·회피 효과 확장

현재 `CombatService.applyPlayerHit`는 실제 HP감소 때 `K0HurtDamage/MaxHealth/At`를 기록하고, `K0PlayerHitFeedback`는 약한 붉은 화면·신음·짧은 몸 반응을 사용한다. `PixelFXController.renderHurt`는 공통 enemy 효과를 루트 근처에 방출하며, `BattleController`는 방어/회피 결과 문구를 표시한다. 이 기반을 확장한다. 효과가 전혀 없다고 보고하거나, 기존 효과 위에 독립 피격 시스템을 중복 설치하지 않는다. 이번 확인은 코드/기존 증거 열람이며 새 렌더/청음 검증은 아니다.

| 서버 확정 결과 | 플레이어 몸/접촉면 표현 | 로컬 화면·음향·피드백 |
| --- | --- | --- |
| 물리 명중 | 검=짧은 베기선, 둔기=둥근 충격/먼지, 화살·뼈=작은 관통 흔적. 맞은 방향으로 상체만 짧게 반응 | 기존 약한 붉은 테두리/신음 유지, 실제 적용 피해량과 공격 방향 안내. 출혈/절단 표현 없음 |
| 마법 명중 | 위 표의 원소별 접촉 효과+짧은 원소 윤곽. 투사체가 맞은 위치에 표시 | HP감소는 기존 붉은 테두리, 원소는 몸 접점/아이콘으로 구분. 화면 전체를 원소색으로 바꾸지 않음 |

피격 방향은 서버가 확정한 피해원→접촉 지점으로 계산하고, 플레이어 화면 방향 표시는 당시 카메라 기준으로 변환한다. 광역/주기 피해처럼 방향이 모호하면 전방 화살표를 임의 표시하지 않는다. 접촉 위치는 지면/루트 중앙 고정 대신 서버 충돌점 또는 대상 경계에 투영한 유효 점을 쓰고, 방패/보호막 접점과 몸 접점을 구분한다.

연출 강도는 실제 HP감소 비율·타격 유형으로 제한하고 거대 보스의 VFX 크기가 플레이어 화면 전체를 덮지 않게 한다. 기존 화면 불투명도 상한과0.55초 신음 간격은 첫 원형에서 보존한다. 연속 피격은 짧은 구간에 합치되 서버의 개별 피해를 누락시키지 않는다. 데미지 숫자·상태 아이콘·방향 표시는 TD 공통 UI에 맞추며 자기 피격은 우선, 다른 플레이어는 몸 접점만 거리별 축소한다. 카메라 흔들림/컨트롤러 진동은 선택형 후보로 두고 첫 원형의 필수 항목에서 제외한다.

후속 `DamageOutcome` 이벤트 후보: `runId`, `encounterGeneration`, `attackSequence`, `pulseIndex`, `targetId`, `serverTime`, `sourcePosition`, `impactPosition`, `impactDirection`, `element`, `hitType`, `defenseResult`, `healthDamage`, `shieldAbsorbed`, `statusApplied`. 클라이언트가 피해·방어 성공을 주장하지 않는다. 기존hurt속성과 새 이벤트를 함께 받더라도 같은 hit key로1회만 재생하도록 단일 소비자를 둔다. 현재 HP피해 속성만으로는 전부 흡수/완벽 블록 효과를 표현할 수 없으므로, HP0손실 결과도 서버 판정 이벤트로 별도 전달하되 명중 피해와 구분한다.

바닥 위험도 같은 결과 이벤트에 연결하고, 리스폰/진정/전투 완료/원정 교체 후 과거 이벤트는 무시한다. 네 클래스의 자세/장비·보호막과 충돌하지 않게 상체 반응을 합성하며 서버 루트 이동·스턴시간·스킬 취소 판정을 시각 효과 때문에 늘리지 않는다. 신규 타격음은 기존 승인 자산을 우선 검토하고 새 자산 도입 시 원본/권한/음량/동시 재생 상한을 기록한다.

추가 수용 사례: 물리/얼음/불/독/영혼별 명중, 방패 블록·완벽 블록, 보호막 전부/일부 흡수, 회피·빗나감·벽 충돌, DoT·다중탄·동시피격, ForceField·HP0/부활·장비 교체·캐릭터 교체·원정 전환을 확인한다. 같은 확정hit key의 효과1회, HP0손실의 hurt0회, 벽/빗나감의 명중0회, 주기 피해 신음 연타0회가 기대 결과다. 저품질/효과 감소/무음에서도 위험 윤곽·실제 HP감소·방어 결과를 구분하고, 자기/관전자 표시와 이전 빌드 대비프레임·메모리·음향 중첩을 측정한다. 기존0.47.0 피격/0.70.0 PixelFX 기록은 회귀 기준이며 신규 효과 수용 증거로 재사용하지 않는다.

## 6. 다인 전투와 기술 설계 인계

- 서버가 패턴·대상·경로·시작/고정/활성 시각·피해·상태를 결정한다. 클라이언트는 승인된 `attackId`, `sequence`, `shape`, `origin`, `direction`, `serverStartedAt`, `lockAt`, `hitTimes`, `expiresAt`, `effectKey`로 렌더링만 한다. 복제 비용이 큰 매 프레임 속성 갱신 대신 고정 시점·경로를 전달한다.
- 적 피해를 공통 `DamageEvent` 경로로 통합하는 방안을 먼저 검토한다. 기존 `applyPlayerHit`와 `floorHazard`의 방어/회피/장비/실드/파티 자격 차이를 회귀표로 고정하고 의도적 차이만 `blockPolicy`/`dodgePolicy`로 표현한다. 직접 TakeDamage를 새 패턴마다 복제하지 않는다.
- 투사체/돌진은 서버 이동 구간의 연속 쿼리로 벽·높이·플레이어를 검사한다. `Touched`나 클라이언트 접촉 주장을 피해 정본으로 쓰지 않는다. 경사/계단/문/다른 층을 시험하고 막힘·목표 사망·타 원정 이탈 시 취소한다.
- 피해 유일성 키는 `(runId, encounterId, attackSequence, pulseIndex, targetId)`다. 연타는 펄스별1회, 장판은 명시된 주기만 허용하며 입자/중복 RemoteEvent로 재적중하지 않는다. 다중탄의 동일 대상 적중 상한과 콤보 총 피해를 정의한다. 기존1타 피해를3타 각각에 그대로 복제하지 않는다.
- 보스는 동시에1개의 주요 공간 기믹만 수행하고 초기 시험에서는 작은 잔류 위험2개까지 허용한다. 일반 무리는 큰 강공격을 솔로1개/4인2개부터 시험하고 같은 대상에 대한 돌진·구속을 예약해 겹치지 않게 한다. 보스 단독 웨이브에도 잔류 장판과 강공격의 탈출 가능성을 함께 검사한다. 이 상한은 성능/밸런스 확정값이 아니다.
- 원거리 역할의 후퇴는 시야·유효 바닥·leash 안에서 제한한다. 가려진 목표에게 사격하지 않고, 안전한 사격점이 없으면 일반 접근 상태로 복귀한다. 추가 pathfinding 호출을 개체마다 프레임 단위로 만들지 않는다.
- 대상 지정 위험은 살아 있는 인간 참여자만 선정하고 솔로에서1개로 줄인다. 뭉침/산개 동시 요구·한 명 희생·AI 강제 타깃을 쓰지 않는다. 도발은 유지하고, 별도 표적 기믹이 도발을 예외 처리한다면 그 시점/표시를 명시한다.
- 전멸·퀘스트 전환·전투 완료·진정·지역 정리 시 지연 콜백과 탄/장판/장치/상태를 모두 취소한다. encounter generation을 확인해 이전 콜백이 새 원정에 피해를 주지 못하게 한다. 일반 복귀 시 HP유지, 전멸 시 HP복원 계약도 유지한다.
- 후속 구현은 원정 시작 때 고정하는 별도 `combatPatternVersion` 또는 명시적 새 규칙 버전을 사용한다. 현재 규칙1~8과 진행 중 저장 원정을 소급 변경하지 않는다. 전투 도중 버전 전환 금지. 새원정/재도전/재접속/구버전 지원을 설계하고 버전별 회귀·복귀 경로를 갖춘 뒤 켠다.
- 필수 경고 윤곽은 저품질·음소거·효과 감소·메모리 부족에서 유지한다. 입자·잔해·광원은 풀링/거리 제한/품질 조절을 적용하고 화면을 덮는 투명층을 줄인다. 성능 수용은 아래 실측으로 판단한다.

## 8. 검증·관측 계획
