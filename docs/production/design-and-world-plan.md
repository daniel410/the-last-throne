# 디자인·월드 제작 계획

기준일: 2026-10-28 · 담당: 디자인 에이전트 · 상태: 제작 계획, Roblox 런타임 구현 전

문서는 한국어로 작성하고 게임의 UI·대사·아이템·퀘스트·간판·입력 안내는 영어로 제작한다. 기존 한국어 컨셉은 미술 참고 자료로 보존하고 실제 화면에는 영어 텍스트 레이어를 연결한다. 아래의 신규 제작 절차·수용 기준은 이 계획의 제안이며, 원천 문서에 있던 크기·시간·용량도 검증 전 초안이라는 상태를 유지한다.

## 2. 하나의 세계로 보이게 만드는 아트 디렉션

왕관 문양, 청금 배너, 모서리가 분명한 석조, 보라 포탈과 blocky 캐릭터가 TD와 RPG를 잇는다. 재질의 풍부함은 넓은 면·금속 테두리·큰 실루엣에서 만들고, 게임 카메라에서 사라지는 미세 무늬 때문에 메시·텍스처를 늘리지 않는다. 컨셉의 사진 같은 피사계 심도·광택·수많은 풀을 그대로 성능 목표로 삼지 않는다.

전투 화면에서의 시각 우선순위는 적의 준비 동작/위험 경계 → 조작과 플레이어 상태 → 현재 목표/상호작용 → 장식이다. 배경에는 조용한 바닥 면을 남기고, 강한 발광·안개·꽃/눈/재 입자는 교전 중앙보다 원경과 외곽에 쓴다. 아군 주문도 적 예고의 경계·안전 지대를 덮지 않게 한다. 클래스 색, 재화 색, 위험 상태의 의미를 한 가지 색에 겹쳐 맡기지 않는다.

기존 소스에서 확인한 공통 색은 다음과 같다. 신규 지역의 색을 이 표의 미확정 HEX로 발명하지 않고 실제 원본 재질과 대조해 파생 토큰을 등록한다.

| 역할 | 승계하는 TD 값 | 사용 |
| --- | --- | --- |
| 로비 남색 | `#0C1B36` / RGB 12,27,54 | 로비 바로가기·카드 계열 |
| 메뉴 남색 | `#141D2D` / RGB 20,29,45 | 상세 메뉴 표면 |
| 깊은 잉크색 | `#08101E` / RGB 8,16,30 | 수치·설명 뒤 대비 바탕 |
| 로비 금색 | `#FFBE00` / RGB 255,190,0 | 로비 주 행동·강조 |
| 선택 금색 | `#DEB96A` / RGB 222,185,106 | 선택 레일·체크 |
| 은색 | `#9CB9D2` / RGB 156,185,210 | 비선택 레일·보조 장식 |

GothamBold/GothamBlack은 제목·버튼, GothamMedium은 정보문 기준으로 사용한다. 생성 그림에 그려진 글자·아이콘을 잘라 런타임 텍스트나 스프라이트로 쓰지 않는다. 은색 바깥 레일·금색 피팅·남색 내부·같은 닫기/선택/잠금/저장 상태를 공유하되 전투용 셸은 간결하게 만든다. 골드 장식을 정보 칸마다 반복해 가독성을 떨어뜨리지 않는다.

## 3. 영웅·적·장비의 정체성

전신 컨셉은 승인된 TD 초상에서 확장한 그림이다. 얼굴·종족·주 무기·주색은 승인 초상을 먼저 따르고, 후면/하체·망토 흐름은 모델링 검토 대상으로 남긴다. 체형·히트박스·무기 길이를 그림만 보고 확정하지 않는다.

몬스터는 카탈로그의 종별 원형과 무기를 유지한다. Deepwood에 구 미리보기의 Zombie를 가져오지 않고 현행 Cave Slime을 쓴다. 같은 원형의 적/중립/증언 NPC는 무기 내림·자세·대화 아이콘·이름표·타깃 가능 상태를 함께 바꾼다. 친구나 난민을 색만 바꿔 적과 구별하지 않는다. Queen Ice Elf의 비살상 대면, Lich Sovereign 베이르의 항복/원본 전달은 전투와 대화에서 같은 인물로 이어져야 한다.

9슬롯 장착은 몸체를 매번 새 캐릭터로 만드는 시스템이 아니다. 소켓·방어구 파생·무기 프로필을 사용하고 미지원 조합은 이유와 지원 상태를 표시한다. 파란 망토는 별도의 10번째 성능 슬롯이 아니다. 전체 클래스·계열의 상세 무기 호환과 유물 해금은 기획 정의를 받은 뒤 제작한다.

## 4. 지역별 제작 입력과 모듈 전략

모든 지역은 자유 이동/회피·조사·안전 복귀를 위해 TD 환경을 재조합한다. TD의 U턴 적 경로·설치 패드·자동 이동을 RPG 플레이 규칙으로 승계하지 않는다. 석조/포탈/왕국 문양은 공통 모듈, 지형·식생·장치 외형은 지역 모듈, 진행 상태는 시나리오 데이터가 맡는다.

도면의 Roblox 좌표는 Y 위, 북쪽 -Z다. Dawnspire는 SVG `x=X+400, y=Z+400`, Deepwood는 `x=X+900, y=Z+750`, 나머지 3지역은 `x=X+1000, y=Z+800`을 따른다. 전체 지도만 도면 1단위=1stud이고 내부 연결도는 축척이 없다. 사각형의 중심 Y는 평균 지형/높이 예산이며 생성 좌표가 아니다. Deepwood에는 별도 `scenario-data.json`이 없으므로 7개 상세 Markdown과 보상 정본을 함께 사용한다.

5장 이후 지역은 [통합 제안서](../../the-last-throne-rpg-proposal.md)의 전체 서사 순서를 유지하고, 해당 상세 시나리오·맵 입력이 작성되기 전에는 이 표 수준의 제작 준비가 끝난 지역으로 계산하지 않는다. 레이드와 선택 보스 내부도 현재 주동선 도면의 완료 범위에 합산하지 않는다.

## 5. 이동·전투·안전 공간의 핸드오프

기존 명세의 출발값을 아래처럼 승계한다. 모두 블록아웃에서 검증할 초안이며, 장식/적 몸체/기둥을 뺀 유효 바닥으로 측정한다. 실제 공격 반경과 이동 속도를 받은 뒤 조정한다.

| 항목 | 원천의 시험값 | 수용에서 확인할 것 |
| --- | --- | --- |
| 안전 SP | 40×32stud | 4명/허용 동료의 개별 생성, 바닥/출구/카메라 준비, 적/광역/추격 분리 |
| 주동선 | 18~24stud, 장식 뒤 최소 16stud | 근접·원거리·파티가 장식에 막히지 않고 이동/조준/회피 가능 |
| 비전투 샛길 | 12~16stud | 필수 점프·낙하·좁은 외나무다리 없이 합류 |
| 보스 입출구 | 24stud 이상 출발값 | 돌진축 끝 회피, 파티 끼임 방지, 안전실 공격 침투 방지 |
| 경사 | 일반 12도 이하 목표, 짧은 구간 18도 이내 시험 | 전투 바닥은 완만하게 유지, 높이 차는 진입 램프/안전 승강기로 처리 |
| 카메라 | Deepwood 뒤 12~24stud 시작 범위 | 4클래스·조준/방어/회피 시 전경 수관·지붕·기둥이 적과 예고를 가리지 않음 |

DW-02 Ogre 96×96stud와 DW-07 128×128stud, FV-07 여왕 136×128stud, EC-07/HG-07 144×136stud는 각각 해당 맵 명세의 유효 교전장 초안이다. 모든 보스를 같은 프리팹 크기로 찍지 않는다. 기존 최종 던전 시간 목표인 DW 15~20분, FV 15~25분, EC/HG 20~30분은 지역 전체 분량이나 실제 측정치가 아니다.

DS 4개와 4지역 각 7개로 총 32개 SP를 제작 입력으로 추적한다. `Start`, `Continue`, `Replay from Start`, `Rejoin Party`는 서로 다른 상태다. 스토리 사이 기본 이동은 도보, 에픽 이동/안전 귀환은 포탈을 기준으로 하며 SP마다 포탈을 추가하지 않는다. 미로딩 목적지·보스 공격장 한가운데로 보내지 않고 유효 안전 지점/로딩 상태를 제공한다. 공동 재시작은 개인 확인과 파티 동의를 구분한다.

디자이너는 각 구역의 `Visuals / Collision / Encounters / Interactions / SafeSpawns / Connections` 경계와 앵커를 설명하는 핸드오프를 제공한다. 모델러는 원형 키·소켓·축척·LOD 후보와 단순 충돌을 제공하고, 엔지니어는 전투/시야/AI 쿼리·지형 로딩·안전 생성·개인 진행을 연결한다. 시각 메시의 비충돌 설정을 바닥/공격 판정으로 복사하지 않는다. 공유 메시 안에 스토리 저장 로직을 넣지 않는다.

## 6. 영어 UI와 입력별 정보 구조

| 화면 | 정보/행동 우선순위 | 입력별 제작 계약 |
| --- | --- | --- |
| 로비·원정 | 현재 영웅·Coins/Diamonds·다음 목표·원정/계속하기 | 포탈과 `Expedition` 메뉴는 같은 출발 화면을 연다. 권장 레벨·개인 선행·선택 콘텐츠를 구분한다. |
| 영웅 생성 | `Knight / Elf / Dwarf / Mage`·두 계열·클래스 고정 안내 | 성녀를 추가하지 않는다. 영어 계열명 미확정은 용어표에서 정하고 임의 상위 전직명을 확정하지 않는다. |
| 성장 | `STR / DEX / INT / VIT`·남은 포인트·전후 차이·적용/취소 | 스탯 316P와 스킬 79P 예산을 분리한다. 신규 배분·설명 닫기는 리셋권을 소비하지 않는다. |
| 스킬 | 현재 장착 액티브 3+궁극기 1·배울 수 있는 노드·다음 효과 | 기본 공격/방어/회피는 별도다. 터치/패드에서 hover 없이 노드 설명과 선행을 확인한다. |
| 배틀 | 적 예고·HP/클래스 자원·행동·현재 목표·상호작용 | PC/터치/패드 프롬프트를 실제 입력에 맞춰 교체한다. 공통 MP 통합은 디자인만으로 결정하지 않는다. |
| 배틀 메뉴 | 설정/목표/파티·전투 지속·불가 이유 | 협동 세계는 계속 진행한다. 메뉴 열기/닫기 입력이 공격/회피로 새지 않게 하고 거점 전용 재분배를 잠근다. |
| 결과·복구 | 확정 보상/미수령·현재 진행·재도전/귀환 | 성공 전에는 저장/수령 완료를 표시하지 않는다. `Continue`는 다음 안전 목표를 보여 준다. |

PC는 선택/비교/단축키, 터치는 목록→상세→뒤로와 큰 주 행동, 게임패드는 명시적 포커스·확인·취소/뒤로를 제공한다. 드래그·더블클릭·hover를 필수 조작으로 삼지 않는다. 패드 포커스는 탭→목록→상세/주 행동으로 이동하고 팝업 종료 후 원래 선택으로 돌아온다. 동적 목록 갱신으로 현재 선택이 사라지면 다음 유효 항목 또는 목록 제목으로 복구한다.

터치 이동/카메라와 공격/방어/회피/기술의 영역을 실제 양손 조작으로 시험한다. 노치/안전 영역·미니맵·퀘스트·큰 적의 예고가 겹치면 목록/목표를 접고 위치를 재배치한다. PC 화면을 통째로 축소하지 않는다. 장시간 누르기를 요구하는 행동에는 누르기 방식 선택을 검토한다. 버튼 크기·글자 크기·포커스 두께의 수치는 목표 기기에서 측정한 뒤 승인한다.

잠금/선택/불가/희귀도/쿨다운은 색과 함께 아이콘·문구·숫자로 전달한다. 예고는 바닥 경계·방향·적 모션을 함께 사용하고 음향을 꺼도 해석 가능해야 한다. 카메라 흔들림·플래시·이펙트 강도 감소와 자막/텍스트 확대를 검토한다. 옵션을 줄여도 적의 핵심 예고와 상호작용 상태는 남긴다. 출시 화면의 잘림·대비 검수는 영어로 수행한다.

## 7. 장비·가방·창고 v2 구현 기준

[가방 컨셉](../../assets/concepts/2026-10-27-equipment-storage-v2/01-bag-simple.png)과 [창고 컨셉](../../assets/concepts/2026-10-27-equipment-storage-v2/02-storage-simple.png)의 공간/셸을 참고하고, 그림에 없는 동작은 명세와 검토 HTML을 따른다. 큰 기사 일러스트 때문에 모바일 목록/상세 공간을 줄이지 않는다.

1. 기본 진입은 `Bag` 하나다. 장비/소모품/재료 필터, 선택 아이템의 주요 변화와 요구 조건, 주 행동을 먼저 보여 준다. `Equipment`, `Details`, `Organize`는 접혀 시작한다.
2. 슬롯은 정확히 `weapon / offhand / head / body / hands / feet / accessory1 / accessory2 / relic` 9개다. 고정 슬롯 자동 지정, 장신구만 교체 대상 선택 추가. 좋은 장비 자동 장착은 하지 않는다. 가방 진입 후 선택→장착 2회 입력은 기존 명세의 사용성 목표이며 측정 전이다.
3. `Requires Lv…`, `Knight only`, `Unique group already equipped`, `Cannot change equipment in combat`처럼 구체적인 영어 이유를 표시한다. 고유 옵션의 손실도 상세에서 확인한다. 해제·교체·귀속·잠금 상태가 보이게 한다.
4. 가방 내 교환은 꽉 찼어도 공간을 유지하는 경우 가능하고, 해제만 할 때 공간이 없으면 기존 장비를 유지한다. 서버 확인 전 장착 완료/능력치 확정을 표시하지 않는다. 쿨다운/자원 우회는 서버 계약으로 검사한다.
5. `Storage`는 거점 보관함 상호작용으로 연다. 같은 RPG 계정의 캐릭터끼리 공유하며 TD 인벤토리와 합치지 않는다. 직접 창고 장착은 하지 않고 가방으로 꺼낸다. 장비 이동 수량은 1, 스택 품목에만 수량 입력을 연다.
6. `Unclaimed Rewards`는 미수령이 있을 때 배지로 표시한다. 대기 지급품은 거점에서 가방/창고에 받아 사용한다. 부분 수령은 완료/남은 항목을 구분하고 공간 부족·저장 실패에는 보존한다. 이 카탈로그 구매품의 자동 만료·강제 장착·강제 판매는 없다.
7. 잠금은 판매/분해 보호이며 장착·보관 이동은 허용한다. 이야기 핵/이름/증거는 저널 상태로 다루고 판매 목록에 섞지 않는다. Coins/Diamonds는 칸을 차지하지 않는다. 미리보기·오류/취소에는 리셋권을 소모하지 않고, 최종 확인이 서버에서 성공할 때만 해당 권1개와 투자분 반환을 확정한다.

가방 60/계정 창고 120, 장비 스택 1/소모품 99/재료 999는 [현재 데이터](../../assets/concepts/2026-10-27-equipment-storage-v2/inventory-design.json)의 검증 가설이다. 예상 전리품·정리 빈도·재접속·기기 메모리를 측정해 확정한다. 용량 판매를 임의 추가하지 않는다. 이전의 외형 중심 수익화 문구는 v0.22 이후 성능 장비/리셋권 판매 요구로 정렬했다. 최신 [아이템 명세](../items-and-monetization.md)를 제작 입력으로 사용하며 남은 검증은 가격/계수·무료 동등 획득·권리/지급이다. 디자인이 이 값을 단독 확정하지 않는다.

입력별 기본 검사에는 작은 폰·태블릿·PC·게임패드를 포함하고 각 기기의 실제 해상도/안전 영역/그래픽 설정을 기록한다. 모든 공개 화면을 영어로 완료하고 잘림·겹침·포커스 함정·터치 입력 누락을 결함으로 남긴다. 성능 목표·텍스처/삼각형/입자 예산은 소프트웨어/모델링/QA 담당의 실제 측정으로 합의하며, 컨셉만 보고 FPS나 동시 처리량을 보장하지 않는다.

디자인 수용은 다음을 모두 확인한 뒤 서명한다. QA는 실패 재현과 빌드 증거로 판정을 독립 확인한다.

- 첫 이용자가 외부 설명 없이 다음 목표·현재 위험·실패 이유를 파악하고 첫 장비를 교체할 수 있다. 성공률/소요 시간은 먼저 측정하고 제품 목표를 정한다.
- 필수 경로에 클래스별 열쇠·구매·포인트 소비·동료·강제 점프가 없고 모든 클래스 솔로/동료 0으로 본편을 끝낼 수 있다.
- 32개 SP와 추가 보스 전 안전실에서 첫 시작·전멸·이어하기·처음부터·파티 재합류·서버 소멸 후 복구 위치가 지면/카메라/위험에서 유효하다.
- 선택 3곳을 모두 건너뛰어도 각 에픽의 메인/보고/다음 원정이 열리고, 파티장의 길 개방이 다른 사람의 개인 증거/초회 보상/선택을 덮지 않는다.
- 보스 승리 후 기록/본 전환/원본·안식 사이 접속을 종료해도 다음 안전 단계부터 이어진다. 성공한 보스의 재처치를 강제하지 않는다.
- 안개·눈·용암·아군 VFX와 메뉴가 적의 예고를 가리지 않고, 음소거·효과 감소·큰 글자·색 구별이 어려운 조건에서도 필수 정보를 읽는다.
- 9슬롯/고유그룹/가득 찬 교환·해제/잠금/수량/부분 수령/리셋 취소·저장 실패가 실제 서버 상태와 일치하고 영어 안내가 정확하다.
