## 1. 검사 범위

필수 Markdown **21개를 모두 포함**했다. 루트 진입 문서6개, 역할6개, `docs/production/`의 분야 계획/원천/검토/검증8개, 프로젝트 `SKILL.md`1개다. 기획·엔지니어·디렉터의 최종 파일도 포함했고 작성 중이라는 이유로 누락을 제외하지 않았다. `agents/openai.yaml`1개는 별도 YAML 검사 대상이다.

원천 검토표의 기존 상세 문서55개는 현재 파일 해시를 대조했다. 스토리 정본32행·기획 추적표32행·승인 공통 UI9개와 카탈로그·성장 계산 결과도 확인했다. 외부 URL 응답·HTML/Mermaid 렌더링·모든 기존 원문의 전체 링크를 검사한 것은 아니다. 상대링크 검사는 위21개 Markdown에서 출발하는 링크의 대상 존재와 내부 Markdown 앵커를 대상으로 했다.

## 4. 미검증과 다음 수용

이 보고는 문서/정본 데이터 검증이다. **게임 코드·실제 맵/리그/애니메이션·Studio 전투·저장 장애/동시성·상품/영수증·실제 결제·게시된 테스트 Place 왕복·TD 실행 회귀·실기기 성능/부하·사용자 관찰·운영 복구는 검증하지 않았다.** 각 항목은 [QA 계획](qa-and-release-plan.md)의 해당 Q-케이스와 백로그 수용 증거가 필요하다.

TD 파일/XML의 읽기 전용 표본 조사와 최신성 차이는 제작 입력이며 전체 writer/권한/배포 감사 완료가 아니다. 스킬 형식 검사는 전역 설치·자동 발견·향후 세션의 도구 제공을 보장하지 않는다. 공식 Python 검사기의 의존성 실패도 통과로 바꾸지 않았다. 패키지/전역 설정·TD 운영 코드·라이브 저장·상품·Place 게시를 변경하지 않았다.

백로그100개는 모두 Open이다. G0 전체부터 게임 게이트 통과/출시 판단은 별도이며, 다음은 실제 환경·원본·영어/데이터 계약을 확인한 뒤 Deepwood 기사 K0를 구현하고 독립 QA 증거를 만드는 단계다.

## 5. Git 마감·버전·릴리스·LFS 정책 후속 검증

2026-10-28 후속 사용자 지시를 [개발 마감 규칙](../development-workflow.md)·AGENTS·에이전트/스킬·README·계획/백로그·결정표에 연결했다. 작업 완료 커밋/푸시, 빌드의 세 자리 버전, 실제 릴리스의 주석 태그/푸시를 구분한다. 이번에는 게임 빌드/릴리스를 실행하지 않아 `VERSION`과 릴리스 태그를 생성하지 않았다.

- 기존 문서 검증을 다시 실행해 백로그100개·32구간 추적/보상·기존 원천55개 해시·승인UI9개/카탈로그의 정합성을 확인했다. 새 개발 규칙 문서도 상대링크/코드 펜스 검사에 포함한다.
- `.gitattributes`와 저장소 로컬 LFS 필터/훅을 설정했다. 이미지/자산 압축본86경로·중복을 제외한64객체의 인덱스 포인터를 파싱해 각 원본의 SHA256/크기와 모두 대조했다. SVG/JSON/문서/스크립트는 일반 Git이다.
- 초기 스테이징291개 파일에서 가장 큰 일반 Git blob은61,415바이트다. `.DS_Store`·환경 비밀 파일은 스테이징하지 않았다. 기존 Rojo 기본 뼈대는 원문 그대로 보존했고 프로젝트JSON을 파싱했다. 게임 기능/빌드 검증으로 간주하지 않는다.
- 기본 `git diff --cached --check`의 기존 Markdown 끝 두 공백 줄바꿈 및 원본 프롬프트 공백 경고는 보존할 기존 파일의 형식으로 구분한다. 아카이브/프롬프트 원본을 일괄 정리하지 않았다. 포인터/원본 무결성과 별도다.

최종 커밋/브랜치 푸시와 LFS 업로드 성공은 실제 Git 결과로 확인해 작업 보고에 남긴다. 이 정적 기록만으로 아직 실행하지 않은 푸시나 게임 릴리스를 성공으로 표현하지 않는다.
