# 총괄 디렉터 통합 검토

2026-10-28 · 문서 묶음 v0.25 · 검토 대상: [통합 계획](../../plan.md)·[백로그](../../backlog.md)·분야별 제작 계획·원천/결정·역할/스킬

## 1. 판단과 수용 범위

**계획 패키지는 제작의 공통 출발점으로 수용한다. 게임 게이트는 아직 통과하지 않았다.** 기존8장 완성상과 현재32상세구간을 유지하면서, 원천·제작 순서·여섯 역할·의존·수용 증거·미결정을 연결했다. 다음 제작은 Deepwood 기사 K0다. 이번 문서 작성으로 G0 전체·런타임·출시가 완료된 것은 아니다.

| 판정 대상 | 현재 판단 | 근거와 제한 |
| --- | --- | --- |
| 계획 패키지 | 문서 수용 | 확정/제안/미검증, 전체 완성/공개 묶음, 역할/책임/핸드오프가 구분됨 |
| 실행 백로그 | 후속 제작 입력으로 수용 | 기존001~024를 보존한100개 작업, 선행/주담당/수용 조건. **모두 Open**이며 문서 작성으로 자동 완료하지 않음 |
| G0 전체 설계 | 미통과 | 실제 개발/테스트 구조·TD writer 전수 감사·데이터/자산 계약과 남은 결정이 필요 |
| G1~G8 | 게임 수용 미실행 | 전투·맵·저장·결제·Place 왕복·실기기·이용자·운영 증거 없음 |
| 출시 범위/일정/비용 | 미정 | G2~G4 처리량·실제 가용 인력·품질/보수·잔여 범위로 산정 |

검토 원천은 [원천 검토표](source-audit.md), 판정 기준은 [결정표](../decisions.md)·[QA 계획](qa-and-release-plan.md), 역할 지침은 [director.md](../../agents/roles/director.md)다. 이번 수용은 문서의 실행 가능성과 정합성에 한정한다.

## 2. ‘최고’를 검증할 경험으로 바꾸기

순위·매출·유지율을 현재 성과로 말할 근거는 없다. 우선 이용자가 직접 경험하는 아래 결과를 만든다. 숫자는 초기 수용 가설이며 실제 기기/관찰 조건과 함께 고정한다.

| 플레이어가 얻어야 할 경험 | 확인할 결과 | 통합 책임·수용 시점 |
| --- | --- | --- |
| 내 입력에 반응하고 실패 이유를 이해함 | K0 준비/유효/회복과 실제 타격 일치·PC/터치·80/150/250ms. 신규 관찰12명 중10명 목표 이해/큰 공격 대응 목표 | ENG·DES·ART, QA 독립 확인 / G1~G2 |
| 같은 클래스에서 다른 영웅으로 성장함 | 8계열 각각 다른 판단을 요구하는 유효 빌드2개, 동일 투자/장비 조건·솔로/협동 비교 | PLAN·ENG·ART·QA / G3~G4 |
| 지역의 문제를 해결했다고 느낌 | 목표/증거/주민/환경 변화가 연결되고 개인 선택·후일담이 재접속 후 보존됨 | PLAN·DES·ENG / G2, G5 |
| 혼자 완결하고 친구와 더 풍부하게 플레이함 | 비구매·AI0 솔로 본편 결말, 1~4인 공략·이탈/재합류·개인 수령. 8인 레이드는 별도 공략/성능 수용 | 전 역할 / G3~G6 |
| 시간·장비·구매 결과를 신뢰함 | 동일 보상/영수증/리셋·동시 창고/지갑·중단 후 단일 권리로 복구, 불명 로드를0으로 덮지 않음 | ENG·QA / G3, G7 |
| TD의 세계를 직접 모험한다고 느낌 | 같은 원본ID/소비 버전·승인 UI9장·왕좌/포탈/인물 정체성, TD 기능/권리 회귀 통과 | DIR·DES·ART·ENG·QA / G0~G7 |
| 지원 기기에서 위험과 행동을 읽음 | 모바일/PC P95프레임33.3/16.7ms 초기 목표, 영어·색 외 신호·효과 감소·패드/터치 수용 | DES·ENG·QA / G1 기준선, G7 전체 |

대표 구간15~20분과 본편25~35시간/전체50~70시간은 다른 측정이다. 새 이용자12명 관찰은 큰 사용성 결함을 찾는 표본이며 시장 성공의 통계가 아니다. 공개 뒤 지표는 빌드·기기·코호트·관측 기간을 붙이고 원인과 개선을 기록한다.

## 5. 선행·병목과 첫 실행 묶음

현재 선행ID 없는 후보는 **TLT-002/003/021/025/026/030**이다. 문서가 생겼다는 이유로 자동 Ready로 올리지 않는다. 다음 구현 요청 시 실제 원천/환경·파일 소유·결정을 확인해 준비된 항목을 선택한다.

| 묶음 | 책임/협업 | 먼저 끝낼 입력과 인계 |
| --- | --- | --- |
| A. 결정/영어 기준 | DIR·PLAN·DES·QA / 025·026 | 최신 계약·가칭·원천 충돌·영문 용어/키 → 001/027/029 |
| B. 자산/기술/테스트 준비 | ART·ENG·QA / 002·003·030 | 현행 원본/권한·리그 후보·재현 빌드·테스트 격리·기기/증거 → 028/031/032 |

리그/무기 소켓과 서버 판정, 이동/카메라와 전장 유효 바닥은 함께 검증해야 하는 병목이다. 리그 수용 전32단계 외형을 대량 제작하지 않는다. 전투 계약이 바뀌는 동안 다른 지역을 미술 완성으로 밀어붙이지 않는다. 독립적인 후반 서사/영어 초안·원본 조사·지갑 감사는 병행할 수 있다.

별도 병목은 저장/권리와 TD 호환이다. 프로필→아이템/창고→보상/리셋→영수증/공통 지갑→포탈/회귀의 종속 계약이 필요하다. TD에 DiamondWallet/ReceiptDispatcher가 있다는 표본 근거를 재구현0비용이나 모든 서버 호환 완료로 계산하지 않는다. TLT-024 증거 전 공통 소비/지급·포탈을 운영 활성화하지 않는다.

| D-12 공개 범위·일정·인력·예산 | G2~G4 관측 처리량·품질/보수·병목·운영 담당 / DIR·전 역할 | 공개 제공 범위/일정 안내 전 |

미정으로 인한 차단은 그 결정에 의존하는 작업에 붙인다. 최종 제품 결정을 미리 받은 것으로 만들지 않으며, 비교안·원형·측정 등 이미 가능한 작업은 계속한다. 영문 가칭이나 실ID의 임의 확정으로 차단을 숨기지 않는다.

## 7. 제작량·일정·후반/운영 판단

48기술은 애니메이션48개, 216노드는 같은 길이 작업216개, 32전직 단계는 전신 모델32개를 뜻하지 않는다. 기술별 준비/적중/회복·자원·모션/VFX·영어·장착/저장·실패 복구를, 노드별 효과/랭크/선행·조합을, 전직별 시험/권리/외형을 생산 단위로 센다. 같은 원형의 사용 장면은 누적 확장과 신규 제작을 나눈다.

지역은 블록아웃/SP→적/상호작용→보스 패턴→개인/공유 상태→영어/소리→저장/파티→실기기/관찰까지 끝난 단위로 계측한다. 본편 후반/6던전/3레이드·생활/길드·개인 인물5의 부족한 제작 입력은 기존40몬스터나 지도5개에 포함됐다고 가정하지 않는다.

G2부터 `잔여 실제 단위×관측 시간+통합+QA+예상 보수`를 낙관/기준/비관으로 산정한다. 실제 역할별 가용 시간과 의존 경로를 적용하며 단순히 여섯 에이전트로 나눠 달력 기간을 만들지 않는다. 인력/외주·도구·권한·기기·음향·지원/운영 비용을 받은 후 금액을 제시한다. TLT-020은 종합 산정이고 G2/G4의 중간 추정을 막는 선행 조건이 아니다.

첫 공개 테스트와 전체 완성상은 제공 범위를 명시해 따로 판단한다. 전체 서사·클래스 규칙을 임의 삭제하지 않고, 초기 빌드에 없는 콘텐츠는 안내한다. 공개 뒤에는 저장/결제/접속·권리 복구→조작/가독성→계열/경제→신규 콘텐츠 순으로 원인과 영향에 따라 대응한다. 시즌/생활이 본편 필수 일과가 되지 않도록 수급·성장·참여 이유를 관측한다.

운영 리허설은 코드/콘텐츠·영어·자산/공통 UI·스키마/writer·상품 버전을 한 묶음으로 고정해 실시한다. 기능 중지와 데이터 되돌림을 구분하며, 구버전 writer로 최신 공통 잔액을 덮거나 전체 프로필 과거 복원으로 새 권리를 지우지 않는다. 구체 릴리스 판정 패키지는 [QA §10](qa-and-release-plan.md#10-데이터-복구릴리스-판정-패키지)을 따른다.

## 9. 다음 인계

작업 묶음은 **TLT-025/026의 기준 정렬과 TLT-002/003/021/030의 독립 감사·환경 준비**에서 시작한다. 이후 각 선행을 충족한 K0 구현 범위를 엔지니어·디자인·3D가 함께 만들고 QA가 독립 재현한다. 총괄은 그 증거로 G1 확대와 G2 대표 구간을 판단한다.

이 문서는 계획 패키지의 검토 결과다. 실제 TLT 티켓 상태·게임 게이트·공개 전환의 완료는 해당 산출물과 수용 증거가 생길 때 별도로 갱신한다.
