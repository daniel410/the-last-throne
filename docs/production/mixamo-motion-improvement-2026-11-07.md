# Mixamo를 활용한 3D 모델 움직임 개선 계획

2026-11-07 · TLT-032/033/057/084/087 · 상태: 계획 작성, 제작·게임 적용 전

Mixamo에서 확보한 인간형 동작을 Blender에서 기존 모델 체형과 리그에 옮겨, 발 접지·무게 이동·공격 궤적·동작 전환을 개선한다. 먼저 기사와 드워프의 실제 게임 비교를 통과한 뒤 엘프·마법사·Selene·인간형 적으로 확장한다. 다족·사족·무정형 몬스터는 기존 전용 리그와 수작업 모션을 사용한다.

이번 변경 파일은 이 계획서, [조사 기록](../research/2026-11-07-mixamo-motion.md), README/plan/backlog의 연결 문구다. 검증 범위는 근거·기존 코드 연결·문서 링크·Git diff다. 새 애니메이션 제작, 모델 업로드, Studio 변경, 빌드와 게시를 수행한 상태는 아니다. 부모 티켓은 미완료로 유지한다.

## 도구와 적용 경로

Adobe는 Mixamo 자동 리깅과 애니메이션 라이브러리를 이족 인간형 대상으로 설명한다. 극단적 비율, 큰 소품과 추가 팔다리는 자동 리깅에 부적합할 수 있다. 따라서 드워프·갑옷·로브·큰 몬스터는 통과 여부를 먼저 확인한다. [Adobe FAQ](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html)

현재 세션 도구 목록에는 Mixamo 전용 커넥터가 없다. 제작 단계에서는 Adobe 계정으로 Mixamo 웹 서비스를 이용하고 다운로드한 파일을 Blender에서 처리한다. 별도 플러그인 설치나 유료 리타깃 도구 구입은 이 계획의 선행 조건이 아니다.

권장 흐름은 **Mixamo 동작 확보 → Blender 리타깃/보정 → 기존 런타임용 곡선 변환 → Studio 비교 → 실제 기기 수용**이다.

1. **원본 고정:** TD 공유 레지스트리의 원형 ID·현재 SHA·사용 권한을 확인하고 RPG 파생본을 만든다. 기존 본 이름·계층·rest pose·장비 소켓·스케일·전방 축을 기록한다.
2. **동작 확보:** 처음에는 Mixamo 기본 인간형에 모션을 적용해 내려받고 게임 리그로 옮기는 방법을 우선한다. 자동 리깅이 필요한 모델만 소품을 분리한 중립 자세 파생본으로 시험한다. 기존 스킨 리그를 일괄 재생성하지 않는다. Mixamo는 FBX/OBJ/ZIP 업로드와 리깅된 FBX 매핑을 안내한다. [Adobe 작업 절차](https://helpx.adobe.com/creative-cloud/help/mixamo-rigging-animation.html)
3. **후보 기록:** 아래 동작군별 2~3개 후보를 비교한다. 검색어는 탐색용이며 실제 카탈로그 항목명/ID로 확정하지 않는다. 실제 선택명·URL/ID·다운로드일·속도·trim·in-place 유무·파일 해시·샘플률을 manifest에 보존한다. 제공 옵션은 실제 다운로드 화면에서 확인한다.
4. **리타깃:** `Hips/Spine/Head/Arm/ForeArm/Hand/UpLeg/Leg/Foot` 등 소스 본을 실제 타깃 리그에 명시적으로 매핑한다. rest pose 차이·축·비율을 보정하고 IK로 발·손 접촉을 고친 뒤 키로 bake한다. R15 팔꿈치/손목과 단일 팔 구간인 R6는 별도 결과를 만든다. 단순 본 이름 변경을 리타깃 완료로 보지 않는다.
5. **게임용 보정:** 이동은 in-place로 만들고 서버 이동과 이중 이동하지 않게 한다. 회피/돌진의 실제 변위도 기존 이동 코드가 담당한다. 몸통/골반의 시각적 움직임과 물리 루트 이동을 구분한다. 발걸음 주기를 실제 이동 거리에 맞추고 대기↔보행↔달리기↔공격 전환을 확인한다.
6. **내보내기:** 대표 한 클립으로 기존 곡선 샘플러까지 왕복 검증한다. 신규 변환기가 필요하면 별도 경로로 만들며 기존 export 도구에 Mixamo 지원이 있다고 가정하지 않는다. 위치/회전·보간·rest delta·소켓·원본 대비 오차를 기록한다.
7. **런타임 선택:** 1차는 현재 코드 기반 곡선 재생을 유지한다. FBX/AnimationTrack 경로는 별도 표본에서 비교해 채택한다. Roblox는 외부 제작 리그/애니메이션 가져오기를 지원하지만 Mixamo→현재 게임 리그의 자동 호환을 보장하는 것은 아니다. [Roblox 커스텀 캐릭터](https://create.roblox.com/docs/resources/beyond-the-dark/custom-characters)

| 동작군 | Mixamo 탐색어 예시 | 게임에서 추가할 보정 |
| --- | --- | --- |
| 대기·이동 | idle, walk, run, strafe | 직업별 무기 유지, 발 접지·급정지·방향 전환 |
| 기사 | sword slash, sword and shield, block | 현재 3연격 접촉 시각·방패 방향·무기 소켓 |
| 드워프 | axe attack, heavy attack, throw | 현재 손도끼 체형·그립·도끼 회수, 과한 전진 제거 |
| 엘프 | bow idle, archery, bow shot | 시위/화살·조준·pulse별 발사, 실제 활 기술 기준 |
| 마법사·Selene | spell casting, staff, magic | 지팡이/손 소켓·회복/보호 구분·영웅 실루엣 |
| 공통 반응 | hit reaction, dodge, death | 입력/회피 계약·방향 반응·사망 후 초기화 |

해당 무기/기술에 맞는 후보가 없으면 기본 몸통 동작만 참고하고 손·무기·회피를 직접 제작한다. 총기·포격은 드워프 Gunner 이후 스킬에 한해 별도 묶음으로 다루고 기본 도끼를 교체하지 않는다.

기사·드워프 파일럿은 **착수 후 약 2.5~5가동일**에 최초 비교 가능하다는 추정이다. 비인간형 제작을 제외한 표의 순차 합은 **11.5~21가동일**, 비인간형 진단까지는 **12.5~22가동일**이다. 인간형 적 전체 확장과 재작업은 표본 수용 뒤 추가 산정한다. 단계마다 통과한 범위만 채택한다.

## 전투 동기화와 품질 기준

디아블로 IV의 2021년 개발 설명은 무기 동작·공격 영역·피격 방향을 맞추는 원리를 제시한다. 여기서는 **서버가 정한 접촉 시각에 애니메이션을 맞추는 방향**으로 적용한다. 해당 글은 출시 전 설명이며 현행 패치의 타이밍 수치 근거로 사용하지 않는다. [Blizzard 전투 개발 설명](https://news.blizzard.com/en-us/article/23746639/diablo-iv-quarterly-updatedecember-2021)

- 기존 `windup/active/recovery/hitDelay`, 원정 규칙별 공격 시각·피해/사거리/공격속도/쿨다운을 고정한다. 구간별 리타이밍으로 모션을 맞추고 긴 준비 동작으로 조작 지연을 추가하지 않는다.
- 서버가 확정한 시작·타격·pulse를 표시 기준으로 삼는다. 애니메이션 마커/클라이언트 이벤트는 효과음·VFX용으로만 사용하고 피해·발사 횟수를 결정하지 않는다.
- 관절 하나를 기존 절차 모션과 새 AnimationTrack이 동시에 덮어쓰지 않게 한다. 이동·공격·가드·피격의 우선순위/마스크/합성 순서를 명시하고 현재 관절 writer를 조사한 후 연결한다.
- 재입력·연속 공격·이동 중 공격·회피 취소·경직·사망·리스폰·원거리 스트리밍/재등장·늦은 합류에서 이전 포즈/타이머를 해제한다.
- 예고선·발사 원점·도끼/검날·방패·활 시위·손바닥/지팡이 소켓을 실제 게임 카메라와 전후좌우에서 확인한다. 현재 장비8슬롯의 대표 갑옷/로브 조합과 R6/R15 지원 경로를 포함한다.

아래 수치는 파일럿용 **수용 제안값**이며 기존 확정 제품 사양이 아니다. 실패 시 수치를 몰래 완화하지 말고 비교 영상과 오차를 남긴다.

## 버전과 인계

신규 파일 권장 위치는 `assets/animations/mixamo-motion-v1/{source,retargeted,exports}/`, `manifest.json`, `rig-mapping.json`, `clips.json`이다. 검토 증거는 `docs/evidence/mixamo-motion-<실행일>/`에 둔다. 경로는 예정이며 이번 작업에서 빈 자산이나 가짜 ID를 만들지 않는다.

manifest에는 원형/파생ID·출처/권한·소스/출력 SHA256·리그/소켓 버전·FPS/길이·루프/root 정책·공격 구간/pulse 대응·변환 명령/도구 버전·실제 Roblox 자산ID/소유자/허용 Experience·채택 상태·되돌릴 이전 버전을 기록한다. `.blend/.fbx/.glb`와 비교 이미지는 기존 LFS 규칙을 따른다. 원본 다운로드는 로컬에 보존한다.

곡선 경로는 클립/모듈 참조를 이전 채택본으로 되돌릴 수 있게 하고, 애니메이션 자산 경로는 이전 ID와 권한을 보존한다. Roblox 자산으로 게시하는 경우 올바른 Experience 소유자/그룹으로 생성하고 별도로 로드 확인한다. [Roblox 애니메이션 게시](https://create.roblox.com/docs/animation/editor)

다음 담당자는 ART·ENG이며 MX-00의 현행 리그/소켓 동결부터 시작한다. QA는 동일 장면의 전후 비교와 기존 무기/모션 회귀를 맡고, DIR는 파일럿 통과 여부에 따라 확대 범위를 확정한다. 실제 빌드 때만 VERSION을 증가시키며, 문서 계획에는 빌드 버전/릴리스 태그를 만들지 않는다.
