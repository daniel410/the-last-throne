# 모바일 가로 화면 맵·장비 높이 개선안

2026-11-05 · TLT-028/031/052/084 · DES/RES → ENG → QA

상태: 사용자 첨부 2장과 현재 소스에 근거한 **설계 제안**. 런타임 수정·빌드·게시·실기기 수용은 이번 산출물에 포함하지 않는다. 부모 티켓 상태 유지.

## 1. 문제와 원인

사용자 첨부는 각각 1280×591 이미지다. 이미지 픽셀을 Roblox 논리 UI 크기로 환산할 배율·기기·안전 영역 정보는 없어 아래 수치는 코드의 논리 px로 구분한다.

| 화면 | 첨부에서 확인한 현상 | 현재 소스에서 확인한 구조 |
| --- | --- | --- |
| 장비 | 첫 줄은 보이지만 둘째 줄이 잘리고 아래 넓은 빈 공간이 남음. 큰 초상·2단 분류·저장 문구가 공간을 나눠 씀 | `MobileHeroStatsView`는 모든 섹션에서 `height-94`로 내부 스크롤 높이를 잡음. Gear에는 하단 버튼이 없는데도 약46px 추가 예약. 8슬롯은 4열×2행·행 간격78·콘텐츠 높이156. `HeroGrowthGui`는 메시지가 있으면 본문 아래52px을 확보하며 `Hero saved.`도 계속 남음 |
| 지도 | 지도는 중앙의 얇은 띠로 보이고 지역 버튼·설명·긴 내비게이션 버튼이 위아래를 차지함 | `DeepwoodMap.layout`의 short 분기는 지도 상단112px, 높이 `panelHeight-212`. 제목/진행·지역 탭과 하단 약100px을 확보함. 모바일 상세 모드는 지도 최소 폭680을 적용해 일부만 보이는 상태도 가능 |

스크롤 자체의 작동 여부와 첨부에서 보이는 빈 공간 전체의 정확한 원인은 실기기 재현이 필요하다. 다만 빈 하단 예약과 고정 높이 누적은 소스에서 확인된다. 기존 테스트는 8슬롯의 **존재**를 검사하지만 두 행이 처음부터 전부 보이는지는 검사하지 않는다.

## 2. 공통 배치 규칙

- TD 승인 은색·금색 프레임, 파란 버튼, 선택 상태, 영웅 초상·아이템 원본을 재사용한다. 로비/배틀 기본 메뉴의 이미지·배치·기능은 유지하고 상세창만 재배치한다.
- `CoreUISafeInsets` 내부의 실제 사용 가능한 컨테이너 크기로 계산한다. 이미 적용된 안전 여백을 다시 빼지 않는다. Roblox 상단 버튼이나 노치까지 덮어 높이를 확보하지 않는다.
- 모바일 가로는 안전 영역의 폭≥600, 높이≤540을 시작 기준으로 삼되 실제 가용 높이를 우선한다. PC의 낮은 창에서도 같은 부족 공간 보정을 적용한다. 모든 수치는 검증용 초안이다.
- 터치 동작 영역은 최종 표시 크기44×44px 이상, 기본 정보는12px 이상을 시작값으로 한다. 전체 UIScale 축소로 해결하지 않는다.
- 성공 메시지는 상태가 바뀌지 않은 경우 약2초 후 해제한다. `Saving hero...`, 불명 응답, 실패, `RETRY SAVE`는 확인 전 사라지게 하지 않는다. 토스트는 닫기·장비·지도 조작부를 가리지 않는 지정 위치에 둔다.
- 협동 전장은 계속 진행된다. 상세창 입력이 배경 공격/이동으로 새지 않도록 기존 입력 계약을 회귀 검증한다.

## 3. 장비: 큰 초상을 헤더로, 분류를 왼쪽으로

추천 기본 배치는 상단 한 줄 + 왼쪽 분류 + 오른쪽 8슬롯이다.

| 영역 | 제안 배치 | 높이 절약·동작 |
| --- | --- | --- |
| 상단 | 작은 기존 초상32px·`Elf Archer / Lv. 12`, `STATS` / `SKILLS`, 우측 닫기44px | 제목과 상위 탭을 한 줄48px에 배치. 초상은 장식이므로 터치 대상 아님 |
| 왼쪽 | 폭112px 내외, `COMBAT` / `POINTS 0` / `GEAR` / `EFFECTS`, 각44px·간격4px | 기존 가로 분류행을 옆으로 옮겨 오른쪽 콘텐츠 높이 확보. 현재 선택을 텍스트/상태로 표시 |
| 오른쪽 | 4열×2행 8슬롯, 각 행78px 이내·총156px | 슬롯 그림과 영문 이름을 함께 노출. 큰 세로 초상 제거. 가로로 긴 슬롯 프레임의 원본 모서리/아이콘 유지 |
| 하단 | Gear에는 고정 빈 푸터 없음 | `Points`의 확정/취소와 저장 재시도처럼 실제 버튼이 있을 때만44px 행 확보 |

예산 예: 안전 영역750×280 → 바깥 여백 합16px → 패널734×264 → 헤더48px·콘텐츠 간격8px·하단8px → 오른쪽200px. 8슬롯156px이 스크롤 없이 들어간다. 실제 셸 안쪽 여백·테두리를 포함한 엔진 측정으로 확정한다.

선택형 장비 상세를 추가할 경우 슬롯 탭 → 별도 상세 → 뒤로로 이동하고, 8슬롯 위에 긴 설명을 쌓지 않는다. 장비 교체는 기존 가방 흐름/서버 요청을 재사용한다. 장신구 대상 선택·소유권/장착 자격·안전 상태를 바꾸지 않는다. 이번 높이 교정의 필수 범위는 현행 장비 요약8칸이며 신규 상세 기능은 후속 선택 사항이다.

가용 높이가 더 낮아 두 행이 들어가지 않으면 오른쪽만 세로 스크롤하고 마지막 행까지 도달하게 한다. 왼쪽4버튼조차 들어가지 않는 높이에서는 분류 선택을 헤더 선택 메뉴로 바꾼다. 회전/리사이즈 시 선택 분류·스탯 초안·저장 requestId를 보존한다.

## 4. 맵: 한 줄 헤더와 큰 지도, 조작은 오른쪽

- 상단48px에 `WORLD MAP`·현재 지역 선택(`DEEPWOOD` + 펼침)·짧은 진행(`6/7 · 46%`)·닫기를 한 줄로 놓는다. 긴5지역 가로 탭은 지역 선택 목록으로 대체하며 모든 지역/잠금 설명에 접근할 수 있게 한다.
- 지도는 헤더 아래부터 하단 안쪽까지 채운다. 지도 높이 목표는 **패널 높이의65% 이상**, 기본 배치 계산은 `H-68`이다. 패널 높이300일 때 현재88px에서 제안232px로 약2.6배다. 가상 계산이며 실측 개선율은 아니다.
- 지도 오른쪽 폭48px 조작 레일에 `+`, `−`, `FIT`, `YOU`를44px 높이·4px 간격으로 둔다. 지도 폭에서 레일과 간격을 미리 빼 마커/텍스트를 가리지 않는다. 4버튼은188px이므로 지도 높이가 그보다 작으면 두 열×두 행 조작부로 바꿔 겹침을 방지한다.
- 길게 가로지르는 `Navigation Trail: ON`은 지역 선택 목록의 `TRAIL: ON/OFF` 항목으로 옮긴다. 기능과 영웅별 현재 설정은 유지하며 매번 다시 켜지 않는다.
- 초기에는 현재 에픽 전체를 `FIT`으로 보여 준다. 지리 개요에서 작은 글자를 억지로 전부 표시하지 않고 스토리 번호·목표·현재 위치·파티 마커를 우선한다. 지점 선택 시 전체 장소명/상태를 표시하고 `YOU`로 즉시 현재 위치에 돌아간다. 전체 보기에서는 최소폭680을 강제하지 않는다.
- 긴 지역 설명/완료 스토리 목록은 지점 선택 시 상세 패널로 연다. 상세 패널은 지도 일부를 가릴 수 있지만 닫기/뒤로가 항상 보이고 닫으면 지도 중심·확대 상태를 복원한다. 지도 기본 상태의65% 목표와 상세 표시 상태를 구분한다.
- 체크포인트 선택 시에만 기존 `TRAVEL`을 상세 패널에 표시한다. 확인 없이 자동 이동하지 않으며 현재 에픽·완료 여부·안전/서버 자격·이동 실패 안내를 보존한다. 미개방 지역을 선택해도 전체 지역 탐색을 막지 않는다.
- 탭은 지점 선택, 드래그는 지도 이동이다. 손가락 이동이 드래그로 판정되면 터치 종료에서 지점 선택/이동 버튼이 발동하지 않도록 한다. 핀치 확대는 후속 선택이며 1차는 기존 확대 버튼으로 검증한다.

## 6. 수용 기준

1. 테스트 실제 viewport: 640×360, 750×323, 844×390, 932×430, 태블릿1024×768, PC1366×768/1920×1080. 추가로 **안전 영역 루트**750×280/844×300을 주입해 노치/상단 영역 이후의 낮은 높이를 검증한다. 이미지 해상도와 논리 UI 치수를 혼용하지 않는다.
2. 장비: 낮은 안전 영역750×280에서 스크롤 없이8개 슬롯·이름·닫기를 전부 본다. 실제 클립 영역과 조상 클립까지 포함해 검사하며 자식 존재만으로 통과시키지 않는다. 빈 슬롯/긴 이름·4클래스를 검사한다.
3. 지도: 기본 상태 지도 높이/패널 높이≥0.65, 조작 대상≥44px.5지역 선택, 긴 지역명, 완료/잠금 지점, 진행0/7·6/7·7/7, 위치/목표/파티원4명·쓰러짐을 확인한다. 전체 보기에서 현재 에픽 전체 경계가 들어오는지 검사한다.
4. 저장: 성공→안내 해제, 저장 중·실패·응답불명→상태/동일 requestId 재시도 유지. 초안/분류 전환·회전 중 값 유실/중복 저장 없음.
5. 지도 입력: 드래그·확대·FIT·YOU·지역 전환·체크포인트 이동 성공/거절을 검사한다. UI 드래그가 공격/카메라/이동 입력으로 새지 않는지 실제 클라이언트에서 확인한다.
6. PC 기본 배치와 터치 가능한 큰 태블릿의 분기, 닫기 후 HUD 복원, 영어 줄바꿈·읽기 크기를 검증한다. 엔진 좌표 통과와 실제 휴대폰 터치·사용자 수용은 별도 기록한다.

## 7. 대안·검증 기록·다음 담당자

전체 UI 축소는 비용이 작지만 글자/터치 대상도 작아져 보류한다. 전체창 스크롤만 추가하면 맵의 얇은 기본 뷰포트와 장비 하단 예약이 남아 단독 해결책으로 쓰지 않는다. 추천안은 장비의 불필요한 예약 제거 → 세로 공간을 덜 쓰는 재배치 → 맵의 별도 재배치다. 지도 선택 목록/상세 패널의 상태 관리가 추가 비용이며 기존 파티/여행 테스트 재사용으로 회귀를 줄인다.
