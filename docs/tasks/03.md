# 1. 읽는 법과 상태


기존 `TLT-001~024`를 유지하고 `025~100`을 추가했다. 숫자는 실행 순서가 아니다. `P0`는 현재 단계의 기반/보존/공개 차단 위험, `P1`은 핵심 경험·본편, `P2`는 기반 이후의 전체 완성/운영·선택 확장을 뜻한다. P2로 적힌 전체 완성상 기능을 제품에서 제외한 것은 아니다.

담당 약어: **DIR** 총괄 디렉터, **PLAN** 기획, **DES** 디자인, **ART** 3D, **ENG** 엔지니어, **QA** 품질. 첫 담당이 작업 책임자이며 나머지는 협업/검토자다. `선행`의 숫자는 같은 `TLT-` 접두사를 생략한 작업ID이고 쉼표로 나눈 항목은 모두 충족해야 한다. `—`는 외부 작업 의존 없음이다.

현재 `TLT-002/003/004/005/006/007/008/011/014/021/026/028/030/031/032/033/034/041/043/046/047/052`는 **In Progress**다. 0.22.2의 전투·편성과 장비8슬롯·가방/창고·미수령·8종 물약/아이템 버튼은 부분 시험 원형이다. 0.24.1 이후에는 전직 시험 완료에 따른3→4→5 슬롯과 성장 계정 저장 경로가 구현됐으며 정식 퀘스트·게시 저장 수용은 미완료다. TLT-050/061도0.30.4 캠페인 원형 구현으로 **In Progress**다. 나머지는 **Open**이며 완료된 구현 티켓은 없다. 선행 게이트가 끝나기 전에 시작한 G1 작업은 전투 실험장의 부분 원형이며 선행 조건이나 수용 기준을 대신하지 않는다. 관련 기획서나 코드만으로 게임 구현·수용 완료로 처리하지 않는다. TD 원본 몬스터 교체와 일반 오크 추가는 [몬스터 연결 기록](../evidence/k0/td-monster-integration.md) 및 [오크 연결 기록](../evidence/k0/orc-integration.md)으로 추적한다. [전투 피드백 기록](../evidence/k0/combat-feedback.md)에 슬라임 시험 전투와 네 직업 동작을 추가했다. 슬라임 분열·피격 인식과 엘프 자세 조정은 부분 원형으로 구현하며 전체 수용은 별도다. 리뷰 R1/R2의 부분 수정은 [전투 타이밍 기록](../evidence/k0/combat-timing-fix.md)에 연결하며 나머지 회전·포커스·다인 검증은 열린 상태다. [영웅 로비 기록](../evidence/k0/hero-lobby.md)은 세션 전용 네 직업 선택·기본 공격의 부분 원형과 미검증을 추적한다. [플레이어 무기 기록](../evidence/k0/player-weapons.md)과 [K0 작업 기록](../evidence/k0/README.md)에서 원본과 실제 산출물을 확인한다.

상태는 `Open → Ready → In Progress → Review → Done`으로 관리하고, 실제 차단은 `Blocked(이유/해소 담당/조건)`를 붙인다. 선행 완료와 해당 결정/입력 준비를 확인한 뒤 Ready로 올린다. Done에는 빌드/데이터/자산 버전과 해당 수용 증거가 필요하다.

사용자 요청에 따라 완료한 작업은 해당 변경의 커밋과 원격 푸시까지 처리하고 결과를 보고한다. 빌드 버전·릴리스 태그·LFS는 [개발 마감 규칙](../development-workflow.md)을 따른다. 같은 작업을 나눈 역할들의 통합 마감은 한 담당자가 맡는다.

선행ID가 없는 **002,003,021,025,026,030**을 독립 감사·계약·환경 작업으로 병행한다. 025의 결정 충돌 확인과 상위 선행을 계속 진행하며, 부분 원형이 있다는 이유로 자동 Ready/Done 전환하지 않는다.
