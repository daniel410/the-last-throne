## 1. 공간 방향

**거목 중심의 탐험 거점과, 점차 북쪽 깊은 숲으로 들어가는 일곱 구역**을 만든다. 남서쪽의 밝은 보급로에서 시작해 중앙 거목을 만난 뒤 동쪽 감시탑/점령 유적을 돌아 북쪽 뿌리숲과 제단으로 진입한다. 서쪽 폭포 계곡과 북동쪽 절벽은 원경과 경계다. 중심 거목과 감시탑의 실루엣이 방향을 알려 주고, 제단은 처음부터 내부가 보이지 않게 뿌리 능선 뒤에 가린다.

기존 TD 컨셉과 현행 `VisualFactoryForestKit.lua`의 ForestLandmark/ForestTree·PortalGate·WaterfallGorge·SanctuaryTerrace 키트를 참고했다. 거목, 비대칭 수관, 이끼 낀 석조, 회갈색 돌길, 올리브 초지, 폭포 절벽과 보라 포탈을 공유한다. 기존 컨셉의 U턴 경로와 타워 설치 패드는 RPG 자유 이동·전투 공간으로 재구성한다. 원본 키트 전체를 수십 배 늘려 지역을 만드는 방식 대신 원본 스케일을 유지한 모듈 반복과 지형 사이의 연결로 확장한다. 거목 원본 높이48stud는 소스 참고값이며 지도 구역 폭280stud와 혼동하지 않는다.

화면 밝기는 남쪽의 따뜻한 초지 → 동쪽 점령지의 중성 회색 → 북쪽 뿌리숲의 차가운 녹색으로 변한다. 오염 효과는 국소 장치/연결선에 집중한다. 공격 예고를 가리는 어두운 안개와 보라색 전체 화면 효과는 사용하지 않는다. 왕좌의 생명력 기록은 최종 제단 이후에만 보인다.

## 2. 축척·좌표·영역 예산

지도 외곽 예산은 **1,800×1,500stud**다. 빈 숲·원경을 포함하는 제작 초안이며 모든 면을 걷는 열린 월드라는 뜻은 아니다. 실제 제작은 DW-01~02부터 하고 이동 시간·기기 성능·시야 검증 후 전체 길이를 줄이거나 늘린다. 7개 스토리를 7개 Place로 분리한다고 확정하지 않는다. 우선 하나의 RPG Place에서 연결 구역으로 블록아웃하는 안이다.

Roblox 좌표는 Y가 높이, 북쪽이 -Z, 동쪽이 +X다. 지도 SVG의 `x=X+900`, `y=Z+750`이며 한 도면 단위는1stud다. 구역 사각형은 지형 제작 예산 경계이지 최종 벽/콜라이더가 아니다. 내부 도식7장은 별도의 연결도이며 축척이 없다. 구역 사이 도로의 정확한 곡선·폭·길이는 후속 블록아웃에서 정한다.

수치는 충돌 없는 **유효 바닥** 목표다. 장식 바위·기둥·보스 몸체가 차지하는 면적을 빼고 검증한다. DW-02의96×96은 K0 교전 검사 공간을 수용하는 초안이고 지역 전체 크기가 아니다. DW-07의128×128과 두 임시 기둥 사이 간격은 실제 공격 반경을 확인해 조정한다.

일반 주동선 폭18~24stud, 주민/소품이 있는 구간 최소 유효16stud, 비전투 샛길12~16stud를 출발값으로 둔다. 보스 진입/퇴장 구간은24stud 이상을 시험한다. 이동용 경사 목표12도 이하, 짧은 경사도18도 이내에서 실험한다. 필수 경로에 점프·절벽 낙하·좁은 외나무다리를 요구하지 않는다. 한 구역의 표기 Y는 중심 높이이며 모든 바닥이 같은 높이라는 뜻은 아니다. 전투 바닥은 완만하고 진입 램프에서 높이를 바꾼다.

## 3. 스토리 사이 이동과 개방

기본안은 **스토리 내부/사이는 길, 에픽 이동과 안전 귀환은 포탈**이다. 완료할 때마다 갑자기 포탈이 생기는 구성을 피하고 공간의 인과관계로 길을 연다. 아래의 길 개방 연출과 포탈 배치는 이번 설계 제안이며 최종 이동 시스템 구현은 아니다.

| 연결 | 이동 방식 | 개방/유도 연출 | 개인 진행 처리 |
| --- | --- | --- | --- |
| Dawnspire → DW-01 | 원정 포탈 | 기존 석조 보라 포탈, 적과 떨어진 도착 마당 | 원정 자격 확인 후 안전 생성 |
| DW-01 → DW-02 | 자연스럽게 이어진 숲길 | 바퀴 자국·부러진 나무·공터 원경, 매번 문 생성하지 않음 | 조사/위협/종점 완료 뒤 다음 목표 활성 |
| DW-02 → DW-03 | 연결된 보급로 | 주민 대피와 고블린 위협 해제로 안전 확보 | 증언/종점 확인 후 전초기지 이야기 자격 |
| DW-03 → DW-04 | 순찰길 | 에린 임무 수락 후 지도/이정표 안내 | 구매/스탯 소비/동료 영입 불필요 |
| DW-04 → DW-05 | 점령 통로 | 장치 해제·정령 구조 뒤 뿌리 걸림과 경비 통로 해제 | 기록/F 도착 확인, 지름길 별도 해금 |
| DW-05 → DW-06 | 유적 뒤 숲길 | 군벌 격파 후 봉쇄된 진지 출구와 뿌리 통로 확보 | 포로/기록/종점 완료 확인 |
| DW-06 → DW-07 | 뿌리 통로 | 세 장치를 끊으면 제단 앞 연결길 노출 | E 도착 후 재진입 체크포인트 활성 |
| DW-07 외곽 → 보스 | 던전 내부 통로 | 필수 외곽 장치2개 해제 후 제단 문 개방 | 선택 포로 구조 여부와 무관 |
| DW-07 → DW-03 | 귀환 포탈 | 승리 후 기록 확인 공간에서 안전 귀환 | 보스 승리/기록/개인 선택·보고 별도 저장 |
| Deepwood → Frozen Vale | 다음 원정 포탈 메뉴 | 거점/왕도 원정 화면에 다음 에픽 해금 | 어느 복원 선택이든 동일 진입 자격 |

감시탑→거점과 뿌리숲→거점은 단축 보행로를 우선 블록아웃하고, 너무 긴 귀환 동선이면 거점 연결 포탈로 바꿀 수 있다. 제단의 반복 도전은 해금된 안전 체크포인트로 이동하며 보스 공터에 바로 생성하지 않는다.

세계의 열린 길과 개인의 스토리 자격은 분리한다. 친구가 연 길로 함께 이동/지원할 수 있지만 미완료 선행·초회 보상·핵/결말을 건너뛰어 저장하지 않는다. 던전 목표 시작은 자격 있는 구성원 중심으로 확인하고, 뒤처진 참가자는 안전 입장 지점에서 합류한다. 적이 추격 중이거나 바닥 위험이 남은 자리로 순간이동하지 않는다. 파티원 전원에게 호스트의 문 열림을 개인 완료로 전파하지 않는다. 파티 이동/전투 중 귀환 허용 조건·확인 UI·재접속 유예 수치는 별도 시스템 사양에서 확정한다.

## 4. 일곱 구역의 공간 연출

### DW-01 · 고블린 숲길

도착 마당은32×32stud 이상의 무적 생성 여유를 시험하고 적 스폰/투사체 경로를 분리한다. 돌길을 따라2마리씩 두 무리를 만난 뒤 이정표에서 보급 공터와 습지 길이 갈라진다. 습지 출구는 앞으로 합류하며 보급 공터 조사/위협 목표를 건너뛰어 완료할 수 없다. 숲 가장자리는 낮은 뿌리·바위로 자연스럽게 닫고, 중앙 시야를 덮는 거대 수관은 뒤로 옮긴다. F에서는 다음 수레 공터 일부와 먼 큰 실루엣을 예고한다.

### DW-02 · 무너진 수레 공터

수레 잔해 옆 주민 공간과96×96 교전장을 낮은 바위/완만한 단차로 나눈다. 주민은 전투가 시작되기 전에 안전 엄폐로 이동한다. 고블린 교전의 이동 경로와 예고가 읽히도록 중앙을 비우고 주변 엄폐는 시야를 가리지 않는 낮은 높이로 시험한다. 오우거와의 전투는 없다. 전투 뒤 E 조사 흔적을 출구에 두어 역주행 없이 증언을 읽게 한다. 거목을 향한 출구가 전초기지로 이어진다.

### DW-03 · 거목 전초기지

거목 광장을 중심으로 도착/보고, 정비, 에린 면담, 원정 출구를 하나의 짧은 순환으로 배치한다. 핵심 NPC가 계단 위 여러 층에 흩어지지 않게 한다. 훈련 공간은 NPC 대화/포탈과 분리해 공격 효과가 대화에 겹치지 않게 한다. 중심 수정은 지역 성역 소품이며 Dawnspire 왕좌 자체를 복제해 이야기상 같은 물건으로 취급하지 않는다. 적이 거점에 추격 진입하지 않도록 전투 해제 경계를 둔다.

### DW-04 · 버려진 감시탑

탑을 멀리서 식별 가능한 표식으로 쓰되 전투는 바깥 안뜰과 넓은 하부 층 중심이다. 안뜰 뒤 두 장치 공간은 고리형 이동으로 연결하고 중앙 정령 공간으로 돌아온다. 서/동 장치를 혼자 차례로 해제할 수 있으며 발판 동시 조작을 요구하지 않는다. 끝의 기록에서 점령지 방향을 보여 준 뒤 거목 방향 귀환 문을 해금한다. 기둥/난간 뒤 샤먼이 완전히 보이지 않는 배치를 피한다.

### DW-05 · 오크 점령지

부서진 석조 담으로 입구 전투와 포로/막사를 구분한다. 두 가지 길은 보스 앞 안전 구역에서 합류한다. 장식은 전투장 중앙보다 외곽에 두고 돌진축 끝에 회피 여유를 남긴다. 보스 진입 시 전투 범위와 귀환 경계를 알리며 파티원이 벽/계단에 갇히지 않게 한다. 기록은 승리 뒤 열리는 출구 곁에 둔다. Enraged Warlord 구역으로 잘못 이어지는 지름길은 만들지 않는다.

### DW-06 · 오염된 뿌리숲

난민 마을은 공격 표적/적 스폰 없는 작은 안전 주머니로 배치한다. 고블린 주민과 적 샤먼은 표식·자세·행동으로 구분한다. 세 장치를 따라 뿌리 계단이 완만하게 상승하고, 마지막 Ogre 교전 뒤 옛 봉인 연결망이 드러난다. 좁고 높은 뿌리 위로 올라가 싸우게 하지 않는다. 제단 앞 체크포인트와 거목 복귀 연결은 마지막 조사 뒤에 열린다.

### DW-07 · 검은 뿌리의 제단

회랑 뒤 선택 포로 가지와 직접 장치 접근로가 합류한다. 외곽 장치2개와 보스전 임시 기둥2개는 다른 공간/기호로 표시한다. 보스 앞 안전실에서 장치 완료 상태를 저장한다. 보스 공터는 기둥 주변 순환로와 기본 엄폐를 확보하고 바닥 오염 중에도 항상 접근 가능한 안전 영역을 남긴다. 구조 오우거의 도움은 환경 연출1회이며 4인에서 추가 전투AI가 되지 않는다. 승리 후 공격/위험 효과가 정리된 기록 공간에서 핵을 확인하고 거점으로 귀환한다. 개인 자원 배분 선택은 안전한 거점에서 각자 저장한다.

지도에는 위치와 접근선만 넣었다. 선택 보스3곳의 내부 지형/전투/보상 상세 구현은 이번7스토리 맵 디자인 완료에 포함하지 않는다. 절벽은 시각 경계와 별도 충돌/복귀 판정을 두고 장식 폭포 메시의 충돌만 믿지 않는다. 위험 낙하 후 안전 위치로 복귀시키며 재화 손실/유료 부활을 기본으로 붙이지 않는다.

## 6. 공유 자산·기술 제작 기준

- [TD 자산 레지스트리](../assets/shared/td-asset-registry.json)의 원본 모델/메시/텍스처·공통 메뉴/아이콘을 연결한다. 설계 보드의 숫자·선·도형은 도면 기호이며 게임 UI 아이콘을 새로 만든 것이 아니다. 보드는 공통 남색/금색 토큰을 참고한 검토 도구이며 실제 공통 UI 런타임 연결 완료가 아니다.
- Forest kit의 시각 메시와 플레이 바닥·벽 콜라이더를 분리한다. 원본의 `CanCollide/CanQuery/CanTouch=false`를 공격 판정 규칙으로 그대로 복사하지 않는다. 플레이 바닥, 적 이동, 시야 레이캐스트, 공격 쿼리의 역할을 구분한다.
- 같은 몬스터 원형을 유지한다. 주동선 종별 수/레벨은 각 시나리오를 기준으로 하며 지도 때문에 새 정예 몬스터나 Zombie를 추가하지 않는다. 감지·추격·복귀 영역을 소구역별로 두어 서로 다른 스토리의 적이 거점/보스전까지 몰리지 않게 한다.
- `DW-xx/Visuals`, `Collision`, `Encounters`, `Interactions`, `SafeSpawns`, `Connections`의 구역 폴더 구성을 제안한다. 정적 지형과 개인 퀘스트 상태를 분리하고 공유 자산에 스토리 저장 로직을 넣지 않는다.
- 스트리밍 적용을 검토하되 켜짐만으로 기기 성능을 보장하지 않는다. 이동 목표 바닥/충돌이 준비된 뒤 생성하고 부족하면 안전 로딩 상태를 유지한다. 오브젝트 수·메시/텍스처·동시 적/VFX 예산은 실제 모바일 측정 후 정한다.
- 카메라 검증 시작값은 캐릭터 뒤12~24stud 거리 범위다. 원거리 조준과 근접 회피에서 전경 나무/지붕이 가리지 않는지 확인한다. 필요 시 수관 위치 이동/부분 투명 처리를 검토한다. 실제 카메라 수용값은 조작 실험에서 확정한다.

## 7. 제작 순서와 수용 검증

1. DW-01~02만 회색 블록으로 제작해 바닥·길 폭·카메라·고블린 위협과 주민 대피를 검증한다. TD 원본을 복제 재설계하기 전에 기존 모델 연결을 확인한다.
2. DW-03 안전 거점과 DW-04 순환형 장치 공간을 붙여 도보 이동·장치별 복구·귀환 지름길을 시험한다.
3. DW-07 독립 회색 블록으로15~20분 던전 목표를 측정한다. 포로 미구조·네 클래스·궁극기/동료 없이 보스 패턴을 검증한다.

5. 1/2/4인, 서로 다른 선행/선택, 보스 직후 재접속, 미로딩 구역 이동, 모바일 카메라·터치/성능을 검증한다. 부분 진행이 중복 보상이나 선행 건너뛰기로 이어지지 않아야 한다.

현재 산출물은 전체 축척 배치도1장·내부 연결도7장·좌표JSON·선택형 HTML 검토 보드·이 제작 문서다. Roblox Terrain/Part/맵 파일·공통 패키지 배포·실제 이동/전투 구현은 아직 수행하지 않았다.

## 8. 스토리 스타트 포인트 · 재시작·리조인

**사용자 확정 요구: 일곱 스토리마다 스타트 포인트를 만들고 다시 시작/리조인을 지원한다.** 각 구역 A에 `DW-01-SP`~`DW-07-SP`를 둔다. 보드에서는 SP1~SP7로 표시한다. 스타트 포인트는 안전한 입구 마당과 진행 안내 시설이며 모든 입구에 포탈을 새로 만든다는 뜻은 아니다. 연결된 길로 걸어와도 활성화되고, 해금된 스토리를 원정 메뉴에서 골라 진입할 때도 이 위치를 사용한다. 최초 진입 자격은 앞선 시나리오의 선행 조건을 따른다.

| 포인트 | 설치 위치 | 진입 이후 목표 |
| --- | --- | --- |
| DW-01-SP | 도착 포탈 옆 숲길 입구 | 보급로 조사 시작 |
| DW-02-SP | 수레 공터가 보이는 진입길 엄폐 뒤 | 주민 위치 확인·대피 |

각 시작 마당은 유효40×32stud를 출발값으로 시험한다. 4명과 동료가 겹치지 않게 개별 생성 슬롯을 두며, 바닥·카메라·출구가 준비된 후 생성한다. `layout.json`의 SP 좌표는 구역 내 예산 위치일 뿐 확정 지면/스폰 좌표가 아니다. 실제 블록아웃에서 입구 도로와 맞추고 높이/충돌을 검증해야 한다. 적 스폰·추격·광역 피해에서 분리하며 생성 보호가 필요한 시간/해제 조건은 전투 사양에서 정한다.

### 메뉴와 저장 동작

| 기능 | 복귀 위치와 상태 | 영구 데이터 |
| --- | --- | --- |
| 첫 시작 | 자격 확인 후 해당 SP, 새 임무 실행 생성 | 이전 스토리 완료 유지 |
| 이어하기 | 저장된 유효 안전 체크포인트, 없으면 해당 SP | 완료한 조사/장치/보스는 시나리오 복구 규칙대로 유지 |
| 처음부터 다시 시작 | 해당 SP에서 새 실행 생성, 실행 내 목표/적 초기화 | 장비·레벨·영구 완료·초회 수령·개인 결말은 유지 |
| 파티 리조인 | 동일 실행의 안전 합류 체크포인트 | 자신의 자격/진행만 복원, 호스트 완료를 복사하지 않음 |

원정/스토리 메뉴는 TD 공통 패널·버튼·아이콘을 공유하고 ‘시작’, ‘이어하기’, ‘처음부터’, ‘파티 재합류’를 상태에 맞게 표시한다. ‘처음부터’는 현재 실행 진행 초기화를 명시하고 확인한다. 파티에서는 한 명의 클릭으로 전원의 실행을 지우지 않는다. 공동 재시작은 구성원 동의 흐름을 제공하고 거절 시 자신의 별도 실행/거점 복귀를 선택할 수 있게 한다. 세부 투표 시간은 미정이다. 현재 실행과 재플레이 실행의 상태를 섞지 않는다.

### 리조인과 복구 순서

1. 개인 프로필·선행 자격·파티/실행ID·저장된 체크포인트를 서버에서 검증한다. 클라이언트가 보낸 위치로 바로 생성하지 않는다.
2. 동일 서버/실행이 살아 있으면 파티 재합류를 시도한다. 보스전 중에는 공격장 한가운데가 아니라 보스 전 안전 대기 지점에 복귀시키고 다음 안전한 합류 시점에 입장시킨다. 진행 중 교전의 HP/보상 자격을 재입장으로 초기화하지 않는다.
3. 서버/실행이 없거나 유효하지 않으면 새 실행에서 복구 가능한 개인 목표를 재구성하고 유효 체크포인트 또는 SP에 생성한다. 같은 서버 복귀를 무조건 보장하지 않는다. 미확정 교전 HP/소환물은 초기화하고 확정 조사·처치·수령 기록은 보존한다.
4. 보스 승리 확정 후라면 보스 앞 SP로 되돌려 재처치를 강제하지 않는다. DW-05는 기록/출구, DW-07은 안전 기록실 또는 거점의 개인 선택/보고로 이어간다.
5. 반복 요청·연결 끊김에도 실행 전환/보상 수령을 중복 적용하지 않는다. 임시 데이터의 보관 기간, 재합류 유예, 재시도 횟수는 후속 저장/서버 계약에서 정한다.

추가 검증은 각 SP의 첫 시작·전멸·자발적 재시작·앱 종료/재접속, 서버 종료 후 복구, 보스 도중 파티 재합류, 서로 다른 선행의 4인, 재시작 확인 취소, 영구 장비/결말/초회 보상 보존이다. 현재는 요구사항과 설계 반영이며 실제 서버 이동/저장 구현 완료가 아니다.
