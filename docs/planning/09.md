첫 공개 테스트와 정식 공개의 제공 범위는 G2~G4 실측 후 결정한다. 전체 완성상에서 어떤 묶음을 언제 공개할지는 아직 승인되지 않았으며, 현재 계획을 ‘4에픽만 출시’나 ‘8장 즉시 출시’ 약속으로 읽지 않는다. G5/G6 전체 완성 표시는 실제 전체 산출물이 있어야 한다.

## 정식 출시 실행 계획

**첫 작업은 실제 3인 원정의 출발부터 재접속까지 확인하는 것이다(TLT-053).** 비공개 게시 기록에서 확인한 것은 0.115.33의 Dawnspire 입장과 기존 영웅 표시다. 이후 소스 0.115.52의 전투 검증과 실제 3계정 파티 검증은 서로 다른 빌드·조건의 증거다. QA는 시험 시작 시점의 소스 커밋, 빌드 버전, 로비·배틀 Place 버전을 먼저 대조한다. [비공개 게시 기록](../evidence/release-0.115.33-20261121/README.md) · [3인 출발 장애와 남은 검증](../evidence/party-launch-request-20261116/README.md) · [0.115.52 전투 검증](../evidence/hero-mark-impact-20261122/README.md)

### 데이터·이동·상품 수용

- **저장과 보상** — 테스트 계정에서 로드 실패, 지급 직후 저장 실패, 재접속, 두 서버의 동시 요청을 재현한다. 실패 뒤에도 기존 영웅을 다시 열 수 있고 개인 진도·장비·재화가 처리 기록과 일치해야 한다. 서로 다른 키를 갱신하다 중단된 경우도 개별 권리를 대조하고 복구 재시도까지 검사한다.
- **구매** — RPG용 실상품 ID·표시 가격·계정 권리를 대조하고 구매 보류, 같은 영수증 재처리, 다음 접속의 지급 완료를 확인한다. 영수증 한 건당 지급 한 번이 통과 조건이다. 모의 영수증 결과와 실제 상품 검증을 구분하고 비구매 영웅의 완주도 확인한다.
- **Experience 간 이동** — 별도로 게시된 TD와 RPG 테스트 Experience를 실제 Roblox 클라이언트로 개인 왕복한다. 이동 실패와 재입장 전후에 기존 TD의 시작 Place·잔액·권리·진도를 대조한다. 지갑은 각 게임에서 분리 운영하며 공유 전환에는 별도 계약 검증이 필요하다. [이동과 권리 검증](../production/qa-and-release-plan.md)

### 출시 당일과 첫 주

1. **공개 직전 · TLT-093** — 디렉터는 실제 플레이와 일치하는 영문 이름·설명·아이콘·썸네일, 지원 기기, 대상 이용자별 공개 자격과 콘텐츠 등급을 점검한다. QA와 엔지니어는 해당 버전의 접속·저장·구매·이동 지표를 읽을 수 있는지 확인하고 장애 대응자와 이용자 문의 창구를 지정한다. [Roblox 공식 게시 및 공개 요건](https://create.roblox.com/docs/production/publishing/publish-games-and-places)
2. **공개 전환 · TLT-094** — 출시 승인 후 엔지니어가 고정된 소스의 동일한 단일 빌드를 RPG 로비·배틀에 적용하고 두 Place 버전을 대조한다. 정식 공개 설정을 적용한 뒤 QA는 일반 계정의 첫 입장, 파티 출발, 첫 보상, 재접속을 즉시 확인한다. 실제 릴리스에 검증된 소스의 주석 태그와 게시 결과를 연결한다. [단일 빌드와 릴리스 절차](../development-workflow.md)
3. **중단과 재개 · TLT-088·089·094** — 프로필 덮어쓰기, 구매 누락·중복 지급, 본편 입장 차단이 확인되면 디렉터가 공개 확대를 멈추고 엔지니어가 해당 구매·입장 경로를 제한한다. 처리 ID로 영향 계정을 찾아 권리를 복구하고 현재 저장 형식과 호환되는 수정본을 적용한다. QA가 장애 사례와 정상 경로를 다시 통과시키면 디렉터가 재개를 판단한다.
4. **첫날·첫 주 · TLT-095·096** — 첫날은 접속·이동·저장·결제 실패와 문의를 담당자가 함께 대조한다. 첫 주에는 신규·복귀와 기기별 첫 원정 완료율, 다음 날 재방문율, 반복 이탈 구간을 집계한다. 모수·기간·빌드를 함께 적고 가장 큰 진행 장애부터 첫 패치에 배정한다. [운영 백로그](../tasks/11.md)

QA는 각 시험을 문서·정적 검사·Studio·게시 클라이언트·실기기·사용자 관찰로 구분해 해당 작업의 증거 폴더에 기록한다. 디렉터는 후보가 바뀌면 변경 영향이 있는 결과를 다시 받아 판정한다. [현재 수용 상태](../production/current-status.md)
