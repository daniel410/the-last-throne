# TD·RPG 공통 UI와 룩앤필

문서 묶음 v0.25 · 2026-10-28, America/Toronto · 상태: 원본 조사·설계 기준, 런타임 통합 전

## 1. 사용자 결정과 적용 범위

**Throne Defense와 RPG는 메뉴·아이콘·이미지·3D 모델을 최대한 반드시 공유한다.** 같은 기능은 같은 메뉴 컴포넌트와 자산 원본을 사용하고, 로비·배틀·상세 메뉴의 룩앤필도 하나의 기준으로 관리한다. RPG 전용 정보 구조와 입력/전투 기능은 공통 외형 위에 연결한다.

신규 제작 전 기존 공유 자산을 먼저 확인한다. 부족한 RPG 전용 기술·역할·근접 품질 때문에 확장이 필요하면 원본에 연결된 파생 자산으로 만들고 사유를 기록한다. 기존 타워를 플레이어 직업에 억지로 맞추지 않는 결정은 유지한다. 성녀는 지원NPC, 플레이어는4클래스이며 같은 모델을 공유해도 다른 클래스로 전직할 수 없다.

## 3. 색·글꼴·장식·반응의 공통 기준

현재 TD에도 용도별 색이 다르다. 아래 값은 소스에서 확인한 출발점이며 모든 패널을 한 색으로 일괄 칠하는 규칙이 아니다. 공통 토큰으로 이름을 붙여 용도별로 선택하고 개별 화면에서 새로운 유사 색을 만들지 않는다.

| 토큰 역할 | 확인한 TD 값 | 적용 |
| --- | --- | --- |
| 로비 남색 | RGB12,27,54 · #0C1B36 | 로비 카드/바로가기 계열 |
| 메뉴 남색 | RGB20,29,45 · #141D2D | 공통 메뉴 표면 계열 |
| 깊은 잉크색 | RGB8,16,30 · #08101E | 텍스트/아트 대비 바탕 |
| 로비 금색 | RGB255,190,0 · #FFBE00 | 로비 액센트·주 행동 강조 |
| 선택 금색 | RGB222,185,106 · #DEB96A | 선택 체크·공통 선택 강조 |
| 은색 | RGB156,185,210 · #9CB9D2 | 비선택 테두리·보조 장식 |

- 글꼴은 TD의 GothamBold/GothamBlack 제목·버튼과 GothamMedium 정보문을 기준으로 역할별 프리셋을 만든다. 2026-10-28 사용자 지시에 따라 RPG 게임은 영어(en-US)이며 영문 문자열·줄바꿈·숫자 정렬을 실기기에서 확인한다. 한국어는 개발 문서에 사용한다. 생성 이미지에 그려진 글자를 게임 텍스트로 재사용하지 않는다.
- 원본 패널·아이콘의 외곽선/그림자/입체감/여백을 함께 재사용한다. 금속 장식은 외곽과 주 행동에 집중하고 수치표 안의 반복 장식은 줄인다. 배틀은 같은 셸의 간결한 변형을 쓴다.
- 기본·호버·눌림·선택·잠김·쿨다운·저장 중·실패를 공통 상태로 정의한다. 색만으로 구분하지 않고 체크·자물쇠·남은 시간·문구를 병행한다. 장식 함수가 실제 버튼 활성 상태나 서버 자격을 덮어쓰지 않는다.
- TD의 호버 전환0.12초/복귀0.16초는 참고 시작값이다. 클릭/열기/닫기 음향도 기존 소스를 먼저 재사용하고 전투 중 반복음을 제한한다. 세부 움직임과 음향 수치는 수용 전 초안이다.
- 같은 아이콘은 같은 뜻이다. Diamonds는 공통 지갑 의미, RPG Coins는 별도 재화명/표시를 쓴다. 지도·파티·설정·뒤로·닫기·장착·확인 아이콘을 장르마다 새로 그리지 않는다.

## 4. 로비·로비 메뉴·배틀·배틀 메뉴

| 화면 | 공유할 셸/자산 | RPG에 연결할 정보와 동작 |
| --- | --- | --- |
| Dawnspire 로비 HUD | TD 로비 카드·재화·설정·메뉴 버튼 | 원정·영웅·가방·퀘스트·파티 바로가기. 원정은 포탈과 같은 출발 화면으로 연결 |
| 원정 메뉴 | TD 지도 카드·목록·파티/준비 버튼 | 에픽/스토리·권장 레벨·개인 진행·계속하기·재플레이. 포탈/선행 조건은 별도 이동 사양을 따름 |
| 영웅 메뉴 | TD 영웅 초상·상세 창·탭·장비 카드 | 스탯·장비·스킬·전직. 스탯4P/레벨·총316P와 스킬79P를 별도 표시 |

| 퀘스트·파티·설정 | 같은 메뉴 아이콘·목록·상세/닫기/선택 | RPG 목표·선행/보상·동료 편성·입력·음향·접근성 |
| 배틀 HUD | TD 자원바 셸·영웅/적 초상·상태 아이콘·메뉴 버튼 | 생명력·현재 확정한 클래스 자원·목표/미니맵·장착 스킬3개·첫 전직 후5개와 궁극기 슬롯(미정)·공통 공격/블록/회피/스프린트 |

| 결과/보상/레벨업 | TD 결과 프레임·보상 카드·알림 | 획득 장비/재화·레벨·미배분 포인트·재도전/거점 복귀 |

로비에서는 세계와 다음 행동이 보이고, 메뉴에서는 현재 선택과 적용 결과가 보이며, 배틀에서는 적의 예고와 조작이 먼저 보인다. 창의 기본 제목/탭/닫기/하단 주 행동 위치는 일관되게 유지한다. 모바일에서는 재배치하며 글자/터치 영역을 일괄 축소하지 않는다.

배틀 메뉴를 열어도 협동 세계 전체를 일시정지시키지 않는다. 전투 중 스탯/스킬 재분배를 허용하는 UI를 추가하지 않는다. TD의 웨이브·배속·타워 구매/설치 동작은 RPG 기본 배틀 HUD에 넣지 않는다. 공통 HP/MP 정책을 이 디자인 작업만으로 변경하지 않는다.

## 5. 메뉴·아이콘·이미지·3D 공유 운영

| 계층 | 공유 단위 | 관리 방식 |
| --- | --- | --- |
| 메뉴 | 패널·탭·카드·버튼·스크롤·툴팁·확인창·알림 | 한 공통 컴포넌트 원본, 장르별 데이터/행동 어댑터 |
| 아이콘/이미지 | 아틀라스·영웅 초상·재화·장비/몬스터·9-slice | 공통 자산 키와 기존 Roblox 이미지ID·영역 정의를 참조 |
| 3D | 캐릭터/무기·몬스터·왕성/숲·왕좌/포탈·재질 | 동일 원형 모델·메시·텍스처ID를 참조, RPG 리그/충돌/소켓/LOD/행동은 파생 설정 |
| 규칙/저장 | 장르별 상태·요청·권한·전투/성장 데이터 | 화면 공통화와 별개로 기존 데이터 계약 유지 |

공유 컴포넌트의 단일 소스를 버전으로 고정해 양쪽 프로젝트가 소비하는 구조를 목표로 한다. 장르별 상태/이벤트를 공통 컴포넌트에 주입하고, TD 컨트롤러 전체를 RPG에 복사하지 않는다. 기존 StatusWindowArt에도 TD 전용 웨이브/자동 시작 문구가 있어 범용 렌더와 TD 동작의 경계를 먼저 분리해야 한다. 실제 패키지 경로·배포 방식은 소스 구조 작업에서 정한다.

같은 자산의 새 ID 재업로드·수동 복사 후 별도 수정은 기본 제작 경로로 삼지 않는다. 앞서 만든 컨셉 폴더의 PNG 복사본은 검토용 스냅샷이다. 게임의 런타임 원본이 각각 독립했다는 뜻이 아니다. 기존 Restricted 자산은 같은 Experience의 대상 Place에서 실제 로딩을 검증하고, TD의 운영 로딩과 권한을 보존한다.

공통 버전 변경은 먼저 TD/RPG 테스트 빌드에서 비교한다. 한쪽 게임의 출시가 다른 쪽의 즉시 갱신을 강제하지 않게 소비 버전을 기록한다. 신규 자산이 필요할 때는 원본 키·파생 사유·변경한 부분·사용처·검증 상태를 함께 등록한다.

## 6. 현재 컨셉의 위치와 다음 작업

2026-10-27 사용자가 v2 컨셉 방향을 승인했다. [승인 기준 기록](../assets/concepts/2026-10-27-shared-ui-v2/approved-baseline.json)의 최종9개 이미지를 후속 UI 제작의 시각 비교 기준으로 사용한다. 승인 범위는 컨셉 방향이며 실제 구현·표시 예시 수치·실기기 수용은 별도다.

[v2 공통 UI 갤러리](../assets/concepts/2026-10-27-shared-ui-v2/index.html)에 TD 실제 아틀라스 기반 공통 보드와 로비HUD·로비 메뉴·배틀HUD·배틀 메뉴·스탯·스킬·영웅 생성·원정 메뉴의 신규9개 시안을 모았다. 모든 화면에 동일 보드를 참조 입력으로 사용했고 기존 영웅/NPC5·환경3·몬스터10 이미지는 변경 없이 유지했다. 생성 이미지의 아이콘은 원본을 참조한 재현이며 실제 스프라이트 배치나 공통 라이브러리 연결은 아니다. 출처·수정 이력·표시 수치의 범위는 [제작 메모](../assets/concepts/2026-10-27-shared-ui-v2/README.md)를 따른다.

| 현재 산출물 | 통일 작업 |
| --- | --- |
| Dawnspire 전경 | 월드 정체성 기준으로 유지. HUD/메뉴 공통 레이어는 별도 제작 |
| 영웅 선택·스탯 이미지 | 실제 공통 카드·버튼·닫기·글꼴·여백으로 정합화 |
| 스킬트리 | 공통 프레임/툴팁 위에 RPG 전용 노드·연결·자격 표시 구성 |
| 전투 HUD | TD 배틀 바/아이콘 원본 적용, 터치 안전 영역·가드/회피·카메라 겹침 검증 |
| 원정/배틀 메뉴·결과창 | 원정/배틀 메뉴는v2 시안 작성. 결과창과 기능 연결은 후속 제작 |

원본 레지스트리/공유 경계 문서와 공통 보드·짝지은 시안까지 작성했다. 다음 작업은 시안 피드백 반영 → 범용 컴포넌트 분리·RPG 어댑터 → 기존 자산ID/아틀라스/모델 연결 → 실제 기기 비교다. 실제 모듈 분리/연결은 완료 항목이 아니다.

## 7. 수용 기준

- 동일 기능의 아이콘·자산 키·패널 셸·버튼 상태가 TD/RPG/로비/배틀에서 일치한다. 장르 고유 기능이 없는지와 새로운 이름의 유사 원본이 생겼는지 확인한다.
- 승인된 영웅 초상과 모델 원형·무기·종족 색을 대조한다. 메뉴 이미지와 실제 모델, 로비와 배틀에서 다른 얼굴/복장으로 바뀌지 않게 한다. 신규 파생은 추적 가능해야 한다.
- 작은 폰·태블릿·PC·패드에서 한국어/영어·큰 글자·색각/이펙트 옵션을 비교한다. 가독성·터치·포커스·이전 화면 복귀·값 보존을 실제 입력으로 확인한다.
- 배틀 메뉴 진입/닫기 때 입력이 전장으로 새지 않고, 전투 중 적용 불가/저장 중/실패가 정확히 표시돼야 한다. 파티 전체 정지나 클래스 변경을 UI로 암시하지 않는다.
- 공통 자산이 목표 Place에서 로딩되는지, 모듈 버전 변경이 기존 TD 메뉴/결제/선택/저장 상태에 회귀를 만들지 않는지 확인한다.

현재 완료 범위는 원본 조사·공유 레지스트리·룩앤필/화면 기준 문서와 v2 공통 보드/화면 시안9개다. 실제 공통 라이브러리 추출, RPG UI/3D 연결, Studio/게시/모바일 플레이 검증은 아직 수행하지 않았다.

## 장착·가방·창고 화면 확장

[상세 기획](equipment-bag-and-storage.md)과 [신규 콘셉트/동작 보드](../assets/concepts/2026-10-27-equipment-storage-v1/index.html)를 추가했다. 장비9슬롯/비교·캐릭터 가방·계정 창고/수령 대기를 같은 메뉴 문법으로 연결한다. 생성 이미지의 아이콘/텍스트를 원본으로 채택하지 않고 TD atlas/공통 컴포넌트와 확정 데이터를 실제 구현에 연결한다. 이전 승인 UI를 덮어쓴 작업은 아니다.
