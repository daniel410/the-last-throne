## 1. 제작 운영 원칙

[공통 UI/룩앤필](shared-ui-and-look-and-feel.md)에 따라 TD와 메뉴·아이콘·이미지·3D 원본을 공유한다. 원본 레지스트리 → 공통 컴포넌트 보드/상태표 → 로비HUD/로비 메뉴/배틀HUD/배틀 메뉴의 통일 시안 → 버전 고정된 공통 소스와 장르 어댑터 → 실제 기기/TD 회귀 비교 순으로 진행한다. 이 문서 추가는 실제 컴포넌트 분리·연결 완료를 뜻하지 않는다.

전체 서사와 최종 경험을 먼저 설계하고, 그 경험을 검증할 대표 구간부터 구현한다. 내부 시연 구간은 전체 게임을 줄이는 출시 약속이 아니다. 완성상은 프롤로그·8장·에필로그, 4클래스·클래스별2전직 계열, 6던전·3레이드, 동료·균열·수호전·생활·길드다. 선택형 PvP와 대형 확장은 별도 후속 게이트다.

2026-10-28 사용자 결정에 따라 The Last Throne은 TD와 분리된 독립 Experience로 공개한다. RPG 소스·공개 페이지·저장은 별도로 개발하며, 기존 TD의 잔액·구매/수령 기록·성장·복구는 변경하지 않는다. 공통 Diamonds는 외부 서버 권위 지갑·양쪽 영수증 조정·복구 검증이 끝난 뒤에만 별도 범위로 제공한다. 클래스 고정·두 전직 계열·레벨 전직·스킬트리는 유지한다.

초기 개발의 가장 큰 위험은 전투 품질을 확인하기 전에 콘텐츠 수를 늘리는 것이다. 이동·피격·회피·방어·AI·저장이 불안정하면 같은 결함이 모든 직업과 던전으로 복제된다. 공통 시스템을 먼저 검증하고, 실제 제작 시간으로 잔여 작업을 추정한다.

기획·콘텐츠·미술·엔지니어링·QA는 책임 분야를 뜻한다. 현재 해당 인력이 배정됐거나 별도 에이전트가 작업 중이라는 의미는 아니다. 이 문서는 구현·게시·업로드를 실행한 결과가 아니다.

관련 상세 설계는 [Deepwood 지역](deepwood-region-design.md)과 [동료/성녀 지원](companions-and-support.md)을 따른다. Deepwood는 주동선7지점·선택3구역이며 필수 보스2/선택 보스3을 분리한다. 성녀 지원AI·모션·대사·교단NPC는 플레이어 기술/노드 예산 외의 별도 작업량이다.

## 2. 완성상 제작량과 산정 단위

| 지속 콘텐츠 | 균열·수호전·보스 추적·시험 | 반복 규칙·변수·목표 보상·운영 비용 |

이 범위는 작은 단독 프로토타입의 작업량이 아니다. 기존3D 모델을 공유해도 리깅·애니메이션·새 AI·퀘스트·서버 검증·모바일 최적화가 남는다. 자산 재사용으로 줄어드는 시간은 실제 후보별 채택/보수 기록으로 계산한다.

직업의 전투 요구를 먼저 정하고 자산별 직접/부분 재사용·NPC/지원 활용·신규 제작을 판단한다. 모든 전직에 대응하는 TD 타워가 있다고 가정하지 않으며, 신규 직업 모델·무기·모션의 부족분을 별도 작업량으로 산정한다. 재사용률 자체를 완료 기준으로 삼지 않는다.

G1~G3는 일부 독립 작업을 병행할 수 있지만 선행 게이트를 통과한 것으로 간주하지 않는다. 예를 들어 임시 레벨을 넣은 전직 화면 시연은 전체 저장·보상·실기기 검증 완료가 아니다.

공개 테스트는 구현된 범위를 정확히 밝히고 진행한다. 공개 출시의 콘텐츠 묶음과 날짜는 G2~G4 제작/검증 결과로 산정한다. 원안의 전체 완성상과 공개 빌드의 실제 제공 범위를 구분하며, 미구현3레이드나8장을 출시 완료로 안내하지 않는다.

### 기사 전투의 첫 구현 단위

[기사 전투 상세 명세](knight-combat-spec.md)에 검·방패·강철기사/성기사 기술과 K0~K4 작업 묶음을 작성했다. **명세 작성 완료, 게임 구현/실험 미착수** 상태다. 첫 제작·전투 검증 맵은 Deepwood다. 다음 구현은 Deepwood 공터에서 K0의 이동·3연격·방어/회피·자원/자세·고블린/오우거이며 TLT-002/003의 환경·자산 선행 확인 후005~008의 기사 부분으로 진행한다. K2의 임시 계열 체험을 전체 전직/저장 완료나 G1 전체 통과로 간주하지 않는다.

## 5. 일정과 비용 산정

시작일·출시일·주 단위 약속은 현재 확정하지 않는다. G2 대표 구간에서 아래를 실제 작업일로 기록한다.

- 캐릭터 원형: 리그 보수·기본 모션·무기·기술1개·터치 조작까지의 시간.
- 적 원형: 외형 채택·행동·예고·피격·판정·초기화까지의 시간.
- 보스: 패턴1개·단계 전환·솔로/협동·VFX/음향·재도전까지의 시간.
- 지역: 모듈 키트·동선·조명·스트리밍·사건·기기 성능까지의 시간.
- 퀘스트: 상태표·대사·보상·분기·재접속·파티까지의 시간.
- 전직/트리: 계열의 시험·기술·노드·외형·저장·검증까지의 시간.

산정은 `잔여 단위 수 × 관측 단위 시간 + 통합/현지화/QA/보수`로 한다. 공유3D 모델은 직접 재사용·부분 변형·NPC/지원 활용으로 나누고, 적합한 원본이 없는 신규 제작과 기존 원본의 재제작을 별도 산정한다. NPC로 활용한 타워가 플레이어 직업의 모델 제작까지 대신한 것으로 계산하지 않는다. 서로 다른 책임 분야의 시간을 단순 합쳐 달력 기간으로 말하지 않고, 병렬 가능성·병목·실제 가용 인력을 함께 계산한다.

비용은 실제 견적 단가·월 가용 시간·음향/애니메이션 외주·도구·테스트 기기·운영 비용을 받은 후 계산한다. 범위 변경이 생기면 전체 서사와 클래스 규칙을 지킨 채 작업 방법과 단계 배치를 먼저 조정하고, 실제 제공 범위 변경은 기록한다.

## 6. 품질 검증 계획

### 6.1 새 이용자 관찰

G2와 첫20분 완성 시 각각 신규 이용자12명 이상을 초기 관찰 표본으로 제안한다. PC/터치·솔로/친구 참여를 나눠 기록한다. 이 표본은 시장 성공을 예측하는 통계가 아니라 큰 이해/조작 결함을 찾기 위한 제작 기준이다.

| 질문·측정 | 초기 통과 기준 제안 | 실패 시 개선 |
| --- | --- | --- |
| 다음 목표와 귀환을 이해하는가 | 12명 중10명 이상이 직접 안내 없이 첫 원정 완주 | 목표 문구·지도·NPC 동선·입구 연출 |

### 6.2 클래스·전직·스킬트리

1. 4클래스×2계열×4전직 단계의32개 전이를 검증한다. Lv19/20·39/40·59/60·79/80 직전/정확 경계를 포함한다.
2. 다른 클래스ID·타 클래스 노드·반대 전직 고유 기술·잠긴 전직 단계·모순된 저장 빌드를 서버가 거부한다. 마법사는 두 입문 방식에서20레벨 Pyro/Cryo를 모두 선택할 수 있다. 기초 물/바람 유지,40레벨 Pyro 대지/Cryo 번개,60레벨 광역,80레벨 최강 주문의 경로/레벨·노드 선행을 검증한다.
3. 레벨당 포인트 총계79·노드별 최대3·유효 투자 합계·선행/OR 조건·리셋권 기반 전체 초기화·미리보기 취소·환급 예산 보존을 검증한다. 확정 투자분의 부분 초기화는 첫 출시안에서 제외한다.
4. 전직/트리 저장 중 연결 끊김·중복 클릭·동시 요청·서버 이동에서 전직명/기술/포인트가 서로 어긋나지 않는다.
5. 모든 전직 계열의 표준 솔로 보스·다수 적·4인 공략·터치 조작을 확인한다. 성기사/빙결 같은 계열도 본편 공격 수단이 충분해야 한다.
6. 드워프의 강철/화약이 단일 장갑 파쇄와 원거리 광역 제압으로 구별되는지 확인한다. 화약의 벽 너머 피해·무한 연쇄·섬광 가림·박격포 중복 설치/잔류와 설치 불가 지형에서의 솔로 공략을 검증한다.
7. 엘프 명궁의 속사/저격 두 빌드와 마법궁수의 속성 폭발/자연 제어를 검증한다. 두 계열 모두 터치 조준·사선·솔로 피해가 충분하고, 마법궁수의 효과가 화살 궤적과 적 예고를 가리지 않아야 한다.

기본 스탯 도입은 [스탯 설계](character-stats.md)에 따라 검증한다. 같은 총 투자 예산의 공격형/생존형·혼합 계열을 비교하고, 포인트의 중복/초과 배분·재분배·재접속 보존·공격속도에 따른 모션/판정 일치를 확인한다. 스탯 포인트는 Lv2~80 매 레벨4포인트·총316포인트로 스킬79P와 분리한다. Lv1/2/20/40/60/80의 누적 획득량0/4/76/156/236/316, 다중 레벨 상승·미배분 잔량·재접속/재처리 시 중복 지급 방지를 확인한다. 기본 스탯 초기값·효과 계수·스탯별 상한 확정은 성장 통합의 선행 작업이다.

### 6.3 보상·퀘스트·협동

퀘스트 완료 직전/보상 직후 종료, 서버 종료, 재접속, 호스트 이탈, 뒤처진 파티원, 초회/반복 보상, 개인 선택 자격, 체크포인트 전멸, 아이템ID 충돌을 검증한다. 저장 불명 상태는 신규 계정으로 간주하지 않는다. 거래를 도입한다면 양쪽 소유권·중단·복구 계약을 별도 게이트로 추가한다.

공통 Diamonds는 검증된 외부 권위 지갑을 전제로 TD↔RPG 개인 이동, 잔액100에서 양쪽80 동시 소비 시 한 요청만 성공/잔액20, 같은 공동 보상/영수증 조정 재시도 시1회 반영, 차감/외형 지급 사이 종료, 외부 지갑 장애를 포함한다. TD 영웅/타워 성장·기존 구매권·재접속/복구가 유지되는지도 확인한다. [연동 설계의 검증표](experience-integration.md#5-도입-순서와-수용)를 별도 완료 조건으로 사용한다.

보상 발급 결과를 화면 축하와 분리한다. 보스 처치가 확인됐으나 보상 저장이 지연된 경우 재접속 후 다시 발급 가능한 서버 기록과 중복 방지 키가 필요하다. 정확한 저장 빈도·장애 중 획득 제한·복구 경계는 기술 사양에서 결정한다.

### 6.4 입력·화면·성능

TD/RPG 로비·배틀·상세 메뉴를 같은 기기 조건으로 비교해 패널/버튼/선택·잠금/아이콘/글꼴/초상이 일치하는지 확인한다. 같은 자산ID·아틀라스/모델 원본의 로딩·버전 추적과 TD 기존 기능 회귀를 포함하며, 그림이 비슷하다는 이유만으로 공통 라이브러리 연결 완료로 기록하지 않는다.

PC 작은 창/표준/초광폭, 폰 가로/세로, 태블릿, 게임패드·TV 거리에서 실제 입력과 가독성을 확인한다. 입력 장치를 바꿔도 선택·메뉴·스킬 편성이 보존돼야 한다. 색상 의존·화면 흔들림·이펙트 밀도·자막/글자 크기 옵션을 포함한다.

기준 Android/iOS와 PC를 G1에서 선정한다. 4인+적24+보스1, 솔로+동료2,8인 레이드 장면을 따로 측정한다. 모바일/PC의 P95 프레임 시간33.3/16.7ms 목표, 메모리 추이, 네트워크80/150/250ms, 접속·지역 이동·재도전 P50/P95를 기록한다. 실패 시 장식·VFX·AI 갱신·활성 적 수를 조정하되 위험 표시를 먼저 줄이지 않는다.

### 6.5 증거 구분

정적 파일 검사 → 엔진 자동 검증 → 실제 화면/조작 → 실기기 부하 → 새 이용자 관찰 → 미술 수용을 구분한다. 각 결과에 빌드·조건·기기·표본·관측 결과·미검증 영역을 남긴다. 스크린샷 하나를 저장/멀티플레이/FPS의 통과 증거로 사용하지 않는다.

## 8. 운영 준비

출시 전에 개발/테스트/운영 저장 공간과 상품을 구분한다. 버전별 코드·자산·스키마·기술/노드 데이터를 묶어 추적하고, 데이터 변경이 있을 때 소스만 되돌려도 안전하다고 가정하지 않는다. 영수증 재처리·보상 복구·아이템ID 조사·장애 공지·복구 책임을 정한다.

독립 TD/RPG Experience의 외부 지갑·결제 조정 계약이 호환되는지 확인한다. TD 기존 잔액·확인된 구매/수령 기록을 보존하며, 양쪽 잔액을 단순 합산하거나 이동 때 재지급하지 않는다. 이동 기능 차단과 데이터 스키마 복귀는 다르며, 공통 데이터 변경 뒤 구버전 저장기로 단순 롤백하지 않는다.

공개 전에는 신규 접속→캐릭터→전투→장비→전직→던전→서버 이동→재접속→복구의 전체 경로를 실제 환경에서 리허설한다. 상품은 최신 [아이템/수익화](items-and-monetization.md)의 실제 성능 장비·스탯/스킬 리셋권과 기존 외형을 반영한다. 가격/효과·동등 플레이 획득·영수증/지급을 검증하며 전직·스킬포인트·필수 기술을 결제로 우회하지 않는다.

핵심 지표는 첫 원정/첫 전직 이탈, 계열별 채택과 만족 이유, 스킬트리 다양성, 보스 재도전, 동료/친구와의 연계, Coins와 재료 수급, 저장/전송 실패다. 버그를 반복하는 시즌 증량보다 불편과 진행 차단을 먼저 처리한다.

## 9. 결정 상태와 문서의 범위

확정한 계열명·강철기사 계보·마법사 단계별 학습·자산 활용 기준과, 가칭/수치/일정 같은 초안은 [기획 결정표](decisions.md)에서 구분한다. 성녀 지원 기술/AI와 다른 계열의 상위 이름,79포인트·216노드·36액티브·12궁극기는 현재 설계 제안이다.

우선 남은 작업은 전체 퀘스트/기술/노드의 데이터화, 장비/XP/경제 곡선 검증, 공유 자산 적합성 감사, 기존 TD 지갑/상품 writer 감사와 Place 호환 계약이다. 공개 콘텐츠 묶음·출시일·인력·예산은 대표 구간의 실제 제작/테스트 결과로 산정한다.

이 문서는 실행 계획이며 Roblox 게임 코드·3D 제작·실기기 성능·운영 데이터 연동·신규 이용자 테스트의 완료 보고가 아니다. 완료는 각 단계의 관측 결과와 증거로 판정한다. 문서 수정 이력은 [CHANGELOG](CHANGELOG.md)를 따른다.
