# 화살·마법: 실제 몸 방향과 발사 시각 동기화

2026-11-13 · TLT-032/054/056/084 · ENG → QA. 사용자의0.104.29 재신고와 마법 동일 증상을 함께 수정한다. [이전 방향 수정](../elf-arrow-heading-20261113/README.md)의 단위 검사만으로 실제 Play의 몸 방향까지 일치한다고 판단하지 않는다.

## 실제 재현

사용자가 실행하던 **0.104.29 Client**를45초 읽기 전용 관찰했다. [원본201프레임/발사 기록](live-before.json), [집계](live-before-summary.json). 발사33~38의6개 유효 패킷 중37번에서 몸과 서버 발사선이 **32.73도** 벌어졌다. 활/화살 자체는 잠근 방향을 따랐지만 몸은 이동 입력의 회전을 따르고 있었다. 이전 수정은 표시 방향만 보정해 이 불일치를 남겼다.

또한 `K0ArrowRelease`는 전투 경과 시각(예:157.213696)을 게시하고 `K0AttackStartedAt`/클라이언트 모션은 절대 서버 시각(예:1794604982)을 사용했다. 발사 확인의 시작 시각 비교가 실제 세션에서 성립하지 않았다. 기존 모의 검사는 두 clock을100부터 시작해 이 결함을 놓쳤다. [서로 다른 epoch를 사용한0.104.29 실패](public-clock-baseline.log).

Mage의 선택 대상이 준비 중 옆으로 이동해도 추적하던 결함도 기존0.104.29에서 재현했다([기준 실패](magic-direction-baseline.log)).

## 수정

- **서버 승인 시전 방향:** Elf/Mage가 준비를 시작할 때 공격 순번·방향을 `K0AttackAim`으로 게시한다. 기존 `K0BowAim`은 엘프 호환용으로 유지한다. 서버의 원래 AutoRotate 정책도 별도로 전달한다. 발사 직전에는 제한된 조준 보정이 반영된 **최종 서버 발사선**을 다시 게시한다. 피해/표적 결정은 서버에 남는다.
- **로컬 이동 제어:** `BattleController`가 자기 캐릭터의 `AttackFacing`을 PreSimulation에서 실행한다. 유효한 같은 순번의 시전 동안 AutoRotate를 끄고 몸 yaw를 서버 방향에 맞춘다. 위치·이동 속도·속도 벡터는 보존한다. 원래 AutoRotate의 true/false를 복원하며 회피/사망/스턴에는 개입하지 않는다. 관전자 Root를 변경하지 않는다. 이 코드는 표시 렌더러의 Root 이동과 구분한다.
- **화살 발사 확인:** 단조 전투 시각의 경과분을 공개된 공격 시작 시각에 더해 발사 확인도 같은 절대 시각으로 게시한다. 기본 공속/발사 판정 시점/DEX는 그대로다.
- **마법 동일 경로:** 공통 마법3종의 준비 범위를 벗어난 옆/뒤 유도 명중을 제거하고, 활/지팡이 끝의 모든 수평 시각 보정을 서버 선에 투영한다. 실제 발사 높이는 유지한다. MP·쿨다운·범위 안 명중과 스킬 효과는 유지한다.

## 고정 빌드와 남은 수용

첫 고정0.104.30은 실제 Play에서 Elf89프레임·8발, Mage40프레임·3시전의 몸/서버 방향 차이0도와 정상 AutoRotate 복원, 기본 화살의 발사 후 nocked 잔여0을 확인했다([측정](play-0.104.30.json)). Mage는19.81stud 이동 중 시험했다. 다만 마법 비행의 남은 원점 보정각13.03도를 발견해 수용하지 않았으며,15도 이하를 허용하던 조건까지 제거했다. [0.104.30 빌드](build-0.104.30.json)와 [엔진 원문](0.104.30-native.log)은 이 중간 단계의 증거다.

현재 브랜치의 별도 도로 기능 버전0.105.0 이후 수정 빌드0.105.1을 고정하고 실제 비행 yaw를 다시 확인한다. Roblox 게시/실기기/다인 네트워크·최종 사용자 수용은 별도다. 다음 QA는 이동 사격·근접 사격·빠른 회피 취소·시전 중 표적 이동을 Elf/Mage 각각 재확인한다. 상위 티켓 완료로 변경하지 않는다.
