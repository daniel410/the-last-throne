## 판정과 범위

첫 기술 원형의 기반은 마련됐다. 서버가 타격·자원·AI를 소유하고, 운영 데이터 없이 독립 실행하며, 스폰 문제를 실제 Play에서 찾아 고친 점은 유지할 가치가 있다. 다만 **K0 전투 수용은 보류**한다. 다음 개발은 새 클래스·스토리 확장보다 아래 판정/입력 결함과 Goblin/Ogre 실전 한 사이클의 검증을 우선한다.

이번에는 현재 코드·기사 전투 명세·기존 빌드/Play 기록을 검토하고 로컬 Lua 검사를 다시 실행했다. 새 Studio Play, 실기기, 네트워크/부하 주입, 새 게임 빌드는 실행하지 않았다. 이전 Play 증거는 [QA 기록](qa.md), 빌드 식별자는 [빌드 기록](build.md)을 따른다. 기존 테스트의 성공과 이번에 찾은 조건부 결함은 함께 성립한다.

## 발견 사항

### R1 · P1 — 서버 프레임이 유효 구간을 건너뛰면 공격이 사라짐

연결: TLT-006/007/034. 근거: `src/server/Combat/CombatService.luau:504` 및 `:686`.

플레이어·적 모두 현재 시간의 `Rules.phase()`가 `Active`일 때만 피해를 검사한다. 이전 프레임부터 현재 프레임 사이에 타격 구간이 있었는지는 처리하지 않는다. 첫 검격의 유효 구간은 `[0.16, 0.26)`이다. 서버 샘플이 `0.15 → 0.27`로 넘어가면 준비에서 회복으로 바로 이동해 사거리·시야 안에 정지한 적도 한 번도 검사하지 않는다. 적의 0.10초 공격도 같은 조건으로 피해가 누락된다.

실제 `K0Rules`와 `K0Config`를 사용한 Lua 수치 재현:

```text
sample 0.000 → Windup
sample 0.150 → Windup
sample 0.270 → Recovery
sample 0.430 → None
Active 샘플 수 = 0
```

이는 서버의 긴 프레임 조건이며 일반 네트워크 ping과 같은 수치로 취급하지 않는다. 이번 리뷰에서 Roblox 부하를 주입해 실제 교전을 재현한 것은 아니다.

수정 방향: 서버의 이전 처리 시각과 현재 시각 사이에 지나간 타격 이벤트를 처리하고, 대상당1회 제한을 유지한다. 이동 중 대상의 과거 위치를 어떤 기준으로 평가할지도 정의한다. 120~200ms 서버 프레임과 정상 프레임을 섞어 양쪽 공격이 사라지거나 중복되지 않는지 검증한다.

### R2 · P2 — 정상 60Hz에서도 버퍼에 받은 단발 입력이 버려질 수 있음

연결: TLT-005/006. 근거: `CombatService.luau:309`, `:530`.

입력을 받을 때 만료를 `수신 시각+0.12`로 고정한 뒤, Heartbeat에서는 실행 가능 여부보다 만료를 먼저 확인한다. 첫 검격이0.420초에 끝나고 다음 공격을0.301초에 누르면 버퍼에 들어가지만 만료는0.421초다. 60Hz의 다음 처리 시각이0.416667과0.433333이면 전자는 아직 실행 불가, 후자는 만료라서 입력을 잃는다. 유효한 실행 가능 시각0.420이 만료 전이었다는 사실이 반영되지 않는다.

Lua 재현 결과: `accepted=true, eligible=0.420, expires=0.421, executed at 60Hz=false`.

홀드 반복 전송이 이 현상을 가릴 수 있지만 단발 클릭/탭과 취소 입력의 신뢰성은 낮아진다. 버퍼 입력의 실행 가능 시각이 유효 기간 안에 도달했는지 확인해 다음 서버 처리에서 한 번 소비하는 방식으로 고친다. 유효 기간 밖까지 무조건 연장하는 방식은 피한다.

### R3 · P2 — 검이 보이는 방향과 서버 타격 방향이 어긋날 수 있음

연결: TLT-005/032/033. 근거: `CombatService.luau:209`, `src/client/K0SwordVisual.luau:45`.

타격 방향은 공격 시작의 `root.CFrame.LookVector`로 저장되고 이후 갱신되지 않는다. 반면 공격 중 이동은 허용되며, 소스에는 캐릭터 회전을 고정하거나 저장된 공격 방향에 시각을 맞추는 처리가 없다. 검 연출은 현재 캐릭터 손에 붙은 관절을 움직인다. 공격 도중 캐릭터가 회전하면 검과 몸은 새 방향을 보면서 타격 부채꼴은 이전 방향을 유지할 수 있다.

이 항목은 코드 경로 검토 결과이며 새 Studio 교전에서 회전/적중을 재현하지 않았다. 전방 공격 중 옆 이동·카메라 전환을 수행하고, 화면의 무기 방향과 서버 판정 방향을 함께 표시해 확인해야 한다. 명세의 준비 중 방향 보정과 유효 구간의 방향 잠금을 하나의 기준으로 모션·몸 회전에 연결한다.

### R4 · P2 — 메뉴/채팅 진입이 이미 시작된 홀드 입력을 정리하지 않음

연결: TLT-005/036. 근거: `src/client/init.client.luau:79`, `:112`, `:188`, `:202`.

새 InputBegan에서는 처리된 입력/텍스트 포커스를 검사하지만, 이미 시작된 공격·방어 반복 루프는 메뉴나 텍스트 포커스를 검사하지 않는다. 정리는 입력 종료·새 Character·OS 창 포커스 이탈에만 연결돼 있다. 공격 버튼을 누른 채 Escape 메뉴나 채팅으로 진입해도 OS 창은 활성 상태이므로, 버튼이 종료될 때까지 게임 행동 의도가 계속 전송될 수 있다. 방어는 UI 진입만으로 해제되지 않는다.

이는 정적 경로 확인이며 새 Studio 메뉴 조작으로 재현하지 않았다. 메뉴 열기·텍스트 포커스 진입에서 홀드/대기 입력을 정리하고, 메뉴를 닫았다고 물리 버튼 확인 없이 자동 재개하지 않도록 한다. 키보드·터치 버튼·패드 트리거와 입력 전환을 각각 검사한다.

## 제품·디자인 평가

- **전투 기반:** 고정 프리셋, 세 검격, 방어/완벽 방어/회피, 적 자세와 공격 예고가 있어 전투 실험을 시작할 수 있다. 서버 권위·대상당1회·사선 검사와 스폰 준비 동기화를 유지한다.
- **전투 피드백:** 반격 기회와 적 자세는 서버에 있지만 현재 HUD에는 표현이 없다. 플레이어가 완벽 방어 뒤의 강화 기회나 자세 붕괴를 보고 판단할 수 있는 표시·피격 반응·음향을 보강해야 한다. 서약은 아직 미구현이다.
- **TD 정체성:** 현재 월드·기사 소품·HUD는 임시 구현이다. TD 후보12개 preload 성공은 유용한 준비 증거지만 게임에 실제 공유 자산을 적용한 결과가 아니다. 다음 미술 작업은 검증된 TD 기사 검·적과 공통 HUD를 K0에 연결하는 것이다.
- **맵과 콘텐츠:** 안전 시작·통로·공터는 훈련장으로 적절하다. 퀘스트·목표 진행·보상·스토리·탐험의 재미를 판단할 게임은 아직 아니다. 이 범위는 첫 원형에서 의도한 미완성으로 분류한다.
- **네트워크 준비:** 입력 `lifeId/inputSeq`가 없어 이전 캐릭터에서 늦게 도착한 의도를 새 캐릭터 요청과 구별하지 못한다. 악의적/중복/지연·재접속 검증과 함께 별도 보완한다. 실제 상품·지갑·저장은 현재 연결하지 않는다.
