# K0 전투 판정·입력 타이밍 보정

2026-10-28 · `TLT-005/006/007/034` 일부 · ENG/QA/DIR

## 대상

[첫 구현 리뷰](first-implementation-review.md)의 R1과 R2를 먼저 다룬다. 기사·적의 타격 구간 전체가 서버 프레임 사이에서 지나가면 타격 검사가 누락되던 문제와, 행동 가능 시각이 입력 버퍼 만료 전에 도달했는데 다음 서버 프레임이 만료를 먼저 확인해 단발 입력을 버리던 문제다.

## 시간 계약

- 기사와 적은 서버에서 타격 유효 구간을 검사하며 동일 공격에서 같은 대상에게 한 번만 적용한다. 유효 구간을 한 번도 관측하지 못한 채 건너뛴 경우에만 보정 검사 한 번을 실행한다. 이미 유효 구간을 검사한 공격이 회복 구간에서 새 타격 기회를 얻지는 않는다.
- 지연 검사에서 기사의 타격 시작점과 대상 위치, 적 공격 대상의 위치·방어는 **처리 시점의 서버 상태**를 사용한다. 적의 공격 원점과 방향은 기존 예고에서 마지막으로 정한 값을 유지한다. 시야·자원도 현재 상태로 확인하며 과거 위치나 방어를 재구성하지 않는다. 유효 구간 종료에서 0.25초가 넘게 지난 공격은 보정하지 않는다. 이 상한은 K0 실험값이며 네트워크 지연 보정이 아니다.
- 버퍼는 수신 시점에 정해진 유효기간 안에 해당 행동을 시작할 수 있는 시각이 도달했는지 기준으로 다음 서버 처리에서 한 번 소비한다. 비용·쿨다운·생존·우선순위·취소 조건은 다시 확인한다. 행동 가능 시각에서 0.25초를 넘겨 처리하는 오래된 입력은 버린다. 이 상한도 K0 실험값이다.
- 같은 처리에서 처음 관측하는 공격은 예정된 유효 구간 시작 시각, 이미 유효 구간을 관측한 반복 검사는 현재 처리 시각으로 정렬하며 동일 시각이면 플레이어를 먼저 처리한다. 취소·사망으로 이미 폐기된 공격은 되살리지 않는다. 프레임 보정은 입력 처리에서도 실행하므로 원격 요청 빈도에 따라 추가 검사가 생긴다. 네트워크·다인 부하 검증은 별도다. 방향과 시각의 불일치 R3, 메뉴/채팅 홀드 해제 R4는 별도 작업으로 유지한다.
- 적의 판정 전에 진행 중인 서버 소유 회피를 현재 시각까지 이동해 위치를 갱신한다. 같은 시각에 다시 이동 함수를 호출해도 이미 이동한 거리를 빼므로 거리와 비용이 중복되지 않는다. 벽·낭떠러지의 기존 제한과 회피 무적 시간은 유지한다.
