# 표적 사격·기사 무기 가시성

작업: TLT-005/006/032/033 일부 · 2026-10-28 · ENG/ART/QA, 통합 DIR. 사용자 요청에 따른 시험판이며 전체 티켓 수용은 아니다.

- 사용자의 0.6.1 Studio 클라이언트에서 당시 검 메시 `130169610186060`와 방패 메시 `86935256146675`의 `GetAssetFetchStatus`가 모두 Failure였다. 이것만으로 권한 문제와 네트워크 문제를 구분할 수는 없다. 같은 소스의 격리 Studio에서는 두 메시가 Success였다. TD 원본은 그대로 두고, 개별 클라이언트에서 메시 로드를 기다리는 동안 및 실패 시 임시 검/방패를 손에 표시한다. MeshPart를 대상으로 로드 결과를 확인하며 성공하면 원본을 표시하고, 실패 시 제한된 횟수로 재시도한다. 대체 외형과 팔 동작은 시각 전용이다.
- Elf는 활을 높이고 왼손에 활을 들고 R15의 오른손 IK 목표를 활시위의 당겨지는 쪽에 둔다. TD 활시위의 지나치게 깊은 원본 형상은 대기 중 풀린 길이로 줄인다. 준비 중에만 오른손 목표, 시위 끝과 화살을 같은 당김에 맞춰 뒤로 움직이고 발사 시 놓아 손이 머리 뒤로 넘어가지 않도록 한다. 발사 순간 오른손 IK를 유지한 뒤 회복 중 점차 해제한다. 시위 기준 크기와 조인트 상태는 생존 중 강하게 보존하고 제거 시 정리해 반복 축소를 막았다. R6에는 어깨 동작을 사용한다.
- Elf는 몬스터를 왼쪽 클릭하면 선택하고 발사한다. Mage는 몬스터를 왼쪽 클릭해 선택한 후 Q 또는 Cast 버튼으로 발사한다. 터치 월드 탭은 표적 선택이며 발사는 HUD 공격/스킬 버튼이다. X는 표적 해제다. 선택은 노란 테두리로 표시하고 적 사망/제거·캐릭터 교체·로비 복귀 시 해제한다. 표적이 없으면 기존 전방 조준을 유지한다.
- 클라이언트는 적 모델만 제안한다. 서버는 실제 등록된 적, 직업, 생존, 사거리, 높이, 장애물을 검증하고 피해를 결정한다. 사라진 표적은 다른 적으로 자동 전환하지 않는다. 방어·근접 공격과 마법 재사용 시간은 유지한다.

## 검증과 한계

- [서버 native 검사](targeted-combat-native.log)에서 등록되지 않은 표적 거부, 선택한 측면 적 우선, 벽/사거리 차단, 사망 표적의 다른 적 자동 타격 방지 등을 검사했다. [무기 native 검사](targeted-visual-native.log)는 R6/R15 무기 원본과 대체 외형의 가시성·복원·비충돌을 확인했다.
- 격리 Studio의 실제 R15 Player에서 활 조인트의 장착 손은 LeftHand, IK 대상 손은 RightHand였다. 준비 중 오른손 깊이는 루트 기준 -0.56 studs, 머리는 약 0으로 손이 앞에 있었고 목표와 거리는 약 0.86 studs였다. 시위 깊이는 대기 1.192 → 준비 1.651 → 발사 1.206 → 복귀 1.192 studs였으며 대기 3초 동안 변하지 않았다. 발사 구간 오른손과 목표 거리는 약 0.71 studs였다. Mage HUD의 CAST 문구를 확인했다. 화면의 슬라임을 클릭해 선택 표시와 장애물 안내를 확인했다.
- 같은 격리 환경에서 Mage의 클릭 선택과 Q 시전을 확인했다. 원래 가림벽이 있을 때 피해가 없었고, **테스트 복사본에서만** 벽을 제거한 뒤 슬라임 체력 220→120을 확인했다. 별도의 실제 Player 원격 공격 요청으로 Elf의 슬라임 체력 220→150도 확인했다. 수동 기기·다인·지연·게시 Experience의 원본 메시 권한과 사용자별 최종 손 접촉/애니메이션 미술 수용은 미검증이다.
- 다음 담당: QA가 사용자 아바타와 기기에서 조작·가독성을 확인하고, ART가 원본 메시 접근 권한과 대체 외형의 수용성을 검토한다.
