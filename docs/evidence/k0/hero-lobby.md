# 네 영웅 시험용 로비 작업 기록

2026-10-28 · 작업: TLT-004/008/014의 부분 원형 · 총괄 DIR, ENG·ART·QA

사용자는 간단한 기본 로비에서 Knight, Elf Archer, Dwarf Axe Thrower, Mage를 기반으로 새 영웅을 만들고 튜토리얼을 시작해 네 직업을 직접 시험하도록 요청했다. 같은 세션에서 서로 다른 영웅을 선택할 수 있으며, **각 영웅의 최초 직업은 바꿀 수 없다**.

이번 범위는 게임의 지속 캐릭터 데이터나 계정 창고·공통 지갑을 만들지 않는 시험용 세션이다. 직업별 1명씩 최대 4명으로 시험하며, 중복 생성은 거부하고 기존 영웅을 선택할 수 있다. 로비에는 접속 종료 시 시험 영웅이 초기화된다는 영어 안내를 표시한다. 이 시험용 제한을 정식 계정 슬롯이나 과금 정책으로 확정하지 않는다. 정식 데이터 저장은 별도 계약과 재접속·오류 복구 검증을 거친다.

영웅 선택 초상과 검·방패·활·도끼는 기존 TD 자산을 재사용하고, 마법사 지팡이는 이번에 만든 나무 지팡이다. 플레이어 캐릭터는 Roblox 아바타를 사용하며 TD HeroSystem의 팔·몸통 색을 적용한다. 의상·장신구·얼굴은 보존한다. TD의 전신 후보와 보관 리그는 플레이어용 완성 리그로 수용된 상태가 아니다.

## 소스 검증

- `lua tests/k0-hero-session.spec.lua`: 서버 영웅 소유권·최초 직업 고정·네 직업 전환·잘못된 요청·지연된 생명·경계 등 77개 검사 통과. Roblox 네트워크가 아닌 Lua 신원 모형이다.
- `lua tests/k0-spawn.spec.lua`: 네 플레이어, 실패 시 backoff, 늦은 Humanoid, 목적지별 스폰과 로딩 중 전환·구 생명·사망 후 리스폰·이탈 통과. 검사 중 발견한 초기 로딩 실패의 즉시 반복 회귀를 수정해 재검증했다. 이 결과만으로 실제 엔진 배치를 수용하지 않는다.
- 격리 Studio의 [로비 소스 native 검사](hero-lobby-native.log)는 348개/12사례 통과·종료 0이고 신원·로드 경계는 모형이다. [첫 실행](hero-lobby-native-first.log)은 QA fixture의 신호 등록 전에 신호를 보내 1사례가 시간 초과됐으며, 테스트 동기화만 수정해 재실행했다. 게임 소스는 두 실행 사이 같았다. [로비 포함 소스 smoke](hero-lobby-source-smoke.log)는 Player 0에서 346개 통과·종료 0이다.
- 격리 Studio의 실제 전투 소스와 신원 모형을 사용한 [기본 공격 검사](hero-combat-native.log) 94개/24사례, [기사 타이밍 회귀](hero-timing-native.log) 116개/37사례, [직업별 무기·시각 fixture](hero-weapons-native.log) 2,118개/34사례가 각각 종료 0·실패 0이었다. 네이티브 rig·물리 API와 실제 메시 로딩을 포함하지만 실제 플레이어 입력·통신은 별도다. 로그의 소스 해시는 각 fixture를 생성한 시점이며, 이후 SpawnService의 위 실패 재시도 수정은 해당 독립 전투 검사 입력과 구분한다.
- 원거리 피격 수정 후 [최종 기본 공격 검사](elf-aggro-native.log)는 122개/30사례, [기사 타이밍 회귀](hero-timing-final-native.log)는 116개/37사례, [무기 fixture](hero-weapons-final-native.log)는 2,118개/34사례 통과·종료 0이다. 첫 검사는 약 25.86stud 명중·추격, 50stud 명중의 6초 회복 유예, 추적 경계, 무효화된 영웅, 다중 궁수와 기사 회귀를 포함한다. 타이밍 로그에는 검사 성공 이후 Studio 기본 Toolbox의 React 스택 출력이 있었고 게임 검사의 실패로 기록되지는 않았다. 원인 미확인이며 원문을 남긴다.
- `lua tests/k0-rules.spec.lua` 122개, `lua tests/k0-appearance.spec.lua`, `lua tests/k0-hero-palette.spec.lua` 및 TD 검·방패 원본의 두 추출 도구 `--check`가 통과했다. 색상·외형 Lua 검사는 모의 생명주기이며 Studio 화면 수용이 아니다.

## 독립 Studio Play 사전 검사

실제 빌드 전에 PlaceId 0의 격리 소스 fixture에서 Play하고 기존 TD 초상 네 장이 표시되는 화면을 확인했다. 마우스로 네 카드의 `CREATE HERO`를 눌러 4/4 영웅을 만들고, Mage → Dwarf → Knight → Elf 순으로 로비 복귀·영웅 선택·`START TUTORIAL`을 실행했다. 각 서버 캐릭터의 직업, 준비 상태, 지정 무기와 공격 순번 증가를 확인했고 기사의 분리 방패 메시도 확인했다. Elf는 이동·공격·Space 회피 후 연습 완료 문구가 표시됐으며, 사망 후 같은 영웅 ID/직업의 새 세대 캐릭터와 활이 재등장했다. 실제 사용 계정의 로컬 Studio, 가상 PC 입력 1명이며 게시된 환경이나 실기기 수용은 아니다.

실제 원거리 공격에서는 Goblin의 감지 범위 밖에서 피해 직후 체력이 `300→230→300`으로 즉시 회복되는 결함을 발견했다. 수정 후 같은 격리 Play에서 약 25.94stud 거리의 실제 마우스 공격은 `300→230`을 유지했고 Goblin이 공격자에게 추격·공격 예고 상태로 접근했다. 적의 기존 추적 경계를 유지하며 경계 밖 원거리 명중은 마지막 명중 뒤 6초간 피해를 유지한다. 경계 밖에서 계속 명중해 유예를 갱신할 수 있어 최종 AI·장거리 밸런스는 별도 검증이다.

사전 검사의 첫 Studio Play 전환은 소스 fixture 주입기가 복제된 실행에서 다시 초기화하려다 종료됐다. 이후 `/private/tmp`의 시험용 주입기에 중복 시작 가드를 넣어 재실행했다. 게임 소스와 빌드 결과물을 바꾸는 수정은 아니다.

## 0.5.0 고정 빌드

소스 커밋 `02424864917bed834c2e2f03615cbf3a1f47733b`, Rojo 7.7.1, `VERSION=0.5.0`으로 만든 로컬 빌드의 해시는 `b26f395c2f6e53096f6544c3439d4cc729889e6f6929dd115a6ba8b004a6717e`이다. 고정 빌드에서 [엔진 smoke](hero-lobby-build-smoke.log) 346개가 종료 0으로 통과했다. Player 0이며 수집된 런타임 오류는 없다.

같은 빌드의 독립 PlaceId 0 Studio Play에서 실제 플레이어로 네 영웅을 만들고 [4/4 로비 화면](hero-lobby-0.5.0.jpg)을 확인했다. Mage, Dwarf, Knight, Elf 순으로 각 영웅을 선택해 튜토리얼에 들어갔으며 각 서버 캐릭터가 준비되고 나무 지팡이, TD 도끼, TD 검·방패, TD 활을 각각 장착한 상태에서 실제 마우스 공격 순번이 증가했다. 영웅 사이에는 버튼으로 로비에 복귀했다. Elf로 약 25.70stud 거리에서 Goblin을 맞혔을 때 서버 체력 `300→230` 유지와 추격을 확인한 뒤 로비에 다시 돌아왔다. 사전 검사에서 한 Elf 사망/재등장과 연습 완료도 관찰했으며, 고정 빌드에서 이를 반복한 것은 아니다.

실제 스토리 튜토리얼·영구 저장·영웅 전신 리그·성장/보상은 구현하지 않았다. 게시된 Experience의 제한 자산 권한, 실기기·패드·다인·지연·성능, 장거리 적 AI 밸런스와 최종 모션은 미검증이다. `rbxassetid://203785492`의 기존 유형 불일치 경고가 반복됐으며 출처는 확인하지 못했다. 릴리스 태그나 Roblox 게시는 없다.
