# 네 영웅의 이동 공격과 방출

2026-11-24 (토론토) · TLT-033/057/059 · 기준 0.115.100 · 후보 0.115.102

| 영웅 | 기술 | 변경 |
| --- | --- | --- |
| Knight | Radiant Charge | 방패를 낮춰 밀고 첫 타격 뒤 반대쪽 발을 디디며 올라온다. 낮은 금빛 첫 획과 더 높은 두 번째 획을 각 서버 펄스에 연결한다. |
| Dwarf | Blast Step | 뒤로 미끄러진 뒤 왼팔의 포격 반동을 팔꿈치로 받아내고, 몸통과 디딤발을 되돌린다. 포구에서 전방으로 퍼지는 짧은 압력파를 쓴다. |
| Elf | Gliding Shot | 낮은 발자국을 남기고 앞발로 체중을 받으면서 시위를 놓는다. 발사 잔상 한 획과 기존 화살을 쓰고, 근접 엄폐가 무기 끝 앞에 있으면 영웅 원점부터 끝점까지 그린다. |
| Mage | Ember Step | 지팡이를 몸 앞에 접고 빈손으로 출발지를 뒤쪽으로 쓸어 올린다. 출발지에 남는 불꽃의 높낮이와 방향으로 이동 흔적과 공격을 구별한다. |

이동 흔적은 서버가 승인한 이동을 따라 열린 길과 짧게 잘린 경로에 표시된다. 피해 경계는 기존 원과 부채꼴이 표시한다. 피해, 상태 효과, 이동 거리, 엄폐와 펄스는 기존 서버 판정을 사용한다. [공식 게임 사례와 적용 근거](../../research/2026-11-24-hero-mobile-releases.md)

## 검증

- Rojo 7.7.1로 소스 `baa01583`을 고정해 단일 Place를 빌드했다. 기준·후보 파일의 SHA-256과 런타임 소스 5개씩을 해당 Git 커밋과 대조했다. [기준 빌드](../epic-fifth-chapter-route-infrastructure-20261124/build.json) · [후보 빌드](build.json) · [패키지 대조](package-check.json)
- 같은 R15 리그·카메라·조명으로 16장을 비교했다. 첫 후보 0.115.101에서는 방패 뒤에 첫 타격이 가려지고 엘프의 삼각형 면이 화살과 겹쳤다. 최종 후보는 방패 양옆까지 타격선을 넓히고 화살 잔상을 한 획으로 정리했다. 최종 비교 각도에서 표적이 포격 압력파 중앙 일부를 가린다. [전후 화면](comparison.jpg)
- 격리 Studio 25묶음에서 256,214개를 통과했다. 4클래스 128개 기술의 R6·R15 재생, 서버 이동의 열린 길·짧은 벽·차단·낭떠러지, 착지·취소, 확정 타격과 기술 경계를 확인했다. 집중 단독 검사 60개는 모두 통과했다. 기준은 실행된 집중 검사 42개 중 28개를 충족하지 못했다. 여러 검사를 이어 실행하면 앞선 검사에서 남은 표시 부품이 정리되기 전에 공용 한도에 닿아 세 범위 확인이 실패했다. 집중 검사는 같은 빌드를 새로 열어 확인했다. [검사 결과](studio-results.json)
- 네 영웅 동시 시전의 같은 장면에서 영웅 VFX는 Beam 75→13, 표면 131→16, 보조 발광선 7→0, 입자 요청 18→0이다. 적의 붉은 예고선 16개와 아군 화살의 피해 숫자 42를 확인했다. CPU 전직·스킬 렌더러·스탯 미리보기 15,351개와 패키지 정적 336개를 통과했다.
- 별도 Gunner 타이밍 검사는 기준과 후보 모두 Rolling Charge의 비행 창 대기에서 중단됐다. Blast Step의 포구·부채꼴은 집중 검사와 캡처에서 확인했다. 기존 순수 Lua 자세 검사는 Luau 복합 대입을 해석하지 못해 R6·R15 Studio 결과를 사용했다.
