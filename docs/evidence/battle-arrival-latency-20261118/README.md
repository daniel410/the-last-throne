# 배틀 입장과 교전·스토리 진행 잠금

2026-11-18 · TLT-040/053/087 · ENG → QA/릴리스 · 0.113.16 후보

## 재현된 원인과 변경

- 출발 임무가 DW-01이고 같은 원정의 저장 진행이 HG-03인 경우, 기존 코드는 저장 계정을 열기 전에 DW-01의 에픽을 만들었다. 캐릭터 목적지 계산 시에는 HG-03을 읽고 그 에픽도 준비했다. 이제 입장권과 영웅의 저장된 원정을 확인해 HG-03만 준비한다. 새 원정은 기존 서버 승인 출발 기록과 계정 저장을 확인하고 출발 임무를 준비한다. 지역 생성과 재접속 권리 확정을 병행하며 둘 다 성공한 뒤 입장한다.
- 기존 2초 주기 검사는 영웅 준비와 여행 잠금 해제를 각각 기다리게 했다. 이제 영웅·지역 준비 이벤트가 입장 검사를 깨우고, 전투 가능한 상태가 되면 첫 교전 검사와 스토리 상태 전송을 요청한다. 첫 파티 도착 대기 규칙은 유지하며, 이미 파티가 시작한 뒤 파티원이 나가도 최초 대기를 다시 시작하지 않는다.
- 기존 20초 주기 원정 갱신에 일시적인 실패를 한 번 주입하니, 다음 성공까지 20초 동안 전투·스토리가 잠겼다. 마지막으로 확인한 서버 소유권은 그동안 유효했다. 이제 네트워크 실패 시 해당 소유권의 만료 안에서만 진행을 유지하고 짧은 간격으로 재시도한다. 소유권 손실이 확인되거나 임대가 만료되면 잠그며, 응답이 진행 중이어도 만료 시간을 연장하지 않는다.

## 검증

- [입장 가상 시계 시험](../../../tests/expedition-arrival-latency.spec.lua) 26검사를 CLI와 고정 빌드의 격리 Studio에서 통과했다. 재접속 지역 선택, 지역·재접속 기록의 응답 순서 양쪽, 실패 재시도, 파티 지연·이탈, 소유권 만료 및 확인 손실을 포함한다.
- 0.113.15의 실제 갱신·잠금 코드에 첫 갱신 실패와 두 번째 성공을 주입했다. 가상 시계 20초부터 40초까지 잠김을 재현했다. 0.113.16은 같은 일시 오류에서 유효 소유권으로 진행을 계속했다. 실제 서버에서 당시 해당 오류가 발생했다는 의미는 아니다.
- Studio 페이즈 275검사와 교전 913검사 통과. 준비 이벤트 전에는 첫 무리를 차단하고, 잠금 해제 후 범위 안의 첫 무리를 별도 주기 호출 없이 생성했다. 기존 저장 확인 뒤 다음 무리 시작과 에픽 완료 알림 순서도 통과했다.
- Lua 원정 재개 183·출발 42·저장소 52·저장소 전환 34·장애 복구 9·영웅 세션 149·도착 덮개 326검사와 파티·스토리 저장·부활·체크포인트 회귀를 통과했다. 소스 Luau 546개를 컴파일했고 변경 런타임 소스 4개 및 빌드 파일 해시를 확인했다. [고정 빌드](build.json).

게시 서버의 첫 입장·재접속 총시간, 실제 MemoryStore 오류 간격, 4인·실기기와 사용자 수용은 미검증이다. 다음 담당 QA/릴리스는 같은 지역에서 플레이하다 원정 갱신 오류가 발생할 때와 다른 에픽으로 재접속할 때를 각각 확인한다. 지역 자체의 생성 비용은 [별도 월드 계측](../world-runtime-optimization-20261118/README.md)을 따른다.
