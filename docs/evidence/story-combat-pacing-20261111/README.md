# 길목 전투 공백과 전투 HUD 초기화 보강

## 변경과 근거

사용자는 [47장 전투량 검사](../story-combat-audit-20261111/README.md) 후 수정을 요청했다. [Diablo 우선 조사·적용 판단](../../research/2026-11-11-story-combat-pacing.md)에 따라 기존 장소를 늘려 걷게 하거나 체력을 올리는 대신 목적지 사이에 유한 전투를 넣었다. 게임 문자열/식별자는 영어이며 신규 미술·TD 운영·상품/장비·계정 지갑은 변경하지 않는다.

`CampaignCombatPacing`은 GW/HG의 거점을 제외한 전투 장12개와 EC-05에 일반 길목 교전13개를 추가한다. 기존75전투·보스·단서/결말·완료 보상은 유지한다. 신규 목표는 기존 서버 접근/파티/원정 자격·최대 동시 무리·처치/저장/재시도 경로를 사용한다. 새 장이나 끝없는 재생성은 없다. 추가된 총234마리의 솔로 적은 정상 일반 처치 XP/Gold를 지급하므로 총 유입과 물약 소모/전투 시간은 늘어난다. 승인 완료 XP나 기존 처치 보상을 줄여 상쇄하지 않았다.

## 진행·저장 호환

추가 목표는 `pacing=true`와 별도 안정ID를 가지며, 기존 `coreGoals`를 수정하지 않는다. `DeepwoodProgress`의 `combatPacingVersion=1`에서만 필수/접근 가능하며, 기존 뒤쪽 목표에는 별도의 `pacingRequires`를 적용한다. 기존 확장 계약을 쓰는 신규/계속 원정13/14는 `AdventureRules`의 저널 투영과 계정 사건 처리에서 같은 이관을 사용한다. 구형1~12 저널에는 추가 필수 목표를 자동 부과하지 않는다.

- 추가 전투 뒤쪽 목표가 저장 완료됐거나 부분 단계가 저장돼 있으면 새 전투만 `pacingWaivers`로 면제한다. 완료/활동/단서/선택·재화·기존 영수증은 보존하고 역주행이나 보상을 발생시키지 않는다.
- 뒤쪽 목표가 미진행이면 기존 조사 다음에 새 교전이 필수이며 뒤쪽 상호작용으로 우회할 수 없다. 신규 필수 전투를 완료하지 않은 조작된 완료 플래그는 검증에서 거부한다.
- 면제/적용은 멱등이며 클라이언트가 진행을 주장해 지급받지 않는다. 실제 계정 변경은 기존 저장 성공 경로를 따른다. 이미 정리한 무리는 기존 서버 확정 처치 영수증으로 복구한다.
- 해당 장의 재플레이는 별도 원정의 새 교전을 요구하고, 영웅의 영구 결말과 완료 보상 청구 기록은 보존한다. 소스만 이전으로 되돌리면 새 목표ID를 모르는 구형 저널 검사기가 신규 저장을 거부하므로, 새 저장이 생긴 뒤의 복구는 콘텐츠/이관 코드를 유지하는 전진 수정으로 처리한다.

## 전투바

기존 `BattleController`는 HUD를 끈 뒤 음악/적 시각 효과 등9개 모듈을 동기 시작하고 마지막에 세션 구독과 HUD 활성화를 했다. `init.client`도 분위기를 컨트롤러보다 먼저 시작했다. 이 구조에서는 연출 모듈의 오류/원격 대기가 전투바 활성화와 클라이언트 준비를 중단/지연시킬 수 있다.

새 `BattlePresentation`은 HUD 세션 구독/최초 표시 이후 각 연출을 독립 비동기 시작하고, 실패 이름/원인을 경고한다. 분위기와 지도/저널 시작도 같은 오류 격리를 사용한다. 전투 입력의 서버 권한·모험/리스폰/로비 표시 조건·TD 공통 HUD 구성은 유지한다. 오류/대기 주입으로 다른 연출과 HUD 시작 순서가 유지되는지 검증한다. 사용자 화면에서 발생한 원인과 같은 오류였는지는 미확정이며 실제 게시 클라이언트 재현/해결 확인과 구분한다.

## 검증

[정적 회귀 로그](campaign-combat-pacing.log): 기존 확장 저널의 모든 단계별 저장 이관·부분 보존·진행 우회 거부·기존14 Continue·실제 계정 사건/재시도/재플레이 **50,349 PASS**. [연출 시작 오류/대기 주입](battle-presentation.log) **41 PASS**. [전체 교전·처치ID·보상·위치/복구](campaign-combat-routes.log) **77,381 PASS**. 확장/스토리 가이드/완료/순서/원고/계정/체크포인트/선택 원정/길찾기 등 관련 정적 회귀도 실행했으며 상세 명령별 로그를 함께 보존한다.

기존 `story-region-handoff`, `battle-startup`, `story-continuation`, `quest-completion-rewards` 검사는 각각 오래된 모의 `encounters`/`prepare`·필수 확장 생략·규칙13 고정 가정을 사용해 실패했다. 변경 전 HEAD를 임시 디렉터리에 추출해 같은 실패를 재현했다. [원격 기준 재현](baseline-failures.json). 이번 변경의 통과로 숨기거나 관련 없는 런타임 수정으로 우회하지 않았다.

첫 엔진 후보는 실제 서버 교전817·새 경로6,332(몸체/바닥 차단0)·기존 사건3,974표본(차단0) 뒤 오래된 왕좌 테스트 장면에서 실패했다. [첫 후보](native-preview.log). 테스트 장면이 현재 `DawnspireThrone`/`HeartPosition` 계약과 실제 심장 부모를 사용하도록 고쳤다. 포트 충돌2회와 미리보기의 큰 지도 Source 재할당 제한1회는 하네스 실패이며 게임 통과가 아니다. 최종 고정 빌드/실행 결과는 아래 마감 기록에 연결한다.
