# 장착 사전 다운로드·도착 캐릭터 초기화

2026-11-11 · TLT-057/084 · ENG/QA · 사용자 보고: 배틀 시작 후 몸 없이 머리만 보임.

원인 경로: `ArmorAppearance`가 기본 몸을 숨긴 뒤, 기존 `EquipmentAssetLoading`이 다운로드 중인 장비도 숨긴다. `ArrivalLoading`은 맵·카메라·서버 스폰만 확인해 캐릭터 장비 메시가 가려진 상태에서 화면을 열 수 있었다. 사용자 당시 네트워크·화면의 직접 재현은 미확인이다. 열려 있는0.103.5 클라이언트 조사 시점에는 현재 장비 메시가 모두 Success·로컬 마스크0으로 회복된 상태였다.

변경:

- 승인된 실제 가져오기 기록의 메시·텍스처를 공유 manifest로 고정한다. 장착 버튼·가방 더블클릭은 같은 command 경로에서 다운로드 성공 후 서버 Equip 요청을 보낸다. 실패하면 현재 장비를 유지하며 재시도 안내를 표시한다. 대기 중 선택·영웅·아이템 revision이 바뀌면 오래된 요청을 보내지 않는다.
- 메시에는 SpecialMesh, 색상에는 Decal 표현으로 요청한다. 성공 캐시와 동시 요청 합류, 실패3회 재시도, 임시 객체 정리. 이전 계열 등 manifest 외 장비는 기존 경로와 실제 캐릭터 로더를 유지한다.
- 로컬 캐릭터의 기본 머리/몸·착용 의도와 복제된 장비 모델/부품 수·무기/방패 정의를 확인하고 실제 시각 자산을 다운로드한다. 애니메이션/스킬 사운드 전체를 로딩 완료 조건으로 삼지 않는다.
- 다운로드 후에도 동일 캐릭터·동일 장비 구성인지 재검사한다. 새 부품/장착 변경은 준비 상태를 즉시 무효화한다. 재스폰의 이전 다운로드 완료가 새 캐릭터를 해제하지 못한다.
- 도착 화면은 맵·카메라·기존 전투 준비와 함께 `TLTLocalAppearanceReady` 및 기존 장비 마스크 해제를 기다린다. 실패 때는 커버를 유지하고 자동 재시도한다. 이 값은 클라이언트 표시용이며 서버 소유권/피해/저장/입장 자격에 사용하지 않는다.

검증:

- `lua tests/equipment-warmup.spec.lua`:13검사, 실패 시 장착 준비 거부/복구·성공 캐시·후드와 머리 동시 준비.
- `lua tests/character-asset-loading.spec.lua`:6검사, 초기 지연·교체 캐릭터·새 부품·오래된 완료 격리.
- `lua tests/arrival-loading.spec.lua`:283검사, 맵 도착 후에도 캐릭터 준비26프레임까지 커버 유지·준비 후3프레임 확인.
- 기존 로더21검사, 가방 더블클릭26검사, 인벤토리 소유권/저장274검사 통과.
- 실제 Studio 격리 fixture에서 SpecialMesh/Decal 사전 로딩,4클래스의 빈 무기/복제 전/완성/몸 부품 누락 구분 통과. 고정 소스 `08c567ed97af764b5ff604f995ca8436645983c1`의 실제 모듈을 연결된 격리 Edit Studio에서 실행해51묶음 전체 다운로드와4클래스 상태 검사를 통과했다([native.json](native.json)). 테스트 뒤 임시 모듈/마네킹을 제거했다.

**빌드0.103.7**: [build.json](build.json), 입력 소스 `08c567ed`와 단일 rbxlx 해시를 고정했다. `run-in-roblox` 자동 실행은 Studio 온라인 대기 시간 초과로 시작 실패했다([native.log](native.log)). 따라서 성공한51묶음 결과는 연결된 로컬 Studio의 정확한 수정 모듈 fixture이며, 새 빌드 전체를 부팅해 수용한 결과로 보고하지 않는다.

캐시 없는 게시 클라이언트·저속망·실기기·타 플레이어 스트리밍·실제 Teleport 이동·GPU 표시 완료는 미검증이다. 다운로드 callback Success가 GPU 렌더 완료 자체를 보장하지 않는다. 사전 다운로드는 이 클라이언트에서 수행하며 다른 기기의 캐시나 다음 서버의 초기화를 대신하지 않는다. 다음 담당: 고정 빌드의 엔진 fixture, 사용자 첫 접속/배틀 수용. Place 게시는 별도다.
