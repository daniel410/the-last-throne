# 딥우드 첫 스토리 스턱·전체 지역 통행 수정

2026-11-11 · TLT-031/050/057/061 · ENG → QA · 게시/실기기 수용 별도

사용자 스크린샷은 DW-01 본편1/7·단계2/3의 화물 회수 중이다. 현재 열려 있던 로컬0.102.3의 캐릭터 좌표 `(-1773.37,3.18,-695.24)`에서 실제 충돌체를 조회했다. 바로 앞 `x=-1778`에 투명도1의 `ForestBoundary` 두 조각이 있었다. 본편 확장 뒤 기존 경계를 화면에서만 숨기고 물리 충돌을 남긴 것이 직접 원인이다. [실행 중 세션의 전후 조회](active-session.json).

## 수정

- 외형에서 폐기된 `ForestBoundary`를 기존 블록아웃 정리 대상으로 추가한다. 10개 딥우드 구역의749조각에 충돌·쿼리·터치를 제거하고 이미 로드된 월드 재사용 시에도 복구한다. 실제 바닥·서버 지역/진행 권한 검사는 유지한다.
- 예전 검사가 투명도0.95 이상의 실제 충돌체를 제외하던 조건을 제거한다. 강화한 검사로 발견한34개 전투 표본의 나무 충돌도 수정했다. 새 전투길은 미술 폴더의 형제였기 때문에 기존 길 예약에서 빠져 있었다.
- 전체 월드의 전투길·사건 연결길·목표/도착 공간을 예약한다. 나무는 외형과 충돌체를 함께 안전한 바닥으로 옮긴다. 도착 검사 상자의 대각선까지 여유 폭을 확보해 같은 월드 재검수 때 재이동하지 않는다.
- 복귀 산책로를 새 나무 배치 예약에 포함한다. 산책로 전체 폭이 지역 바닥 안에 남도록 선택 공간의 외곽 여유를 늘린다. 실제 경사면에 몸이 겹치는 위치에는 걸을 수 있는 길처럼 장식선을 그리지 않는다.
- 게임 콘텐츠·보상·저장·전투 수치·목표/스폰 위치와 TD 운영 코드는 변경하지 않는다.

## 빌드와 검증 한계

초기0.102.4 [빌드](build.json)는 경계/전투길 수정 단계다. 이후 전수 검사에서 발견한 복귀길 보강을 포함한 최종 빌드는 **0.102.6**, 입력 `86594e1f22cec560fa92f73710daa6e5fde91db7`이다. [최종 빌드](build-final.json)·[역할10/도착 로딩192/실제 산출물 검사](artifact-final.log). 공유 저장소의 다른 작업이0.102.5를 이미 사용했으므로 덮어쓰기를 거부한 뒤 다음 버전을 사용했다. [버전 충돌 기록](build-version-conflict.json). 기존 미커밋 자산은 선별 스테이징에서 제외했으며 최종 빌드는 그 시점까지 정식 커밋된 TD 머리카락 작업을 포함한다.

전체 에픽 보행 진단도 보존했다. [원문](traversal-preview.log). 딥우드 밖의 고정 시설/도로 겹침8개와 Ember Caldera 복귀 경로 NoPath4개가 검출됐다. 이들을 통과나 이번 수정 완료로 간주하지 않으며 다음 ENG/QA가 시설 접근 의미와 실제 보행 경로를 재현해야 한다. 딥우드 수용과 구분한다.

기존 확장 종합 검사는 기하 검사 이후 왕좌 복원 UI의 `Crownheart` 존재 조건에서 실패했다. [원문](full-preview-2.log). 이번 전용 하네스는 그 검사 파일의 바닥/몸체 기하 부분만 실행하며 종합 UI 통과를 주장하지 않는다. 초기 나무/복귀길/멱등성 실패도 중간 로그로 보존했다.

고정0.102.6 전체 엔진 재실행은 처음 CLI 연결의 `Invalid first message received from Roblox Studio plugin` 오류로 두 차례 시작하지 못했다([첫 실패](native-launch-failure.log), [재시도](native-final.log)). 이후 **최종 산출물을 별도 Studio Edit 인스턴스로 직접 열어 동일 하네스를 실행했고 통과**했다. [최종 엔진 상태/로그 JSON](native-final-mcp.json)·[최종 로그](native-final-mcp.log).

`python3 tools/prepare-boundary-stuck-native.py`의 `/tmp/tlt-boundary-stuck-native.luau`를 최종0.102.6 Studio `34118dde-0d09-4e03-a889-35968997e488`의 Edit에서 `execute_luau`로 비동기 실행했다. 모듈5개 Source 일치·전체 문법을 먼저 검증했으며, `ServerStorage.DeepwoodStuckQA`의 상태가 `Passed`, 오류가 빈 문자열, 마지막 표식이 `BOUNDARY_STUCK_ALL_PASS true`임을 확인했다. 위 표의 모든 수치와171경로·차단0/바닥 누락0을 고정 최종 빌드에서도 재확인했다. 저장소 산출물 SHA256은 `af407726b3ee47b2d1af31700b3bac3502c8544b81e258a0e9e11ab238e7e5f8`이다. 이 인스턴스는 격리 검증용 Edit 씬이며 게시/정상 플레이 수용과 구분한다.

Roblox 게시·릴리스 태그·실계정 저장/재접속·실기기·멀티플레이·사용자 정상 조작 수용은 미검증이다. 상위 티켓 전체를 Done으로 바꾸지 않는다. 다음 QA는0.102.6에서 첫 화물 회수부터 본편7장·선택4장을 정상 입력으로 연속 진행하고, 밖의 경로 진단은 별도 후속으로 확인한다.
