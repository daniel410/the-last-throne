**전체 목록 리뷰는 완료하되 최종 미술 수용은 보류한다.** 영웅 개별 판정은 개선 권장22개·유지 후보106개다. 원소별 주 형상과 열린 바닥 표현은 유지할 방향이다. 먼저 원소 팔레트 연결과 기술 방향 의미를 정리하고, 다음으로 기술/보스의 위계와 개별 실루엣을 다듬는 순서를 권한다. 유지 후보는 미술 방향을 보존하자는 판단이며 실전·실기기 PASS가 아니다.

## 캡처와 판단의 보정

- 영웅은 Hero/Wind/Pixel의 .10초를 직접 샘플하고 AdvancedSkillVisual Tween층은 초기 상태로 복제했다. 입자는 재방출 후 동결했다. 첫 임의3개 대상점을 모든 기술에 준 시도는 폐기하고, 최종 points={}·체인/Multishot만 합성 목표 가이드를 사용했다.
- Quickfire는 수명.13초라 .10초에는 섬광이 이미 끝난다. 이 시각의 IsLoaded=false를 로딩장애로 해석하지 않았다. [이른 .035초 보완](hero-early/dwarf.gunner.quickfire.png)과 [메타데이터](hero-early/manifest.json)에서 실제 섬광을 별도로 확인했다. [늦은 재촬영](hero-retry/manifest.json)은 경위 검증용이다.
- 적3단 표본은 charge/primary/impact를 나란히 정규화한다. primary0.45배의 광역은 실제 범위/위력 비교가 아니다. 원본60장 오른쪽 impact는 모형 뒤로 가려졌으므로 강도 판정에서 제외하고 [앞면 근접20표본](enemy-impacts/manifest.json)으로 보완했다. 고리12개도 primary 형상 판단만 사용한다.
- 예고12개는 정규화하지 않은 실제 정의의 경계다. 실제 지형/벽/다인 교전의 가림은 미검증이다. 공통4개 Trail은 Clone 잔상 손실을 피하려고 살아 있는 생산 Trail을 임시 무기 모형에서 움직여 촬영했으며 실제 공격 클립 재생이 아니다. Selene는 필수 Bone/파트를 가진 단순 모형의 생산 합성 경로다.
- 큰 raw RGB가 CLI 전송1MB를 넘긴 시도는 폐기하고 적/예고는 무손실 Zstd RGB로 재촬영했다. PNG에 효과를 추가하거나 생략하지 않았다. 접촉시트의 배치/레이블/크기만 검토용으로 구성했다.

`hero-capture.luau`, `enemy-capture.luau`, `enemy-ring-capture.luau`, `enemy-impact-capture.luau`, `enemy-warning-capture.luau`, `common-capture.luau`가 재현 도구다. 저장/계정/서버 gameplay 없는 PlaceId/GameId0·플레이어0 격리 fixture에서 순차 실행했다. 모든 런타임 모듈은 [입력 SHA256](inputs.json)에 고정한다. [사진 수/PNG 해시 대조·재현 도구/로그 해시](review-validation.json). 게임 소스 변경·새 게임 빌드·VERSION 증가·Roblox 게시·릴리스 태그는 없다.

## 다음 담당과 수용 조건

1. ENG/ART: 공통 명중/Focus 팔레트를 원소 정본에 연결하고, 대표 준비→시전→접촉을 실제 TD 영웅/무기로 비교한다.
2. ART/DES: 전방 기술/예고의 방향·비색상 보조를 먼저 A/B 비교한 뒤 산탄·포격·자연·증기·궁극기/보스 위계를 다듬는다. 현재의 열린 바닥/명확한 원소 형상은 유지한다.
