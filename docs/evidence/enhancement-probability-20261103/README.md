# +9 확률 강화·게임 내 설명0.64.0

2026-11-03 · TLT-028/029/041/043/044/052/073/084 · ENG/DES → QA

사용자 요청으로 단계별 실패율0/10/20/30/40/50/60/70/80%를 실제 강화 reducer/서버/클라이언트에 적용했다. 지원 장비의 신규 강화 상한은 공통+9다. 실패하면 장비/단계를 보존하고 시도 보석/마석만 소모한다. 단계별 보석2n·마석max(0,n−3), 기본 Power/Armor/HP 단계당3%와 성공 투입 재료80%회수를 적용한다. 강화 시도 Gold0, 교환5보석+50Gold는 유지한다. Diamonds는 소비하지 않는다.

## 플레이어 화면

BLACKSMITH → ENHANCE에서 현재/다음 능력치, 성공/실패율·재료 비용/보유량과 실패 처리를 확인한다. 버튼을 다시 눌러 확인한 뒤 서버 저장 결과를 기다리며 자동 연속 강화는 없다. 성공/실패 메시지는 MerchantService가 돌려준 저장된 결과로 구분한다.

BLACKSMITH 제목 옆 **ENHANCEMENT GUIDE** 버튼으로 읽기 전용 영어 설명 화면을 연다. +1~+9 성공/실패·비용/효과, 실패 시 보존/소모, 재료 획득/교환, 회수와 확인/저장 흐름을 제공한다. 확률·비용은 실제 Enhancement 규칙에서 생성한다. TD 원본 panel/shellDetails/shellUpgrade 아틀라스를 사용한다. 외곽 셸은 기존 HeroMenuChrome을 유지하며 이전 룩앤필 리뷰의 외곽 원본화·교환 카드 우선순위·강화 카드 전체 모바일 재설계까지 완료하지 않았다.

강화 주요 버튼을 shellUpgrade로 구분하고 선택 BUY/SELL/ENHANCE에 텍스트/색 표시를 추가했다. 숨긴 카테고리54px을 제거하고 상단 도움말/닫기/탭의 겹침을 피하도록 행을 나눴다. 설명 영역은 기기 폭에 맞춰 문단 높이와 스크롤을 계산한다.

## 저장·기존 데이터

- 서비스가 요청을 접수할 때 서버 난수0~9999를 한 번 생성해 shopPending에 보존한다. UpdateAsync 콜백과 SaveUnknown 재시도는 같은 값을 사용한다. 클라이언트의 난수/확률 필드는 네트워크 허용 목록에 없다.
- 단계·규칙 버전·아이템 버전·계정 revision을 검사하고, 재료 차감/성공 여부/성공 원장/아이템 버전/영수증을 단일 계정 키에 함께 저장한다. 실패도 revision과 아이템 버전을 올린다.
- 영수증 fingerprint가 같은 재요청은 저장된 결과로 응답한다. 내용 변경은 거부한다. 최근96개 영수증에서 제거된 오래된 요청도 필수 revision 때문에 새 시도로 실행되지 않는다. 회수는 실패 소비를 원장에 더하지 않으며 최근 영수증과 장비의 마지막 시도 기록을 삭제하지 않는다.
- 최초 새 확률 시도에 계정 schemaVersion을2로 올린다. 신규 서버는1/2를 읽지만 과거 schema1 전용 writer는2를 읽거나 덮어쓸 수 없다. 예전 서버로의 롤백은 schema2 호환 코드를 유지해야 한다. 기존 +10/Lv60+ 장비·능력치·구재료/혼합 원장은 보존한다. +10 장비의 추가 강화는 거부하고 회수는 기존 원장 기준이다.
