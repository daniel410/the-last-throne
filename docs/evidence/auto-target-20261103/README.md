# 네 영웅 자동 타겟·설정 OFF

2026-11-03 · TLT-005/006/028/032/033/050/061/084 · ENG/Research → QA/DES · 0.69.0 로컬 시험 구현. 상위 티켓 수용 완료는 아니다.

## 사용자 결정과 변경

사용자는 타겟 유지/이동 문제를 네 영웅의 공통 문제로 명시하고 RPG 추가 조사·어린 연령의 쉬운 조작·자동 타겟을 논의한 뒤 설정에서 끄는 옵션을 요청했다. [공식8사례 비교·Roblox 조사 한계](../../research/2026-11-03-combat-targeting-and-younger-players.md)를 근거로 전방 선택 보조를 구현했다. 연령별 우월성을 사용자 실험으로 입증한 것은 아니다.

- `GameSettings`/`SettingsText`의 `Auto Target` 기본 ON·OFF를 기존 TD 프레임/버튼/스크롤 목록에 추가했다. 메뉴 설명과 패드 초기 포커스도 갱신했다. 다른 설정처럼 현재 접속 동안 유지하며 재접속 때 ON이다.
- `K0Targeting`은 네 클래스의 기본기/실제 장착 슬롯1~5/해금 궁극기 정의에서 사거리·높이를 가져온다. 마법사 기본 공격은 기존 지팡이 근접이며 주문만 주문 사거리를 쓴다.
- 공격 입력이 있을 때, 살아 있는 등록 적·정상 루트·전방120°·현재 화면·현재 기술 사거리/높이·장애물을 확인해 가까운 후보를 고른다. 유효한 직접 선택과 기존 자동 선택을 우선해 대상 흔들림을 줄인다. 공격 없이 선택/발사를 반복하는 루프는 만들지 않았다.
- 보통 이동은 타겟을 즉시 지우지 않는다. 공격 시 이동 방향을 기준으로 뒤쪽 표적 보조를 제외하며, 부적합한 자동 선택은 다음 공격 때 교체/정리한다. 직접 선택 표시는 공격에 부적합해도 유지할 수 있으나 해당 공격 요청에는 전달하지 않는다. 엘프의 직전 이동 즉시 해제 구현을 최신 공통 계약으로 대체했다.
- 자동 표식은 기존 노란 Highlight를 사용하고 선택 알림을 반복하지 않는다. OFF는 자동 선택 표식을 즉시 정리하며 새 자동 선택을 중단한다. 직접 선택과 기존 전방 공격 판정은 유지한다. X 수동 해제는 누르고 있던 공격 반복도 멈춰 즉시 재획득하지 않게 한다.
- 서버는 버퍼된 기본기와 기술 시작 시 관측 수평 속도를 재검사해 이동 뒤쪽 타겟을 향한 회전을 제외한다. 미세 물리 흔들림은 기존 WalkSpeed의5% 이내에서 제외한다. 자기 중심 광역/자기 강화/회수 기술은 새 자동 적 선택 대상이 아니다.
- 기존 서버 피해·MP·쿨다운·보상·최종 명중 검증을 유지한다. 서버가 이미 승인한 동작의 공격 취소 규칙을 바꾸는 작업은 아니다.

## 검증과 증거

- `lua tests/auto-target.spec.lua`: 실제 K0Targeting/설정/공통 규칙과 서버 이동 필터 본문을 실행하는 CPU fixture. 네 클래스의 ON/OFF·수동 우선·기존 자동 선택 유지·전진/후퇴·사망/스트림 아웃·화면/벽/사거리/높이·실제 기술 정의·슬롯·안정 우선순위·설정 재생성/부울 계약·서버 버퍼 이동을 검사한다. 메뉴/컨트롤러 이벤트 연결 일부는 소스 검사이며 엔진 조작 검사가 아니다. 최종 개수와 결과는 `cpu.log`.
- `lua tests/k0-rules.spec.lua`: 기존 서버 타이밍/명중 결정125개 PASS (`rules.log`).
- `/tmp/td233-luau/luau-compile --null`로 변경 Luau7개 컴파일 PASS (`compile.log`). 첫 실행은 잘못된 CLI 모드 인자 `null`로 종료1이었고 올바른 `--null`로 재실행해 통과했다. 게임 빌드 실패가 아닌 검증 명령 사용 오류다.
- `git diff --check`: PASS.
- `tests/elf-movement-target.spec.lua`는 폐기된 동작을 요구하지 않도록 새 공통 회귀 검사의 호환 진입점으로 교체했다.
- 고정 소스의 Lobby/Battle 빌드와 버전·소스 커밋·LFS 입력 검증·산출물 SHA256은 `build.json`에 기록한다. 기존 미커밋 모션/회피/로비/원정 변경은 커밋과 고정 빌드 입력에 포함하지 않는다.

Roblox API 근거(2026-11-03 확인): 클라이언트 이동 의도는 [Humanoid.MoveDirection](https://create.roblox.com/docs/reference/engine/classes/Humanoid/MoveDirection)을 사용한다. 이 속성은 비복제이므로 서버 재검사는 루트의 관측 수평 [AssemblyLinearVelocity](https://create.roblox.com/docs/reference/engine/classes/BasePart)를 사용한다. 화면 범위의 [WorldToViewportPoint](https://create.roblox.com/docs/reference/engine/classes/Camera)와 월드 Raycast를 분리해 확인한다. 서버 속도도 네트워크 지연의 영향을 받으므로 실제 버퍼/급반전은 실기기 검증 대상이다.

## 남은 검증·인계

현재 Studio MCP에 연결된 인스턴스가 없어 실제 엔진 Play·화면·입력·버퍼/급반전 재현은 수행하지 않았다. 패드 포커스/모바일 가로 스크롤/읽기·4인+AI/고밀도 후보 선택 성능·게시 클라이언트·10~15세 관찰·정식 각도/거리 밸런스는 미검증이다. Place 게시/실제 릴리스/태그를 수행하지 않는다.

QA/DES는4클래스×3입력기×ON/OFF에서 무리 속 직접 선택→이동→공격·급후퇴·기존 적 사망→다음 공격·벽/화면 경계·자기 중심 광역·궁극기·메뉴 재생성을 검증한다. 실제 연령별 실험에서는 재선택 횟수/의도와 다른 선택/뒤돌림/회피 성공을 비교한다. 수용 전까지 상위 작업은 진행 중이다.
