# 스토리 저장 대기와 지도 표시 복구

2026-11-17 · TLT-040/087, TLT-028/061~065/084 · ENG → QA · 0.113.8 후보, 미게시.

사용자는 입장 직후·스토리 진행 중 몬스터/스토리가 약10초 늦게 나타나며, 맵 메뉴에서 지도가 보이지 않는다고 보고했다. 기준 소스는 `0d14b36b`다. [제품 계약](../../product-contracts.md)의 서버 권위·개인 진도·완료 지역 이동을 유지하는 결함 수정이며 별도 게임성 조사 대상이 아니다.

## 저장 대기

기존 코드는 지도 탐색 칸과 처치 보상을 각각 계정 키의 `UpdateAsync`로 저장했다. 탐색 작업이 연속으로 잠금을 점유하고, 처치 보상도 하나씩 저장하므로 다음 목표 저장과 이에 의존하는 교전 시작이 기다린다. 실제 서비스·저장소·진도 계산기에 저장 응답1.5초를 주입해 다음을 재현했다. 실제 게시 서버의 측정값이나 사용자가 겪은 지연의 원인 확정은 아니다.

| 조건 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 탐색6칸 뒤 첫 목표 저장 | 7회 저장·10.5초 | 1회 저장·1.5초 |
| 같은 시점6처치 뒤 목표 저장 | 7회 저장·10.5초 | 2회 저장·3.5초 |
| 0.1초 간격6처치 뒤 목표 저장 | 비교 미실행 | 3회 저장·5.1초 |

- 탐색 칸은 다음 계정 거래에 최대32개씩 합친다. 다른 거래가 없으면5초 간격으로 묶어 저장하며, 진행/보상 대기열에 우선권을 준다. 저장 전에는 탐색 정보의 영속 반영이 지연될 수 있다. 종료·이동 전에는 남은 관찰을 저장한다.
- 같은 프레임의 처치를 모아 기존 보상 계산기·개별 처치ID·연속 번호를 그대로 적용한다. 거래당 최대32개이며 사망 페널티를 넘어 묶지 않는다. 처치 기록은 목표 완료·새 원정 전에 확정한다.
- 요청 중 들어온 관찰/처치는 현재 묶음에 추가하지 않는다. 불명 응답은 고정된 묶음으로 재시도하고 성공한 항목만 대기열에서 제거한다. 실패한 로드/저장을 신규 프로필로 대체하지 않는다. 하나의 계정 키 내부 거래이며 다중 키 원자성 주장이 아니다.
- 현재 입장 에픽만 생성하는 로딩 정책과 인접 에픽 준비는 변경하지 않았다.

## 지도 표시

기존 `AtlasPlate.draw`는 지도 데이터 누락/압축 해제 실패와 이미지의 픽셀 입력/Content 연결 오류를 메뉴 호출자까지 전파했다. 데이터 폴더 누락을 주입한 기존 코드에서 `attempt to index nil with 'Relief_DW-01'`로 지도 캔버스 생성 중단을 재현했다.

- 데이터가 없거나 손상되면 기존 실측 지형 도식으로 지역·길·이름·목표를 계속 그린다. 데이터가 도착한 후 다시 열면 촬영 지도로 돌아온다.
- 이미지 생성뿐 아니라 픽셀 입력·표시 연결 실패도 처리한다. 이때 기존 촬영본의 색/투명도 기반 UI 대체 표시를 사용하고 중간 이미지 객체를 정리한다.
- 원본44개 촬영 데이터·좌표·완료 조건·보상은 수정하지 않았다. 로비와 배틀이 공유하는 캔버스에 적용된다.

## 검증

[명령·결과·소스 해시](validation.json).

- Lua 회귀13묶음 8,845검사 통과. 새49검사는 지연 재현, 묶음/새 도착 분리, 콜백 재실행, 응답 유실, 저장 실패, 중복 처치, 사망 순서, 새 원정 차단, 종료/이동 저장을 포함한다.
- Studio Luau VM에서도 같은 저장 시험49검사를 통과했다. 메모리 저장 대역·가상 시계 시험이며 실제 DataStore 성능은 아니다.
- 지도 엔진56검사 통과: 누락/빈/손상 데이터, 이미지 API 실패, 픽셀 실패, Content 연결 실패,44개 촬영본. 캔버스는 실제 GUI 인스턴스, 좌표 계산과 공통 모듈을 사용한다.
- 격리 PlaceId=0의 실제 LocalScript에서 지도 데이터를 잠시 제거해도 로비 메뉴·실측 도식을 생성했고,2초 후 데이터 복원/메뉴 재생성 뒤 촬영본과 EC-03 상세를 확인했다. `MissingDataMenuReady`, `RecoveredImageMenuReady`, `DetailReady` 모두 true, 상세 ImageLabel의 `IsLoaded=true`였다. 운영 저장 접근과 원본 Studio 소스 편집은 없었다.
- `src`의543 Luau 파일 컴파일 오류0. 기존 사용자 자산 변경·삭제는 보존했다.

## 미검증·다음 담당

게시된 실제 클라이언트에서 사용자가 겪은 두 현상의 정확한 원인, 네트워크 복제 순서, 실제 저장 응답시간/P95, 모바일·4인 부하·원정 전체 진행·시각 수용은 미검증이다. 이번 격리 시험은 일반 계정의 실제 메뉴 조작/Teleport를 대신하지 않는다. 다음 담당은 릴리스/QA이며 후보 게시 후 입장→첫 목표→연속 처치→다음 목표, 로비/배틀 지도 최초 열기·재열기를 확인한다. TLT 티켓과 G7 전체 완료로 처리하지 않는다.
