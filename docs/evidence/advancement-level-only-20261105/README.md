# 레벨 기준 전직

2026-11-05 · TLT-028/050/052/057/084 · ENG → QA · 0.75.6

사용자는 Lv22에서 전직 선택이 안 된다고 보고한 뒤 다른 조건을 제거하라고 지시했다. UI와 서버의 거점·누적 처치 수 조건을 제거했다. 모험/전투 중에도 Lv20/40/60/80에 자기 클래스의 계열을 선택하고 이후 같은 계열의 다음 단계로 전직할 수 있다. 기존 확인 버튼·최초 클래스 불변·순차 단계·기술 해금/궁극기 규칙은 유지한다. 이전 시험/거점 제한보다 이번 사용자 결정이 우선한다. 명확한 조건 제거 요청에 따른 수정이며 추가 외부 사례 조사는 수행하지 않았다.

변경 경로: SkillAdvancementView의 활성화/요구조건/안내, HeroGrowthGui의 거점 복귀 안내, InventoryService의 서버 사전 검사와 저장 콜백, InventoryRules의 계정 검사, HeroProgression의 전직 및 저장 프로필 검증. battleWins 필드/누적 기록·XP·포인트·장비·편성은 유지한다. 데이터 준비·서버가 확인한 소유 영웅/유효 생명·동일 영웅/세대·revision·중복 requestId/저장 잠금은 계속 검사한다. 스탯 투자/스킬 편성의 비전투 검사는 전직과 별개로 유지한다.

검증 환경은 로컬 Lua와 계정 저장 어댑터 대역이며 실제 Roblox 계정에 쓰지 않았다.

`tests/skill-advancement-native.luau`도 거점밖·처치0 fixture로 갱신했지만 이번에 실행하지 않았다. 현재 연결된 Studio는 TD이므로 변경하지 않았다. 실제 Studio GUI/게시 클라이언트/실계정 DataStore/실기기·독립 QA/사용자 수용은 미검증이며 부모 티켓을 완료 처리하지 않는다. 기존 미커밋 Blender·증거 파일은 제외한다. 다음 QA는 새 빌드에서 모험 중 실제 클릭/저장/재접속과 모바일 안내 적합을 확인한다. 게시할 때에는 거점/배틀 모두 새 저장 검증 규칙을 사용해야 한다. 구형 서버는 처치 수 미달의 전직 프로필을 허용하지 않는다.

고정 소스 빌드의 커밋·명령·산출물 해시는 [build.json](build.json)에 기록한다. Roblox 게시·릴리스 태그는 수행하지 않는다.
