# TD CHECK REJOIN 로비 버튼

2026-11-01 · TLT-028/061/084 · ENG/DES → QA · 0.58.20 로컬 시험판·미게시

사용자 첨부 TD 화면과 실제 TD Client/소스를 대조해 CHECK REJOIN을 안전 영역 상대(12,12),136×44로 추가했다. 기존 TD shellDetails126012242626142의(514,64)/(254,102), BattleChrome revive97570429280107의(248,519)/(275,196)을 그대로 사용한다. 하트/날개28×28, 캡션 좌측48·우측24·GothamBold16·두 줄 배치·SliceScale.45도 같다. 새 그림 생성/업로드와 TD 운영 소스 변경은 없다.

클릭은 기존 모험 창을 열고 ExpeditionRequest GetState를 전송한다. 기존 서버 상태의 재접속 가능한 원정이 있으면 해당 창의 REJOIN EXPEDITION을 별도로 선택한다. 버튼 자체는 Rejoin/Solo/Teleport를 요청하지 않는다. 서버의15분 만료·멤버십/티켓 검증과 TD/RPG의 분리 계약은 유지한다. 영웅 선택/로비 외 상태는 기존 ADVENTURES와 같은 표시 규칙으로 숨긴다. 새 재접속 서버 기능을 구현했다고 보고하지 않는다.

폭500미만에서는 왼쪽 재접속/오른쪽 MENU 사이에 지갑 폭을 맞춰 겹침을 줄인다. 일반 데스크톱 지갑 위치/크기는 유지한다. 이 좁은 화면 규칙은 실제 모바일 검증과 구분한다. 기존 제작 스킬과 TD 공통 자산 재사용 계약에 따른 구체적 UI 이식이다. 원본 해시는 td-sources.json에 기록했다.

Studio Edit의 버튼 원본/위치 검사10개·기존 상단 메뉴/지갑 회귀32개 통과. 실제 Play에서 CHECK REJOIN을 정상 마우스 클릭해 모험 창 열림과 서버 GetState 수신을 확인했으며 자동 Rejoin 요청은0건이었다. 실제 로비 화면에서 위치·하트 아이콘 로드를 확인했다. 최초 검사에서32비트 SliceScale을 정확한 소수 비교로 검사해 실패했으며 허용오차.001로 시험만 수정했다. 실패 fixture는 제거했다. 검증은 verify.luau/native-results.json, 고정 빌드는 build.json을 따른다.

실제 게시된 재접속·Teleport·영구 저장·만료/서버 장애·실기기 수용은 미검증이다. 다음 담당 QA는 게시 테스트 Experience에서 기존 원정 재접속과 모바일 상단 겹침을 검증한다. 다른 미커밋 서버 작업은 포함하지 않는다.
