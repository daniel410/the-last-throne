# 로비 하단 영웅 카드와 Lumi 입력 복구

2026-11-25 · TLT-028/057/070/084 · ENG → QA · 로컬 빌드와 Studio 입력 검증 완료.

- 0.115.124 Studio 세션에서 로비와 PLAY는 표시됐지만 서버의 빈 보유 목록에 따라 하단 카드 네 장이 모두 숨겨졌다. 서버 로드가 끝난 빈 목록에서는 승인된 네 초상으로 첫 영웅을 생성할 수 있다. 보유 영웅이 생기면 보유 클래스만 하단에 표시하며, 로드 실패 중에는 생성 입력을 허용하지 않는다.
- 첫 로비 입장에서는 해금 전 Lumi의 몸이 숨겨져도 프롬프트가 살아 있었다. 선택 영웅과 일치하는 서버 인벤토리 스냅샷으로 로비 재회 장면을 갱신한다. `HG-07` 완료 영웅에게만 Lumi의 모습과 프롬프트를 표시하고, 대화의 자격 판정은 기존 서버 로직에서 실행한다. 로비 스냅샷과 전투 저널이 서로의 장면을 덮어쓰는 경로를 분리했다.
- Lumi를 중앙 길의 로비 원점 기준 `(0, 0, 12)`로 옮겼다. Lumi와 창고 프롬프트의 중심 거리는 27.24스터드로 활성 반경의 합 22스터드보다 크다. 두 곳에서 키보드 `F`와 게임패드 `X` 설정을 유지한다.

## 검증

- 고정 빌드 **0.115.125**를 Git 소스 `bb3f2edcbb706360c4c631495ab204fef748e114`에서 생성했다. [명령·산출물·SHA-256](build.json).
- Lua에서 영웅 세션 149건, 마지막 선택 21건, 로비 진행 문구 9건 통과. 단일 산출물의 역할·도착 검사도 통과했다.
- 격리 Studio Edit에서 HUD의 16가지 로스터 × 4개 화면 등 550건, 재회 장면 402건, 기존 얼굴 자산으로 전환한 재회 장면 12,092건, 난이도별 전투 상태 분리 64건, Dawnspire 왕좌 및 접근 3,229건을 통과했다. 최초 합본 실행에서 현행 메시의 얼굴 Decal 개수가 옛 고정값과 달라 실패한 검사는 메시와 기존 얼굴 자산을 각각 검사하도록 보정하고 별도 Edit 세션에서 다시 실행했다.
- 빌드와 바이트가 같은 복제본을 Studio Play로 실행했다. 정상 빈 계정에서 네 초상이 로드되고, Knight 카드를 클릭하면 서버가 영웅을 생성·선택해 하단에 Knight만 남기고 레벨을 표시했다.
- 별도 Studio Play 복제본은 Studio 세션용 초기 프로필에 미완료 Knight와 `DeepwoodProgress`로 `HG-07`까지 완료한 Mage를 넣었다. Mage로 첫 입장 후 Lumi 앞에서 `F`를 눌러 대화를 열고 창고 앞에서 같은 키로 창고를 열었다. Knight로 전환하면 Lumi가 숨고 같은 자리의 `F`로 대화가 뜨지 않았다. Mage로 다시 선택하면 Lumi 프롬프트가 돌아왔다. [Studio 관찰값](studio.json).

게시 클라이언트, 실제 계정 DataStore, 실기기 터치·게임패드, 사용자 수용은 미검증이다. 다음 담당은 QA이며 게시 테스트 환경에서 기존 영웅과 최초 영웅 흐름을 확인한다.
