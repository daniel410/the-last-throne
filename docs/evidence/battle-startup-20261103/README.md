# 로비·배틀 초기화 분리

2026-11-03 · TLT-003/028/057/061/084 · ENG → QA · 0.68.1

사용자 지시: 로비에서 캠페인 맵과 전투 기능을 초기화하지 않는다. 배틀 시작 때 선택한 임무의 에픽에 해당하는 맵을 생성하고 전투를 준비한다.

서버 시작에서 Studio 전체 캠페인 생성·전투 서비스 시작·훈련장 생성·전체 NPC 템플릿 예열을 제거했다. 게시 Battle 서버는 서버 측 원정 티켓 검증 뒤 저장된 missionId에서 에픽을 결정한다. 클라이언트 TeleportData의 에픽 주장을 사용하지 않는다. Studio의 솔로/파티 입장도 선택 임무를 같은 생성 경로에 전달한다. 에픽별 지형·목표·활동·미술·저장함만 생성하며 다른 에픽으로 향하는 미생성 연결 길은 만들지 않는다. 전체 에픽 무인자 생성은 기존 오프라인 미술/QA 도구 호환용이며 런타임에서는 사용하지 않는다.

계정·장비는 가벼운 전투 어댑터를 통해 로비에서 계속 사용할 수 있다. 실제 CombatService require/start와 적 컨테이너는 첫 배틀/훈련 진입 때 생성한다. 훈련장 지형과 훈련 몬스터도 훈련 진입 전에는 없다. 클라이언트 BattleController는 LoadingTutorial/Tutorial/Respawning에서 한 번 시작하며 HUD·전투 지도·공격/방어/회피 입력·무기/몬스터/피격/스킬 효과를 담당한다. 로비 공통 UI·카메라·NPC 외형은 유지한다. 지도와 전투 일지는 훈련 진입이 아닌 실제 모험 때 연결한다.

맵 생성은 서버 내 단일 실행으로 직렬화하고 완성된 에픽은 재입장에서 재사용한다. Studio에서 다른 에픽을 시작하면 기존 테이블을 보존하며 그 에픽만 추가하고 목표/동료 캠프를 연결한다. 이미 입장한 다른 플레이어를 위해 이전 에픽은 자동 삭제하지 않는다. 생성 오류 후에는 부분 월드에 입장시키지 않고 해당 서버의 추가 생성을 차단한다. 재접속/새 서버로 복구한다. 반복/완료 임무의 복귀 위치는 전역 다음 스토리가 아닌 실제 원정 임무를 사용한다.

원인이 명확한 시작 경로 결함 수정으로 별도 RPG UX 비교 설계는 하지 않았다. [Roblox 공식 성능 문서](https://create.roblox.com/docs/performance-optimization/improve)의 비필수 시작 작업 지연 지침을 2026-11-03 확인해 적용했다. 읽기와 코드 실행의 증거는 구분한다.

검증: `lua tests/battle-startup.spec.lua` 223개 PASS. 실제 콘텐츠 전체 구역의 에픽 분할·연결 양 끝·안정ID·다른 생성기 미호출·반복 진입·에픽 추가 시 테이블 보존·로비 장비 읽기 중 전투 미로딩·전투 단일 시작을 검증한다. 생성기 호출은 mock이며 실제 지형 생성 증거가 아니다. 변경 Luau 컴파일·`git diff --check` PASS. 고정 소스 빌드/Studio 실행은 아래 후속 기록을 따른다.

미검증: 게시 클라이언트 이동·실계정 저장/재합류·실기기/4인+AI·전체 전투 완주·접속 시간 전후 계측·최종 사용자 수용. 상위 티켓을 완료 처리하지 않는다. Roblox 미게시·릴리스 태그 없음. 다음 담당 QA는 로비 콜드 접속과 다섯 에픽 입장/복귀·훈련→모험·파티 동시 요청을 확인한다.
