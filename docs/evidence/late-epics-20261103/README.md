# Gloamwood · Haunted Graveyard 로컬 구현

2026-11-03 · TLT-064/065/057/061/084 · 0.65.1 · 로컬 시험판·미게시

기존21개 뒤에 GW-01~07/HG-01~07을 추가해5에픽35개 본편을 연결한다. 승인된 구조/우정/회복 서사를 적용하며 HG 안정ID와 고정6091XP/6280Gold는 보존한다. GW 고정 보상은 예산 미승인 상태의 임시0이며 처치/반복 원정 재료는 기존 서버 규칙을 쓴다. Lv1~80 성장 예산/최종 밸런스를 완성한 것으로 처리하지 않는다. 후반 입장 레벨은 기존 말미Lv27에서 새 무근거 성장 잠금을 더하지 않는 시험값이다.

## 변경과 원천

- [승인 서사](../../production/five-epic-adventure-story-2026-10-30.md), [리서치/적용](../../research/2026-11-03-late-epic-playable-chain.md).
- GW 정찰대 구조/개인 Tali 호위·안전 야영지·엔트/지네 킹/여왕·숨은 묘지 입구. HG 동맹 집결/유령 Lumi/성문 돌파/왕좌 장치/유한 증원 Veyr전/심장 회수/포탈 폐쇄. 저장 서브스텝·재요청/실패 큐·서버 거리/영웅 검사와 기존 파티 계약을 재사용한다.
- 두 지역14개 지반/연결길/체크포인트·NPC 역할/창고/기존 Selene 편성 게시판. 로비 지도/퀘스트/원정과 영어 목표/완료 화면을 연결한다. 완료된 개인 영웅의 로비에서만 복구 왕좌/심장/축제 배너를 표시한다.
- 사용자 명시 지시에 따라 HG는 [기존 TD10종](../../../assets/shared/td-haunted-graveyard/manifest.json)의 메시·텍스처ID를 그대로 가져왔다. Veyr는 기존 Dread Commander 외형을 공유한다. TD 소스/잔액/게시를 변경하지 않는다. 신규 Roblox 자산 업로드는 없다.
- 사용자 최신 지시에 따라 GW8종은 교체 가능한 네이티브 블록 모델이다. 거미8다리·지네10마디/20다리·박쥐 날개·엔트 팔/뿌리와 단순 동작을 추가했다. 승인 컨셉의 최종 메시/얼굴/2~3k tris 수용이나 Blender 제작 완료를 주장하지 않는다. HG는 기존 검토된 동작 곡선을 재사용하며 전용 신규 모션 제작은 후속이다.
- 게임 모델/진행 ID와 외형 생성기를 분리해 후속 모델 교체 때 저장/퀘스트를 바꾸지 않는다. 개인 구출 거미줄/왕좌 장치/심장/포탈의 시각 상태를 서버 확정 저널로 표시한다.

## 검증 상태

정적: `lua tests/late-epics.spec.lua` 954검사 PASS; 기존 Frozen460/Ember598/스토리 완료356검사 PASS. `python3 tests/haunted-graveyard-assets.spec.py` 원본10템플릿/11EnemyKind·모델 내부 스크립트 없음·메시ID/해시 PASS. 전체 Lua43개 중42개 PASS. 기사 외형 mock1개 실패는 변경 전HEAD에서도 재현했다([기준](baseline-failure.json)). 전체 Luau 컴파일과 [Lua 결과](lua-tests.json)를 별도 기록한다. 보상 정본 산술 검사는 `/tmp/tlt-progression-check.json`으로 실행했으며 원본을 수정하지 않았다.

엔진·고정 소스 빌드 결과는 후속 검증 파일에 추가한다. 실제 플레이어 정상 전투 완주·계정 저장 장애/재접속·게시 클라이언트의 자산 권한/Experience 이동·PC/터치/패드·4인+AI·최종 미술/밸런스·Lv80 성장·관찰 수용은 미검증이다. 임시 지형/모델을 최종 미술로 보고하지 않는다. 상위 티켓은 In Progress이며 문서/정적 통과로 닫지 않는다.

다음 담당: QA의 정상 입력/솔로·다인·실기기 수용, ART의 GW 외형 교체, PLAN의 GW 보상 및 Lv1~80 예산. Roblox 게시/릴리스 태그는 이번 로컬 구현에 포함하지 않는다. 초기 로비/이동/애니메이션 미커밋 작업은 선별 커밋·고정 빌드에서 제외한다.

## 엔진 검증과 빌드

0.65.0 고정 소스 `b6122de`에서 Lobby/Battle Rojo 빌드 성공([빌드/해시](build.json)). 같은 Battle 파일을 별도 미게시 Studio에서 열어 실제 지반/메시·네이티브 모델·모션30/60/144Hz·서버 목표 처리를 검사했다. [엔진1,930검사](native-0650.json) PASS이며 플레이어/계정 저장 의존성만 fixture다. 자동 전투 승리는 테스트에서 직접 피해를 주므로 정상 조작 완주/난이도 수용을 뜻하지 않는다. 로비 지도88/퀘스트71개 엔진 검사도 PASS했다. 첫 시도는 자동 시작을 끈 fixture에 Remotes/Combat 초기화가 없어1,567검사 뒤 실패했고, 실제 CombatService 초기화를 추가해 통과했다. 게임 결함 수정으로 포장하지 않는다.

후속0.65.1은 두 안전 캠프에 Selene의 실제 TD 외형을 배치해 미편성 때도 만나게 하고, 스트리밍이 늦은 개인 완료 소품에도 확정 상태를 재적용한다. 새 진행/보상ID는 만들지 않는다. 최종 빌드/엔진 결과는 별도 기록한다. 아래 실제 Studio 렌더는0.65.0과 공통인 모델 생성기의 검토이며 최종 미술 수용을 대신하지 않는다.
