# 엘프 화살의 뒤·옆 발사 수정

2026-11-13 · TLT-032/054/084 · ENG → QA. 사용자의 뒤·옆 발사 재신고를 재현하고 수정했다. 이전 [발사 확인](../elf-confirmed-release-20261111/README.md), [모션/착용/VFX 수명](../visual-lifecycle-fit-20261113/README.md) 검증을 대체해 최종 사용자 수용을 선언하는 기록은 아니다.

## 재현과 변경

0.104.28 실제 서버/클라이언트 함수를 격리 엔진에서 호출했다. [기준 원문](baseline-native.log)의 방향 검사31개 중14개 경우가 실패했다. 기존 직선 비행 검사는 발사 이후의 방향 고정과 기본 공격을 확인했지만 아래 준비/발사 원점 조건을 빠뜨렸다.

- **서버 공통 기술9경우:** Aimed Shot/Rapid Fire/Multi Shot의 선택 대상이 준비 중90/-90/180도로 이동하면 기본 공격에만 적용되던 정면 범위 검사를 우회했다. 공통 화살 기술도 준비 시 승인한 방향의 기술별 범위를 적용한다. 범위를 벗어난 대상을 따라 꺾거나 피해를 주지 않고, 잠근 방향으로 빗나간다. 처음 수동 선택한 옆 대상을 향해 정상적으로 몸을 돌리는 기능은 유지한다.
- **근접 시각2경우:** 서버 원점에서3.2stud 앞의 대상과, 좌우1.5stud/앞3stud의 활 끝을 조합하면 활 끝에서 대상까지의 벡터가 약82도로 꺾였다. 활 끝 보정이 서버 발사선과15도 이상 차이나면 활 끝을 서버 선 위로 투영한다. 투영은 원점과 도착점 사이로 제한한다. 원거리에서 자연스러운 실제 활 끝 출발은 유지한다. 실제 판정/도착점은 바꾸지 않는다.
- **몸 회전3경우:** 화면의 활은 현재 Root 회전을 따르지만 서버는 준비 시 방향을 잠그고 있었다. 몸이90/-90/180도 돌아도 활은 같은 발사 방향을 보도록 서버의 `K0BowAim`을 사용한다. 한 속성에 공격 순번과 방향을 함께 게시한다. 이전 순번·잘못된 값은 거부하고, 중단/해제 시 지운다. 표시 코드가 Root를 회전/이동시키지 않는다. 구형 서버는 기존 몸 방향으로 폴백한다.

TD 원본 화살의 실제 Native Mesh도 확인했다. 주요 길이는Z축3.8542stud이며 음의Z에 화살촉, 양의Z에 깃이 있는 기존 방향을 유지했다. 메시를 임의로 뒤집어 위 재조준 결함을 숨기지 않았다. 피해·MP·쿨다운·기본 공속·저장/장비 소유권·TD 운영 코드는 변경하지 않는다. 정면 범위를 벗어난 대상의 잘못된 유도 명중만 제거한다.

## 검증

- `tests/elf-arrow-direction-native.luau`: 실제 private 서버 발사·클라이언트 활 원점/그립 함수로47검사 통과. 기본/공통3기술 ×정면/좌/우/후방, 근접/원거리 활 끝, 몸 회전, 이전/잘못된 방향 패킷과 Root 불변을 검사한다.
- 기존 직선 발사570검사: 실제 기본/공통 기술의 방향 패킷 게시·취소도 추가했다. 피해/공격당 발사1회·이동/회전 중 비행 방향·30/60/144FPS를 유지한다.
- 공속873·Blender Reload986·R6/R15 활4,890·화살통253·서버 발사 확인9검사. 후보 합계 **7,628통과**. [원문](candidate-native.log), [입력 해시](candidate-inputs.json).
- 현재 사용자가 열어 둔0.104.25 Studio **Edit 메모리**에도 관련3모듈의 이번 변경9개 hunk만 적용하고 원문/컴파일을 재확인했다([readback](studio-readback.json)). 다른 Scene/스크립트 변경은 보존했다. 이전 고정 Place 파일을 저장해 덮어쓰거나 Roblox 게시하지 않았다. 다음 Play부터 이번 방향 수정을 사용할 수 있으나 이 메모리 상태를0.104.29 전체 빌드로 보고하지 않는다.

## 고정 빌드·남은 수용

0.104.29 소스 고정·빌드·동일 산출물 회귀 결과를 마감 때 추가한다. 재현 도구는 `tools/prepare-visual-lifecycle-tests.py --place <빌드> --output <임시 폴더>`다.

게시 클라이언트·다인 지연/소유권·모바일·사용자 실제 조작 수용은 미검증이다. 다음 담당 QA/사용자는 근접 사격, 이동하며 연속 사격, 적이 등 뒤로 지나가는 준비 동작, 회피 직후 속사/다중 사격을 새 빌드에서 확인한다. 상위 티켓 완료 상태는 변경하지 않는다.
