# 스토리 몬스터 출현 대기 후속

2026-11-18 · TLT-040/087 · ENG → QA/릴리스 · 0.113.13 후보

0.113.12의 저장 묶음 이후에도 사용자가 몬스터 생성이 느리다고 보고했다. 기존 서버는 마지막 처치 묶음이 확정될 때까지 목표 완료 요청을 대기시켰고, 확정 뒤 별도 저장을 마친 시점부터 다음 목표의 몬스터를 활성화했다. 파티에서는 첫 목표 저장이 다른 파티원의 마지막 처치 보상 등록보다 먼저 시작될 수 있었다. [이전 저장 수정](../campaign-save-map-20261117/README.md) · [기준 게시 기록](../release-0.113.12-20261118/README.md).

서버는 마지막 처치 보상을 전원에게 먼저 등록한다. 아직 제출하지 않은 처치 보상은 목표 완료와 같은 계정 거래에 넣고 처치부터 적용한다. 제출 중인 저장과 사망 페널티의 순서를 보존한다. 불명 응답은 고정된 처치 기록과 목표로 재시도하며, 성공이 확인된 묶음만 제거한다. 퇴장 중에도 남은 결합 저장을 재시도한다. 스토리 몬스터 등록 시 사용되지 않는 리스폰용 모델 복제도 제거했다. 경로별 접근 판정과 처치ID는 기존 규칙을 적용한다.

## 검증

저장 어댑터의 응답 시간을 1.5초로 고정하고 목표 완료가 확정될 때까지 측정했다.

| 조건 | 0.113.12 | 0.113.13 |
| --- | ---: | ---: |
| 같은 프레임에 6처치 후 목표 완료 | 3.50초 · 2회 저장 | 1.50초 · 1회 저장 |
| 0.1초 간격으로 6처치 후 목표 완료 | 5.10초 · 3회 저장 | 3.10초 · 2회 저장 |

- `tests/campaign-save-latency.spec.lua` 58검사를 통과했다. 위 비교와 함께 콜백 재실행, 응답 유실, 저장 실패, 목표 거절, 중복 처치, 사망 페널티 순서, 퇴장 후 계정 잠금 해제를 확인했다. 기준 비교는 `git show a79e499c:src/server/Inventory/InventoryService.luau` 결과를 시험의 첫 인수로, `previous`를 둘째 인수로 전달해 재현한다.
- `python3 tools/prepare-campaign-combat-routes-native.py --runtime-only`로 만든 스크립트를 후보 Place의 격리 Studio에서 `run-in-roblox`로 실행했다. 생산 서비스의 진입·생성·격파·재개 경로를 실제 엔진 인스턴스, 가짜 플레이어·장비·저장 대역으로 실행해 839검사를 통과했다. 기준 Place에서는 같은 시험이 파티원 보상 등록 순서에서 실패했다.
- 경로 77,381검사, 부활 688검사, 난이도별 진행 4,621검사와 파티·인벤토리·성장·사망 페널티·경제·지역 준비 회귀를 통과했다. 소스 Luau 546개를 컴파일했고 빌드의 변경 런타임 소스 3개와 SHA-256을 대조했다. 별도 `campaign-combat-pacing.spec.lua`는 65행에서 `StoryLocked`가 발생했으며, 기준 커밋을 별도로 추출해 동일 실패를 확인했다.
- 고정 소스 `cb59b9cde41aa16c374f2dbd2236b2dff1fc2b1b`에서 `builds/0.113.13/TheLastThrone-0.113.13.rbxlx`를 만들었다. [빌드 명령과 SHA-256](build.json).
