# 엘프 기본 사격의 발사 확인과 화살 표시 동기화

2026-11-11 · TLT-005/008/032/084 · ENG → QA. 사용자: 클릭 기본 공격에서 손앞의 화살이 사라지고 공격이 없어진다는 신고. 상위 티켓 수용 완료가 아니다.

## 재현과 변경

- `K0BowMotion`은 서버 시간으로 계산한 windup이 끝나면 실제 발사 여부와 무관하게 손의 화살을 숨겼다. 격리0.103.10에서 실제 발사 패킷 없이 windup+0.02초를 렌더링하자 **화살이 사라짐**을 재현했다. [수정 전 실패](baseline.log).
- 서버가 `K0ArrowRelease`에 공격 순번·시작 시각·실제 발사 시각·발사체 순번을 게시한다. 클라이언트는 현재 공격 및 `K0ArrowVisual`의 같은 발사체와 일치해야 손의 화살을 놓는다. 두 속성이 역순으로 복제돼도 기다리며, 이전 공격/이전 발사체로 새 화살을 지우지 않는다. 발사 확인 전 취소된 공격은 가짜 발사 모션을 만들지 않는다.
- 새 프로토콜은 일반 엘프 발사에만 적용한다. 기존 Rapid Fire/고급 다중 펄스 확인과 구형 서버 호환 동작을 유지한다. 기본1.2초 주기·DEX 속도·피해·사거리·직선 조준·서버 명중 조건·장비/보상/저장은 변경하지 않는다.
- 실행 중0.103.5의 실제68발을 읽기 전용으로 관찰했다.54발은 실제 HP 감소,14발은 빗나감/대상 소멸이었다.8stud 미만19발은 **19발 모두 HP가 감소**했다. [집계/표본](active-session.json). 이 기록에서 신고된 피해 누락 자체는 재현되지 않았으며, 실제 발사 전 화살 표시가 사라지는 결함과 구분한다.

## 검증

`python3 tools/prepare-elf-confirmed-release-native.py --preview` 후0.103.10 격리 Place에서 후보 소스를 주입했다. 전체 런타임 Luau 컴파일을 확인했다. [후보 원본 로그](native-preview-2.log).

- 발사 확인9검사: 서버 미발사·지연·이전 공격·속성 역순·취소·근접·구형 서버 호환.
- 실제 서버 직선 발사558검사: 방향 잠금·명중/빗나감·공격당1발·새 확인 패킷의 공격/발사체 일치·30/60/144FPS.
- R6/R15 활/Blender 곡선4,890검사: 모든 기존 파지/시위/화살 자세 유지.
- 실제 서버 발사 시점/피해/DEX/속도873검사: DEX0/100/200/316 ×30/60/144FPS,12조건·실제 발사 표본 뒤 화살 표시 해제. 합계 **6,330검사 통과**.
- 추가 종합 `k0-basic-attacks-native`는 기준0.103.10과 후보 모두1,029검사 중 동일24케이스 실패다. 새 실패/해소0. 이 종합 검사를 통과로 보고하지 않는다. [기준 로그](basic-baseline.log), [동일 실패 비교](basic-comparison.json). 이번 수정의 피해/속도 검증은 위 실제 서버 전용 검사에 한정한다.

## 현재 세션·미검증·다음 담당

사용자의 현재 로컬 캐릭터에는 실제 서버 `K0ArrowVisual` 이벤트를 확인 정보로 바꾸는 임시 표시 어댑터와 새 모션 함수를 적용했다. 실제 공격/명중/피해 로직은 실행 중에 바꾸지 않았다. 이 어댑터는 해당 캐릭터/세션에 한정되며 영구 소스 빌드를 대신하지 않는다.

실제 피해 누락의 독립 재현, 게시 클라이언트·지연/저FPS 네트워크·다인·실기기·사용자 수용은 별도다. 기존 종합 검사24실패도 후속 QA로 유지한다. 다음 QA는 새 빌드에서 근접/원거리·이동 중 기본 공격·발사 직전 회피·연속 입력을 실제 조작으로 확인한다. Roblox 게시/릴리스 태그는 생성하지 않는다.
