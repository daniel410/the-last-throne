최신 로컬 빌드는 **0.30.5**, 입력 소스 `3a999498598bc252ae03e89961fb33abf8f3c52e`다. [버전별 산출물·해시](builds.json) · [실제 Player 관측](player-observations.json) · [TD 몬스터 10종 원본](td-monsters.json). 실제 Roblox 게시와 릴리스 태그는 수행하지 않았다. 확인된 게시판은 계속0.18.3이다.

## 연결한 플레이 경로

- 영웅 선택창에서 **ENTER DEEPWOOD** 또는 **TRAINING**을 고른다. 최신 사용자 요청에 따라 **트레이닝 입장은 로비에서만** 허용한다. 모험 중 미니맵의 입장 버튼은 제거했고 서버는 로비 밖 StartTraining 요청을 거부한다. 모험에서 RETURN TO LOBBY 후 TRAINING을 고른다. 서버가 목적지·선택 영웅·새 생명을 확정하며 기존 성장·아이템·퀘스트 기록을 초기화하지 않는다.
- 본편은 고블린 숲길 → 무너진 수레 공터 → 거목 전초기지 → 버려진 감시탑 → 오크 점령지 → 오염된 뿌리숲 → 검은 뿌리의 제단이다. 단서 조사·주민/에린 대화·경비전·장치·구조·기록·안정화·핵 분리·개인 복원 선택까지58개 목표 정의에 연결했다. 이 수에는 본편/숨은 퀘스트의 선택 행동도 포함한다.
- 원본 맵의 상대 위치·고도와 도보 연결을 사용한다. 기존 K0 시험장과 전초기지의 겹침을 없애기 위해 **캠페인 전체에 Z -2000 studs**의 런타임 이동을 적용했다. 문서의 상대 동선은 유지하며, 안전 SP7개와 선택3구역의 연결은 같은 모델 안에 있다.
- 숨은 퀘스트DW-Q1~Q4는 필수 성장/진입과 분리한다. Q2/Q3은 현장 단서와 전초기지 주민 요청이 같은 첫 목표 기록을 쓰며 Q4는 결말 이후 정찰병 요청/흔적으로 연결한다. 발견 전에는 저널에 숨기고, 세 선택 보스 뒤에도 구조/물자/조사·보고가 남는다. XP/Coins가 미정인 숨은 퀘스트의 완료 보상은0이며 보스/처치 보상과 구분한다.
- King Shaman은 고정 Goblin 증원,70% 임시 기둥2개 보호막,35% 바닥 오염 경고를 사용한다. 기둥은 순차 상호작용으로 해제한다. 선택 포로/오우거 구조는 필수가 아니며 최종 페이즈에 한 번 빈틈을 제공한다. Warlord는50%에 샤먼을 한 번 부른다. 패턴·HP·피해·인원 배율·경비 수는 시험값이다.
- **J / JOURNAL**은 완료·현재 목표·초회 보상과 체크포인트 재시도를 제공한다. 재시도는 현재 영웅의 새 생명을 안전 SP에서 시작하며 이미 확정된 목표/보상을 지우지 않는다. 별도 반복 실행ID·반복 퀘스트 지급은 아직 제공하지 않는다.

몬스터는 기존 TD 런타임의 Goblin/Cave Slime/Orc Warrior/Ogre/Goblin Shaman/Orc Warlord/Goblin King/King Ogre/Enraged Warlord/King Shaman 메시를 실제 복제해 별도 전투 리그에 붙인다.3조각/몸체만 있는 원본도 지원한다. [원본 런타임](../../../assets/shared/td-monsters/manifest.json)은 변경하지 않았다. 숲의 나무·거목·절벽·포탈도 [공유 레지스트리](../../../assets/shared/td-asset-registry.json)의 TD 원본을 복제해 사용하며 [환경 캡처](../../../assets/shared/td-deepwood-environment/manifest.json)에 현재 해시/바이트 동일성을 고정했다. TD 소스·라이브 데이터는 변경하지 않았다. 별도 Experience의 게시 자산 권한은 미검증이다.

최신 사용자 요청으로 HP 아래 목표 영역은 **HP와 같은248px 폭·왼쪽16px 정렬·완전 투명 배경**을 사용하며 TD 패널 아트/테두리를 제거했다. 글자는 배경을 가리지 않도록 외곽선만 둔다. 좁은 화면에서도 HP와 같은 스케일로 아래에 정렬한다. 실제 Elf Player에서 폭·정렬·배경 투명도1·패널 아트 없음을 확인했다.0.29.1 양방향 이동 관측은 역사적 증거이며 최신 로비 전용 계약과 구분한다.

대화창은 **배경85% 투명·TD 패널 아트 제거·텍스트 외곽선**을 적용한다. CONTINUE/결말 선택 버튼은 가독성을 유지한다. 초반1~3스토리에서는 현재 목표로 흐르는 바닥 화살표를 제공한다. 지역 사이에는 실제 연결 다리 중심을 경유하고, 목표 변경·이동·리스폰에 갱신하며 로비/트레이닝/사망/초반 완료에는 숨긴다. 최대20개 화살표(40파트)를 재사용하는 클라이언트 시각 안내다. 전체 환경 장애물 탐색이나 자동 이동 기능은 없으며 미술 배치 변경 시 동선 재수용이 필요하다. 실제 Player의 현재 목표 방향으로17개 화살표가 보이는 것을 관측했다.

상호작용은 커스텀 프롬프트로 영문 **F + HOLD**를 고정 표시한다. 한글 입력 상태에서 Roblox 키 문자열은 ㄹ이었지만 표시 F/HOLD와650ms F 입력 성공을 실제 Player에서 확인했다. 패드/터치는 별도 실기기 수용이 남는다.

## 개인 진행·지급 계약

`DeepwoodProgress`는 클래스별 영웅 계정 프로필의 `deepwood`에 선행·완료 목표·초회 영수증·개인 선택·Coins를 보존한다. 이전 프로필에 이 필드가 없어도 유효하며 최초 사건에서 추가한다. 게임 클라이언트가 피해·성공·XP·Coins를 제출하는 경로는 없다. 상호작용은 서버의 활성 생명/영웅·거리·선행 검사, 교전은 서버 등록 모델의 사망으로 처리한다. 주변 참여자 최대4명을 모으지만 파티 초대/동일 실행 리조인 계약은 아직 없다.

- 본편 초회 퀘스트 XP **1,173**, Coins **2,290**은 승인 정본과 일치한다. 각 구간140/163/62/200/247/227/134XP를 재계산하지 않았다. 완료 플래그·XP·Coins·장비/재료 대기는 **같은 계정 키의 한 갱신**으로 반영한다.
- 별도 처치 XP는 `8 + 2 × 적 레벨`, 보스5배이며 Coins는 `3 + floor(레벨/2)`, 보스10배다. 기존 XP 명령의 순번 중복 방지와 같은 갱신에 처치 Coins를 연결한다. 시험 처치 구성과 실제 성장 속도가 기획 예산을 그대로 재현한다고 주장하지 않는다. 프롤로그 미구현 상태의 Lv1 직접 진입도 목표 Lv5 출발 수용과 구분한다.
- 첫/다섯 스토리의 현재 클래스용 무기, 둘째의 방어구, 넷째/여섯째의 재료 묶음과 두 필수 보스 인장은 안정된 아이템ID로 미수령에 넣는다. 현재 장비 정의와 재료5개는 시험 선택이며 최종 등급/수량 승인이 아니다. 가방이 가득 차도 초회 보상을 유실시키지 않는다. 봉인핵·기록은 거래/소모 아이템이 아닌 이야기 플래그다.
- 거목 전초기지 안전 범위에서 성장 관리·미수령 수령과 계정 창고를 사용할 수 있도록 연결했다. 구 데이터 로드 실패를 신규0 프로필로 바꾸지 않으며 불명 저장은 같은 사건/영수증을 재조회한다. 강제 종료 전에 아직 확정되지 않은 사건·처치 대기열의 완전 복구는 후속이다.

[서버 거리/자격 검증 근거](https://create.roblox.com/docs/scripting/security/client-server-boundary)와 [UpdateAsync 재호출 계약](https://create.roblox.com/docs/reference/engine/classes/GlobalDataStore)은2026-10-29 공식 문서로 확인했다. 실제 게시 저장/재접속·동시 서버 장애를 이 문서나 단일 키 모형으로 통과 처리하지 않는다.

### 모바일 HUD 최신 요청

0.30.3에서 터치 화면의 아이템2·스킬5 버튼을 하단12px에 배치한다. Block/Dodge/Sprint는56px로 같은 크기의 왼쪽 한 열, Attack은64px로 오른쪽 위의 이전 Sprint 자리에 배치한다. 기본 JumpButton이 늦게 생성되거나 회전으로 이동하면 공격 버튼 하단과 점프 상단의 간격을 다시 계산한다. 가로폭600px 미만은 하단2줄로 접어 버튼 가독성을 유지한다. 화면 여백은 Roblox 안전 영역을 사용한다. GUI native 검사는 화면 크기를 주입한 대역이며 실제 모바일 터치/회전/실기기 수용과 구분한다.0.30.2의269개 검사 중 세로 화면 하단 폭1건 실패는 원시 로그로 보존하고0.30.3에서 좁은2줄로 수정했다.

최종0.30.3 GUI native 검사는 **279개 통과, 실패0**([원시 로그](0.30.3-ui.log)).1050×506,844×390,740×360,568×320,390×844의 터치 화면 크기를 주입해 하단 고정·동일 크기 세로 열·Attack 상단·점프 예약 영역 간격·폭을 검사했다.0.30.1의 지역 경로 native265개 통과와 분리한 결과다.

검사 로그는 내용과 실패를 보존하며 문서 커밋의 공백 검사에 맞춰 행 끝 공백만 정리했다.

사용자가 MCP를 재연결한 뒤 현재 `The Last Throne` 편집본에0.30.3 소스62개를 동기화했다. 기존 소스와 생성 캠페인은 `ServerStorage.BeforeDeepwood0303`으로 보존했다. 로컬 자산 읽기/MeshId 쓰기 도구 권한 제한 때문에 환경61메시는 `AssetService.CreateMeshPartAsync`로 고정된 TD MeshId를 불러오고 원본 XML의 변환·크기·색·텍스처·SurfaceAppearance·값 메타데이터를 적용했다. 에디터 동기화는 미게시 상태이며 고정 Rojo 빌드의 바이트 동일성과 구분한다.

### 0.30.4 최종 버튼 순서·하단

사용자의 마지막 “반대순서” 정정에 따라 위→아래 **Sprint → Block → Dodge**, 각각56×56px이다. 세로 열은 하단 안전 영역0px까지 내리고 Attack64px은 오른쪽 위를 유지한다. 데스크톱에도 같은 순서를 적용하며, 터치는 실제 점프 상단이 바뀌면 Attack만 위로 피한다.600px 미만의 하단2줄은 세로 액션 왼쪽으로 배치해 열의 하단 정렬을 유지한다.0.30.3의 Block/Dodge/Sprint 순서는 이 요청으로 대체한다. Play 중 실제 Player GUI에 이 순서·크기·하단0px 적용을 속성으로 확인했다.

최종0.30.4 고정 빌드 GUI native **289개 통과·실패0**([로그](0.30.4-ui.log)). 최신 순서·크기·안전 영역 하단 정렬과5개 주입 화면 크기를 포함한다. Studio 편집 소스에도 최종 HUD를 반영한 뒤 Play를 다시 시작했다.

### 0.30.5 Attack과 Sprint 높이 정렬

최신 사용자 요청으로 Attack은 Sprint 오른쪽 같은 높이(로컬 X90,Y0)에 고정한다. 비활성 TouchGui 아래에서도 JumpButton 자체 Visible=true가 남을 수 있어, 상위 ScreenGui.Enabled/GuiObject.Visible과 실제 사각형 겹침을 함께 검사한다. 입력 방식 변경에도 위치를 초기화한다. 활성 터치 점프와 실제 겹칠 때에는 Y를 유지한 채 Sprint 왼쪽으로 피한다. 실제 Player의 두 Play 창에서 Attack/Sprint 화면 Y값은 각각374.8889/374.8889,604/604로 일치했다. 기존 Play에는 위치 유지 가드를 추가한 시각 미리보기를 사용하며, 고정 빌드0.30.5는 수정된 HUD 소스를 포함한다. 실제 모바일 터치·회전은 미수용이다.

0.30.5 고정 빌드 GUI native **289개 통과·실패0**([로그](0.30.5-ui.log)). 기존5개 주입 모바일 화면 크기에 비활성 ScreenGui 아래 Visible=true인 JumpButton을 추가해 Attack이 Sprint 오른쪽 Y0에 남는지 검사했다.
