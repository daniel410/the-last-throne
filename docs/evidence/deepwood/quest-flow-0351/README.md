## 문제와 변경

이전0.33.5는 세부 활동을 확장했지만 본편과 선택 퀘스트의 역할/수주/보고가 섞였다. NPC 요청 노드가 첫 현장 goal과 같은 완료 함수를 호출했고, 조사 순서와 선택 구출의 기본 추적도 과도하게 선형이었다.

- **에픽 → 스토리=메인 퀘스트 → 국면/목표 → 활동**을 원고와 저널에 반영했다. Deepwood는7메인 퀘스트이며58목표/60활동을 별도 신규 퀘스트로 세지 않는다. 지역명과 다른 이야기 제목·목적·3국면·결과를 추가했다.
- **선택 퀘스트:** NPC나 현장에서 요청을 보고 ACCEPT/LATER를 고른다. 수주 상태가 저장되고 NPC 수주는 현장 목표를 완료시키지 않는다. 실제 현장 단서를 읽고 ACCEPT & RECOVER CLUE를 고르면 수주와 그 단서만 원자적으로 확정한다. 수행과 보고/완료가 구분되고 주민에게 돌아와 보고한다.
- **안내:** 기본은 본편 필수 목표다. 제단 포로 구출은 명시적으로 선택 추적한다. 초반 발견한 방수 기록은 본편2 후 보고할 수 있어 Waiting for story 2로 설명하고 그동안 본편을 안내한다.
- **조사:** 단서는 자유 순서로 수집하고 모두 모아야 결론을 확정한다. 이전 앞쪽 카운터 진행은 보존한다. 룬/호위/대화는 순서 계약을 유지한다.
- **저널:** MAIN STORY / SIDE QUESTS / CHRONICLE. 목적·현재 국면·필수 체크리스트, 선택 수주/보고 상태·담당자·고정 보상, 완료 결과·개인 답변을 분리한다. 보상0을 숨기지 않고 처치 보상과 구분한다. 모든 미래 이야기/숨은 퀘스트를 먼저 나열하지 않는다.
- **피드백:** 서버 완료 확정 후 이야기/선택 완료와 실제 XP/Coins를 알린다. 일반 대사는8초 후 닫히는 비차단 표시이며 선택은 직접 응답한다. 대상에서 벗어나거나 영웅/캐릭터가 바뀐 선택은 만료되고 설명 창 높이를 화면/텍스트에 맞춘다.

정본 XP/Coins·아이템·지역 잠금·영웅 성장·로비 전용 트레이닝과 기존 지도/길 안내 토글을 유지한다. 새 고정 보상이나 반복 지급 경로는 추가하지 않았다. 기존 완료/진행 선택 퀘스트는 플래그에서 수주 상태를 유추하며 초기화하지 않는다.

## 실제 Studio Player 입력·화면 확인

고정0.35.1에서 실제 Knight 생성/ENTER DEEPWOOD를 클릭하고, 정상 D/S 이동으로 첫 현장 방수 기록에 접근해 F로 조사했다. 진행/XP를 주입하지 않았다. `LATER` 뒤 서버 수주/플래그는 비어 있고 main0/Coins0이었다. 다시 F → `ACCEPT & RECOVER CLUE` 뒤 DW-Q1 수주와 waterproof_log만 true이며 main0/Coins0을 유지했다. 서버 상태는 실제 실행 중인 InventoryService를 읽는 임시 Script로 관측했고 QA 스크립트는 스스로 제거했다. [입력/서버 전후/GUI 문구](actual-player.json).

실제 렌더링에서 MAIN STORY의 이야기 목적·현재 국면1/3·필수 체크리스트·140XP/150Coins를 확인했다. SIDE QUESTS는 Supplies in the Marsh의 `Waiting for story 2`, `Supply Survivor`, 고정 보상 없음, `CONTINUE MAIN STORY`를 읽을 수 있게 표시했다. 해당 발견/수락 때문에 기본 HUD의 본편1/7·국면1/3이 바뀌지 않았다. 이는 단일 Studio 세션의 정상 입력 증거이며 게시 저장/모바일/전체 전투 완주 증거와 구분한다. 검증 후 Play와 소유한 테스트 실행기를 종료했다.

## 미검증/다음 담당

게시 DataStore 재접속·4인 수주/개인 선택·저속망/실기기·모든7스토리 정상 전투 완주와 재미 수용은 남아 있다. 주민의 고급 리그/표정·전면 서사 분기/지역 재건·정식 전직/반복 퀘스트와 다른 에픽의 런타임은 이번에 구현됐다고 하지 않는다. 답변 기록은 모두 다른 기계적 결과를 가진 선택이라는 뜻이 아니다. 고정 보상0 선택 퀘스트의 체감 가치도 실제 관찰 후 경제/아이템 기획과 검토한다.

QA는 초심자가 목적/필수 여부·다음 행동·보고 대상을 설명하는지 관찰하고 수주/보고 왕복, 사망/재접속 후 단서와 수주 보존을 게시 시험 서버에서 검증한다. 상위 티켓은 In Progress이며 이 조사/원형으로 Done 처리하지 않는다.
