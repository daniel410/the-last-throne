# 장비·아이템·가방·Dawnspire 창고 구현

2026-10-29 · TLT-011/028/041/043/046/047/052 부분 · ENG/DES 자체 검증 · 전체 티켓 수용 대기

사용자의 장비·아이템·가방·스토리지 구현 및 TD 룩앤필 요청을 우선 적용했다. [장비 UX](../../equipment-bag-and-storage.md), [공통 UI](../../shared-ui-and-look-and-feel.md), [기술 계약](../../production/engineering-plan.md)을 기준으로 구현한다.

## 제공 경로

- B 또는 BAG 버튼으로 캐릭터 가방을 연다. Equipment/Consumables/Materials 필터, 아이템 선택·비교, 장비 보기의 정확한 8슬롯, 고정 슬롯 자동 지정과 장신구 대상 선택을 제공한다. Organize에 검색·이름/레벨 정렬·잠금을 둔다. 잠금은 이동/장착을 막지 않으며 판매/분해 연결은 이번 범위에 없다.
- Dawnspire에 보관함과 F/패드 X/터치 ProximityPrompt를 배치한다. 서버는 살아 있는 선택 영웅·로비 경계·상자 거리 14 이내를 다시 확인한다. PC는 가방/창고 목록과 상세를 함께, 좁은 화면은 가방/창고 탭 및 목록→상세→뒤로 흐름을 사용한다.
- 가방 60·창고 120·물약 99·재료 999를 시험 설정으로 적용했다. 확정 밸런스·스토리 보상·판매 가격이 아니다. 캐릭터 생성 시 서버가 시험용 기본 무기, 교체 무기, 공용 방어구/장신구·물약·재료와 물약 5개의 대기 지급을 한 번 생성한다. 유료품·실상품·스토리 XP/Coins와 연결하지 않는다.
- 장착 보너스는 기존 전투의 공격 계수(추가 Power %), 피격 시 고정 Armor 차감(최소 피해 1), 최대 HP에 적용한다. 장비 변경은 현재 HP를 보존하거나 새 상한으로 줄이며 MP/스킬 쿨다운은 초기화하지 않는다. 같은 무기 유형의 상위 장비도 TD 원본 메시를 사용한다. 별도 방어구 모델/외형·제작·판매·상품/리셋권·전리품 분배는 후속이다.
- 물약은 가방의 지급 확정 수량만 사용한다. Z/C에 HP/MP 물약을 배정하고 가방에서도 사용한다. 창고·대기 지급은 직접 사용하지 않는다. 사용 요청의 같은 ID 재전송은 재소모/재회복하지 않는다. 리스폰에 물약 3개를 다시 만들지 않는다. 가득 찬 자원/MP 없는 직업에는 소모하지 않는다.

## 권위와 저장 경계

`InventoryRules`는 한 계정 원본의 영웅별 가방·8슬롯·공유 창고·대기 위치와 요청 결과를 순수 전이로 갱신한다. `instanceId`, 소유자·귀속, 정의/아이템 버전·원본 revision을 검사한다. 꽉 찬 가방 교환은 같은 칸을 사용하고, 해제는 빈 칸이 필요하다. 스택 이동은 전량 성공 또는 무변경이며 분할 인스턴스는 원 지급/부모 ID를 유지한다. 장착은 전투 중/적 주변/공격 후 5초 이내에 막고 안전 필드는 허용한다. 서버 확정 후 화면·전투 projection을 갱신한다.

현재 영웅 수가 클래스별 1명·총 4명인 시험판에 맞춰 영웅 식별자·최초 클래스·레벨 1과 아이템 원본을 같은 계정 키에 둔다. 정식 캐릭터 XP/Coins·스탯·전직·퀘스트 저장이나 다중 키 거래 구현으로 간주하지 않는다. 수령 대기는 거점에서만 수령한다.

`AccountStore`는 UpdateAsync 어댑터, 세션 토큰/증가 epoch·120초 lease와 30초 갱신, 직렬화된 변경 및 같은 ID 재시도를 사용한다. 읽기 실패·불명 쓰기·다른 서버 잠금·미지원 스키마는 빈 프로필로 덮지 않는다. 쓰기 응답이 불명하면 새 변경을 제한하고 같은 요청의 Retry를 제공한다. 일반 아이템 변경의 결과 96개를 보존하고 그 이전 재전송은 필수 revision/아이템 버전으로 거부한다. 결제/보상 원장에는 이 제한 캐시를 사용하지 않는다.

Studio는 실제 DataStore를 호출하지 않는 명시적 세션 어댑터다. 화면에 테스트 종료 시 초기화를 알린다. 게시 서버 경로는 독립 RPG Experience `10773575153`만 허용하며 신규 전용 `TLT_RPG_Accounts_v1_Test` / `account:<userId>` 키를 사용한다. TD 저장소·지갑·인벤토리는 읽거나 변경하지 않는다. 실제 게시 DataStore 저장·재접속·서버 경합 수용은 미검증이며, 이 작업은 Roblox 게시/접근권한 변경을 수행하지 않는다.

물약 효과는 서버가 현재 생명·자원 조건을 확인하고 수량 커밋 뒤 해당 생명에만 적용한다. 응답 유실 재시도는 저장된 작업과 생명 토큰을 확인한다. 확인 중 사망/종료가 일어나면 새 생명에 과거 회복을 전달하지 않는다. HP/MP 자체가 영속 프로필이 아닌 현 전투 세션인 한, 이미 확정된 사용 비용과 종료 전 회복의 영속 원자성을 주장하지 않는다.

## TD 자산

[런타임 원본 manifest](../../../assets/shared/td-ui-runtime/manifest.json)에 TD 커밋과 현재 SHA-256을 고정했다. `StatusWindowArtAssets`와 `UIIconAssets`는 바이트 동일 원본이며, RPG 동작은 별도 `TDInventoryTheme`/`InventoryGui`에서 처리한다. 원본 아틀라스의 남색·은색 프레임·금색 피팅·입체 버튼·닫기/클래스 아이콘과 Gotham 글꼴을 사용한다. 새 아이템 전용 그림이 없는 품목은 읽을 수 있는 타입 표식을 사용하며 생성 컨셉에서 아이콘/글자를 잘라 쓰지 않는다. Restricted 이미지의 게시 Experience 권한은 별도 검증이다.

## 검증 현황

- `lua tests/inventory.spec.lua`: 134개 통과. 네 클래스·8슬롯·요구 레벨/클래스·고유그룹, 가득 찬 교환/해제/이동, 99/999 스택 경계·부분 병합 롤백, 계정/캐릭터 귀속, 같은 요청/변조 요청, lease 탈취 후 구 서버 거부, 쓰기 후 응답 유실 재처리·재열기, 읽기 실패와 미래 스키마 보존을 확인했다. DataStore 어댑터는 장애 주입 모형이다.
- 변경 소스의 격리 Studio `tests/k0-basic-attacks-native.luau`: 481개 통과. 기존 전투와 분열 회귀, 장비 수치·현재 HP/쿨다운 보존·무기 미장착 거부·구 물약 경로 차단을 포함한다. Player 0·신원 모형·가상 시각이며 실제 입력과 구분한다.
- 소스 smoke 초기 시도는 기존 source-probe 생성기가 `src/character/Health.server.lua`를 누락해 실패했다. 기본 회복 대체 스크립트를 정본 프로젝트 매핑대로 포함하도록 생성기를 보완한 뒤 468개 통과했다. 이후 고정 빌드 검사를 별도로 기록한다.
- 소스 주입용 runner를 Play로 전환하면 플러그인이 다시 실행되어 기존 소스 보호 assert로 종료된다. 이 경로는 실제 Player 수용에 사용하지 않으며 고정 Rojo 빌드로 검증한다.

0.19.0 고정 빌드(`bc47ed023c997eebf9e49cc96cb51175d2d4931f`, SHA-256 `5dce98f09dffc03b860e856aa89335ebae38462d9f3ba43ce53bab2c2f0da7ae`)의 실제 Player 도구 입력으로 무기/몸통 장착·장신구2 선택·물약 1개 부분 수령·보관함 F 진입을 확인했다. 이 과정에서 정상 GetState에 Unavailable이 표시되는 Lua nil 조건식 오류와 초기 좁은 화면 배치가 남기는 미수령 0 문구를 발견해 수정했다. 같은 revision의 주기 조회가 상세를 재생성해 입력 포커스/수량을 잃을 수 있어 불필요한 재생성도 제거했다. 고정 수정 빌드 해시·최종 실제 Player 화면·입력 결과는 검증 후 아래와 [빌드 기록](../k0/build.md)에 추가한다.

다음 담당 QA/ENG/DES는 실제 게시 저장/재접속·동시 서버·실기기/패드 포커스·사용자 가독성·장시간 저장 크기를 검증한다. TLT 부모 티켓/G3 전체를 완료 처리하지 않는다.

0.19.1(`5b50ac23756eba4f2ae75136bfc8183dd498bedd`, SHA-256 `d694c0cd73d3c8b6bdd766a448600cbe3fbcea1eee6fa5199d161c0134f047a4`)에서는 정상 조회 오류가 사라지고 미수령 1이 정확히 표시됐다. 실제 F 입력과 텍스트 입력으로 철광석 수량 7을 지정하고 주기 조회 2.2초 뒤에도 포커스/수량이 유지되며 가방 17·창고 7로 전량 성공한 것을 확인했다. 다음 품목으로 바꿀 때 직전 수량이 재사용될 여지를 제거하고, 작은 화면 버튼 44px·탭 폭·제목/영웅 표시·하단 대비를 보완한 0.19.2로 최종 검증한다.

0.19.2의 [실제 Player 관측](0.19.2-player.json)과 [8슬롯 화면](0.19.2-equipment.png), [390×700 부모 영역의 배치 검사](0.19.2-compact-layout.png)를 보존했다. 실제 도구 입력으로 8슬롯 장착, 장신구 대상 선택, 보상 5개 수령, 철광석 부분 보관/다른 영웅의 부분 인출과 병합, 클래스 불일치의 UI/서버 거부를 확인했다. 서버 HP/사망을 통제한 물약 검사는 최대 자원 무소모·실제 회복과 수량 감소·같은 사용 재전송 무변경·리스폰 수량 보존을 확인했다. 메뉴 열린 상태의 공격/회피/스킬·이동 입력은 시퀀스·MP·위치를 바꾸지 않았다. QA 관측 Folder가 캐릭터 교체에 지워져 ScreenGui로 바꾸고 측정을 반복했다. 해당 회차의 리스폰 후 로비 귀환/아이템 등록 입력은 확인하지 못했으며 별도 결과로 남긴다.

작은 화면의 긴 필터명 줄바꿈과 1개짜리 물약의 Lv 표기를 고치고, 현재 로비의 선택 영웅에는 전투 자원이 없으므로 물약 사용을 막고 튜토리얼 진입 안내를 주는 0.19.3을 최종 확인한다. Z/C 등록과 장비/보관 관리 자체는 거점에서 가능하다.
