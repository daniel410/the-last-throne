# 주민 호위 진행 속도와 추적 개선

2026-11-20 · TLT-040/050 · ENG → QA · [스토리 진행 계약](../../production/engineering-plan.md#7-퀘스트체크포인트보상)

사용자가 기억한 영문 안내와 일치하는 주민 호위 공통 경로를 추적했다. 대표 구간은 DW-02의 `survivors`다. 기준 0.115.3에서 플레이어가 주민 곁에 있고 적과 저장 대기 시간이 없는 조건으로 37.42초를 재현했다. 기존 NPC 이동은 0.2초 간격이며, 목표 표식은 저장된 스냅샷을 사용했다.

- 활성 주민을 초당 12스터드로 서버 프레임마다 움직인다. 거리 이탈과 근처의 적, 저장 확인 대기에서는 주민이 멈춘다. 저장 결과가 불명인 동안 같은 주민을 유지한다.
- 같은 주민에게 구출 요청을 반복해도 이미 시작한 길을 다시 걷지 않는다. 시작 안내는 전투 화면의 짧은 알림으로 표시한다. 길 안내는 주민이 스트리밍돼 있으면 현재 위치를, 스트리밍되지 않았으면 마지막 서버 위치를 사용한다.

## 검증

- 같은 격리 Studio 시험에서 0.115.3의 37.42초가 0.115.4의 21.70초로 줄었다. 고정된 60 Hz 모의 이동 시간이며 플레이어 이탈, 적과 교전, 실제 저장 응답 대기 시간을 포함하지 않는다. 후보 14검사는 프레임 사이 이동, 실제 이동 위치를 따라가는 안내, 저장이 불명인 동안 동일 주민 유지, 근접 적 및 거리 제한, 순서대로 3회 저장과 완료 정리를 확인했다. [시험 스크립트](../../../tests/escort-pacing-native.luau).
- Studio의 DW-04 포로 구출·재개 12,654검사와 스토리 페이즈 414검사를 통과했다. 포로 구출 fixture는 구형 모델의 `Torso`에 의존하던 단일 검사를 현재 승인 모델의 표시 파트 전체를 확인하도록 고친 뒤 실행했다.
- Lua의 부활, 길 안내, 파티 스토리, 저장 지연 회귀가 통과했다. 별도 `campaign-expansion.spec.lua`의 초기 Gold 기대값은 기준 커밋 `c8a4a65d`과 후보에서 동일하게 실패했다.
- 0.115.4 단일 Place의 SHA-256과 내장 런타임 모듈 3개를 대조했다. [고정 빌드](build.json).

Roblox 게시 전이다. QA는 실제 Roblox 플레이 및 실기기에서 주민 움직임과 길 안내 반응을 확인한다.
