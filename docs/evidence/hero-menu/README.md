# 영웅·스킬·스탯 컨셉 UI, 가방 관리와 전투 HUD

2026-10-29 · ENG/DES/QA · TLT-005/028/041/042/043/046/047/052/084 부분 범위

## 변경과 근거

- 승인 v2 `07-hero-creation`·`05-hero-stats`·`06-skill-tree` 및 최신 시스템 시안 `04-hero-stats`·`05-skill-tree`·`06-hero-selection`의 픽셀을 열어 비교했다. 남색 셸·은색 테두리·금색 장식·4열 큰 영웅 카드·초상 주위 장비8칸·스탯 투자·원형 스킬 노드·상세창·편성 슬롯으로 재구성했다. 좁은 화면은 스크롤과 세로 배치를 사용한다.
- TD의 기존 영웅 초상과 프레임/설정 아틀라스를 재사용했다. 스킬 동작 가족의 방패/회전/도발/화살/도끼/물/비전 표시는 네이티브 GUI 도형이다. 컨셉 그림의 글자·숫자·노드를 잘라 사용하거나 업로드하지 않았다. 이미지와 완전히 같은 일러스트/성 전체 배경을 새 제작한 것은 아니다.
- 게임명은 **THE LAST THRONE**, 관리·귀환 안내는 **Hub**로 구분했다. Dawnspire 세계관 지역이나 별도 TD Experience는 변경하지 않았다.
- 스킬은 실제 공통3개+선택 계열13개를 표시한다. 연결선은 기본 동작 가족의 시각적 묶음이며 새로운 구매 선행 조건이 아니다. 습득·전직·강화·슬롯·최대5칸·기존 궁극기 편성 규칙은 유지한다. 임의 노드/무료 초기화/가짜 저장 버튼을 추가하지 않았다.
- 장착 성공 시 실제 장비 슬롯을 바로 보여준다. 전투 중 장착 제한은 유지하며 `COMBAT LOCKED`와 거점 귀환/거리·5초 대기 안내를 표시한다. 이번 사용자 화면의 거부는 `In combat` 상태였으며 거점에서 동일 빌드의 EQUIP 성공을 재현했다. 방어구별3D 영웅 외형 교체는 이번 범위에 없다.
- 가방의 DONE/정리 모드를 제거하고 그 위치에 Sort를 항상 표시한다. 잠금/해제는 상세창의 고정 버튼이다. 잠금은 버리기를 막으며 사용·장착·보관은 허용한다. 장착 장비도 잠글 수 있다.
- 버리기는 소유 영웅 가방의 잠기지 않은 아이템만 수량 확인 뒤 영구 삭제한다. 월드 드롭은 없다. 장착/창고/미수령 직접 삭제·다른 영웅·전투·잘못된 수량·구 revision을 서버에서 거부한다. 요청ID/아이템 버전/계정 fence와 기존 불명 저장 재시도를 사용해 중복 삭제를 막는다. UI 취소는 요청을 보내지 않는다.
- Unclaimed는 가방 위 별도 팝업이며 자체 X로 가방에 돌아온다. 가방 필터가 미수령 항목을 숨기던 문제와 직전 가방 아이템이 상세에 남는 문제도 수정했다.
- HP/MP 채움은 프레임 안쪽의 clipping 영역에만 그린다. TD 9-slice 비율을 바 크기에 맞추고 외부로 커지던 프레임 오프셋을 제거했다. 상태 패널 높이는 HP100/HP+MP145이며 자원 값/회복은 유지한다.
- Shield Bash는 방패 팔을 크게 앞으로 뻗고 몸통과 다리를 실어 미는 동작, 전방 링24조각+빛6개를 추가했다. 동일 공격 순번은 한 번만 재생하며0.55초 후 정리하고 최대12개 동시 효과로 제한한다. 명중 효과도 확대했다. 피해/범위/쿨다운은 그대로다.
- 사망은 관절 분해를 차단하고 전체 리그를0.7초에 걸쳐 앞으로 눕힌다. 죽은 몸의 상태 머신/충돌·쿼리를 정지하고 지형을 기준으로 착지한다. Respawning 동안 메뉴를 닫고 새 열기를 막아 시체를 가리지 않는다. 기존5초 리스폰·생명 fencing·새 캐릭터 자원/장비 복원을 유지한다.
- 오른쪽 위 긴 메뉴 버튼 대신 원형 미니맵을 넣었다. 실제 전투장의52개 정적 조각을 가볍게 복제한 ViewportFrame, 북쪽 기준 영웅 위치/방향·살아 있는 적 표식을 사용한다. 상단 기기 안전 영역에 배치하고 톱니바퀴 메뉴에서 영웅·가방·거점 귀환을 연다. H/B 키는 유지한다. 미구현 퀘스트 핀은 만들지 않는다.

## 실제 Player 관측

PlaceId0·격리 Studio·단일 Player·세션 어댑터에서 도구 입력으로 확인했다. 아래 0.26.1의 게임플레이 결과와 이후 미니맵/사망·가독성 변경을 구분한다.

- 0.26.1: Knight 생성→거점 EQUIP→UNEQUIP 표시와 슬롯 자동 노출, 튜토리얼의 `TLTEquippedWeapon=knight_weapon_fine`까지 확인했다. Sort 상시 표시, DONE 없음, 잠금 후 Discard 비활성화, 해제 후 확인 팝업을 관측했다. 실제 텍스트/확인 입력으로 철광석24 중7개를 삭제해17개가 남았다. [버리기 화면](discard-0.26.1.png).
- Unclaimed는 Materials 필터에서도5개 Small HP 스택을 별도 팝업에 표시하고 X로 가방에 돌아왔다. 0.26.0에서 실제1개 수령의 성공 응답도 확인했다. [최종 스타일 팝업](unclaimed-0.26.1.png).
- [영웅 선택](hero-selection-0.26.1.png), [스탯](hero-stats-0.26.1.png), [스킬](skill-tree-0.26.1.png)을 컨셉과 비교했다. 실제 확인 중 버튼 글자 가림, 궁극기 이름/설명 겹침, 좁은 단계 라벨 줄바꿈을 발견해 후속 버전에서 수정했다.
- Mage를 XP100의 **로컬 QA 서버 스크립트 지급**으로 Lv2에 올린 뒤, UI의 INT+1/Confirm으로 사용 가능 포인트4→3·INT15·최대MP107, 스킬 강화로 숙련2/4·SP1→0, Water Ball을 슬롯1에 편성해 슬롯2의 Mana Bolt와 교체되는 것을 확인했다. 정식 처치/성장 속도 수용과 구분한다.
- HP-only 상태 패널 높이100·HP 프레임 y51~79, Mage 패널145·MP 프레임 y96~124와 내부 clipping을 확인했다. [Mage 자원 화면](resource-frame-0.26.1.png). [실제 Shield Bash 입력/연출](shield-bash-0.26.1.png).
- 390px 부모 폭의 스킬 레이아웃에서 지도 폭338·상세 아래 배치·슬롯 폭96을 관측했다. 실기기 터치 검사로 표시하지 않는다.
- 0.27.0 미니맵52조각·영웅 표식 위치·기존 Hero/Bag launcher 숨김과 메뉴에서 가방 열기를 확인했다. 제어된 서버 사망에서 관절16→16·root 방향Y=-1·Respawning·로비 화면 숨김, 이후 HP250·새 root 비고정·Ready를 확인했다. 최종 버전에서는 사망 중 열려 있는 관리창도 닫으며 메뉴 아이콘/상단 위치를 보완했다.

최종0.27.3 실제 Play에서 `GetCoreGuiEnabled(Health)=false`, `DeviceSafeInsets`, 미니맵 로컬y8·지역명 로컬y4, 가운데 배경 투명도1·프레임 아트 없음·톱니바퀴 존재를 확인했다. [최종 HUD](final-hud-0.27.3.png)·[관측값 전사](player-observations.json). 기기 안전 영역 기준으로 Core UI 상단 여백을 제거한 좌표이며 캡처/플랫폼별 AbsolutePosition 원점과 구분한다.

최종 고정0.27.3 GUI는 [243개 통과](0.27.3-fixed-ui.json), 게임 코드가 동일한0.27.1의 실제 사망 리그는 [39개 통과](0.27.1-fixed-death.json)다.0.27.3의 [카메라 native 검사7개](0.27.3-fixed-camera.json)는 실제 Camera/Model 인스턴스에 수동 렌더 API를 호출해 거리 유지·투명도·다음 생명의 CameraType/Subject 복원을 검증했다. 기본 Play 카메라와 최종 사망 장면의 시각적 수용은 Studio 연결 종료로 최종 캡처를 완료하지 못해 미검증으로 남긴다.0.27.1의 이전 실제 사망에서 몸 관절 유지·메뉴 닫기와0.27.0의 리스폰을 확인한 증거와 구분한다.

0.27.2의 사망 카메라 보완 뒤0.27.3에 기본 CoreGui Health를 비활성화했다. 오른쪽 미니맵 아래의 긴 지역 판도 제거하고 지도 안에 작은 글자만 둔다. 월드의 적 머리 위 체력 표시는 실제 전투 정보로 유지한다. 기존203785492 자산 유형 경고 및 Studio MaterialManager 경고는 게임 오류와 구분한다. QA 명령이 잘못된 GUI 경로/없는 모듈 상태를 조회해 실패한 경우는 그 뒤 정상 경로로 다시 측정했으며 게임 코드 오류로 세지 않았다.

실기기/패드·다인/지연·모든 지형의 사망 착지·게시 자산/저장·재접속·사용자의 시각적 수용은 미검증이다. 다음 담당은 QA의 해당 수용과 사용자 비교 확인이며 상위 백로그 전체를 Done으로 바꾸지 않는다.
