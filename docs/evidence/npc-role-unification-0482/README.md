# NPC 대화·퀘스트·동행 중복 제거 · 0.48.3

- 작업: TLT-016/031/057/061/072/084 결함 수정 / ENG·QA 자체 검증. 사용자 요청은 같은 사람이 대화·퀘스트·동행 역할을 이어받고 같은 화면에 중복 등장하지 않는 것이다. 상위 티켓은 In Progress를 유지한다.
- 원인: 장식·대화·선택 퀘스트·Selene 캠프가 각각 모델을 생성했다. 조사 단계의 `kind=actor`에는 인물 대신 행동 제목이 들어 있는데도 기본 Tobin 외형 NPC를 만들었다. 개인 호위·Selene 동행이 시작돼도 기존 고정 모델/이름표/입력은 그대로 표시됐다.
- 서버 변경: NPCIdentity로 인물과 재사용 외형을 구분한다. NPCActors가 Eryn/Liora/Fen/Pip/Selene의 고정 역할을 동일 인스턴스에 등록한다. Selene 구조 보고와 캠프 선택은 같은 실제 TD nun 모델이다. 조사 행동 제목은 더 이상 주민으로 만들지 않으며, 이전 작성된 씬도 중복/행동 제목 모델을 정리한다. 서로 다른 구조 주민이 Tobin 외형을 공유한다고 같은 인물로 합치지 않는다.
- 퀘스트 연결: DW-Q2/Q3/Q4의 수주·보고·지도 좌표를 각각 Liora/Fen/Eryn의 실제 위치에 맞추고 영어 giver도 인물 이름으로 통일한다. 인물별 하나의 몸체를 공유하되 원래 목표/요청 앵커와 서버 조건은 유지한다. 퀘스트/영웅/보상 안정ID·완료 플래그·XP·Gold·성장·저장 스키마는 바꾸지 않는다.
- 개인 표시: NPCPresentation은 각 클라이언트에서 인물당 한 표현만 표시한다. 본인 호위·가까운 동행을 우선하고 동행 때 캠프 몸체/이름표/중복 입력을 숨긴다. 휴식 시 원래 캠프 인물을 복원한다. 보고 전 파티원은 자기 진행에 맞는 캠프 Selene를 계속 볼 수 있다. 다른 사람의 개인 호위 모델은 중복 표시하지 않는다. 서버의 개인 시도·지원/이동 앵커를 파괴하거나 다른 파티원의 진행을 옮기지 않는다.
- 동행 입력: 표시되는 Selene가 기존 캠프 내 Invite/Rest 역할을 이어받으며 개인 해금/선택 상태에 맞는 입력 하나만 노출한다. 캠프 거리·영입 조건·선택 쓰로틀·기존 지원 쿨다운/경로 이동과 인원별 설계 한도2/2/1/1은 유지한다. 실제 생성은 최신 승인된 파티 전체 상한1명으로 제한한다. 접속/스트리밍/캐릭터 교체 때 동일 인물의 표시를 다시 선택하고 모델 제거 시 복원한다.
- 근거: [캐스트·서사 계약](../../production/npc-cast-and-story-coverage-2026-10-31.md), [퀘스트 흐름](../../production/quest-and-story-flow.md), 사용자 중복 보고와 생성 코드의 직접 대조. 원인이 명확한 결함 수정으로 별도 외부 사례 조사는 생략했다.

## 빌드·수용

최종 고정 빌드/직접 관찰 결과는 후속 기록에 덧붙인다. Roblox 게시·실기기·실제 다중 클라이언트·사용자 관찰은 별도 수용이며 이번 수정만으로 완료 처리하지 않는다. 다음 담당 QA/사용자는 새 로컬 빌드에서 캠프 보고→초대→휴식 및 서로 다른 진행의 파티 화면을 확인한다.

최종 검사 중 기존2인 파티 경로가 Selene2명을 생성함을 추가 확인했다. `SeleneSupport.runtimeCap=1`을 서버 생성 한도에 함께 적용해 숨겨진 두 번째 지원도 없앤다. 2인 파티에서 실제1모델·추가 지원0회 검사를 추가하며 앞선0.48.2 빌드 파일은 보존하고0.48.3으로 재빌드한다.
