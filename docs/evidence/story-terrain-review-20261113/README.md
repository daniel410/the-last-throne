# 에픽별 스토리 맵 지형 리뷰

2026-11-13 · TLT-061/062/063/064/065 · QA/DES · 리뷰 완료, 수정·수용 미완료

가장 먼저 고칠 문제는 **도보 재배치 후 지역 조명 판정 불일치**다. 시각 구성에서는 큰 평지·작은 대표물·교차하는 길이 스토리별 장소의 차이를 약하게 만든다. 건축 원본34종이 존재하고 보행 검사가 통과했다는 사실만으로 지형·장소 표현을 수용하기 어렵다.

## 범위·근거·검증 조건

- 대상: 0.105.2, 입력 소스 `02790e2f653f2e62d26147740c766f5c8a3209d9`. 리뷰 시 HEAD `c3fbcb14`. 게임 소스 수정 없음.
- GW/FV/EC/HG는 [고정 Studio Edit 캡처34장](../regional-concept-map-20261113/index.html)을 전수 접촉 시트로 열람하고 GW-05/FV-07/HG-03을 원본 크기로 추가 확인했다. `captures.json`의 SHA256과 실제34파일이 전부 일치했다. FV-07 콘셉트도 직접 비교했다.
- DW는 [기존 Blender 연결 조감도10장](../deepwood-concept-map-20261112/index.html)을 참고했다. DW-03은 후속 [복구 실제 화면](../deepwood-map-restore-20261113/DW-03-restored.jpg)을 우선했다. DW 옛 화면에 보이는 타 지역 위치는 최신 도보 배치의 증거로 사용하지 않았다.
- 화면은 제작자가 지역 조명을 직접 적용한 Edit 캡처다. 클라이언트 자동 지역 판정이나 Play 카메라가 정상이라는 증거가 아니다.
- 현재 연결된 Studio는 0.104.25/0.105.1로 최신 고정 빌드와 달랐다. 이번에는 Studio 월드 생성·Play·카메라 변경·저장·게시를 수행하지 않았다.
- 변경 산출물은 이 보고서, 읽기 전용 재현 스크립트, 정적 결과 로그뿐이다. 사용자 미커밋 파일·VERSION·게이트 상태는 유지했다.

## 발견 사항

### R01 · P1 · 도보 재배치 후 27개 구역에 다른 지역 조명이 선택됨

**정적 재현 확정.** [DeepwoodAtmosphere.luau](../../../src/client/DeepwoodAtmosphere.luau)의 `Mood.start`는 Z좌표 -3800/-7600/-11200/-15000으로 지역을 분류한다. [CampaignOverland.luau](../../../src/shared/CampaignOverland.luau)는 현재 본편 순서로 에픽 전체 좌표를 이동하지만 이 분류는 기존 순서에 머물러 있다.

| 실제 지역 | 현재 중심 좌표에서 선택되는 프로필 | 불일치 구역 수 |
| --- | --- | --- |
| Gloamwood | FrozenVale | 7/7 |
| Frozen Vale | EmberCaldera | 10/10 |
| Ember Caldera | Gloamwood | 10/10 |
| Deepwood / Haunted Graveyard | 각 지역 프로필 | 0/17 |

재현: 저장소 루트에서 `lua docs/evidence/story-terrain-review-20261113/check-lighting.lua`. 실제 소스의 판정식을 추출해 현재44구역 중심에 적용했으며 **27불일치, 종료1**이다. [원본 결과](lighting-static.log). 프레임/조명 렌더를 재현한 엔진 검사는 아니다.

영향: 밤숲·설원·화산의 시간/색/안개가 서로 뒤바뀐다. Frozen Vale의 복원 조명도 실제 FV에서 `current=='FrozenVale'`가 되지 않아 적용 경로가 어긋난다. 지역 조명을 직접 적용한 기존 비교 화면은 이 문제를 검출하지 못한다.

다음 담당 ENG → QA: 재배치된 지역 데이터와 같은 원천으로 지역을 판정하고, 본편·선택 구역·네 경계 왕복에서 실제 Play 조명과 FV 복원 상태를 검증한다. 수정 전까지 기존 Edit 화면을 실제 플레이의 색·분위기 수용 근거로 삼지 않는다.

### R02 · P2 · 큰 전투 평지와 작은 대표물 사이의 규모 차이가 큼

**화면 관찰.** [FV-07 실제](../regional-concept-map-20261113/FV-07-fixed-detail.jpg)는 기둥과 지붕의 작은 정자이며, [콘셉트](../../../assets/concepts/2026-11-13-regional-epic-stories-v1/FV-07.png)의 궁전·단상·계곡으로 이어지는 장소 구조와 차이가 크다. [EC-02](../regional-concept-map-20261113/EC-02-fixed-detail.jpg)의 Forge City, [EC-07](../regional-concept-map-20261113/EC-07-fixed-detail.jpg)의 Great Furnace도 넓은 바닥 위 소규모 작업장/프레임으로 읽힌다.

콘셉트 전체 재현을 이번 구현의 완료 범위로 주장하지 않았다는 점은 기존 기록과 일치한다. 다만 최종 스토리 맵 품질에서는 대표 장소의 무게·진입 장면·공간 깊이가 부족하다. DW 복구 화면도 거목 외 넓은 빈 바닥과 고른 수목 반복이 강하다.

다음 담당 DES/ART: 구역별로 대표 실루엣·전경/중경/배경·높이 차의 제작 범위를 정하고 주요 접근 카메라에서 장소가 구별되는지 확인한다. 단순 건물 확대만으로 해결하면 기존 전투·목표 예약을 침범할 수 있다.

### R03 · P2 · 길과 바닥의 겹침이 자연 지형보다 강하게 보임

**화면 관찰.** [DW-03 복구 화면](../deepwood-map-restore-20261113/DW-03-restored.jpg)은 회색 직선과 밝은 굽은 길이 교차하며 중간에서 끊기는 조각도 보인다. [FV-06](../regional-concept-map-20261113/FV-06-fixed-detail.jpg)·FV-07은 넓은 청색 바닥 위 회색 경로와 흰 직사각 타일이 겹친다. GW-01/02에는 검은 띠 형태의 바닥 경계가 배경에서 강하게 드러난다.

결과적으로 이동의 주축과 부축보다 포장 패턴이 먼저 눈에 들어온다. 실제 길찾기 실패나 플레이어 혼란을 이번 검토에서 측정한 것은 아니다.

다음 담당 DES/ENG: 필수 길·귀환로·사건 접근로의 표시 관계와 교차부 마감을 정리하고, 도보 기능은 보존한 채 플레이 높이에서 다음 목적지가 읽히는지 검증한다.

### R04 · P2 · Gloamwood 거미줄의 굵기·밀도·연결 표현 부족

**화면·소스 일치.** [GW-05](../regional-concept-map-20261113/GW-05-fixed-detail.jpg)의 거미줄은 가는 삼각 격자 형태이며 양옆 지지체/수관으로 이어지는 부착 관계가 약하다. GW-01~07에서도 비슷한 형태가 반복된다. [Blender 제작 소스](../../../tools/build-regional-architecture-blender.py)의 `silk`는 외곽0.13, 방사0.09, 가로0.08stud 선을 사용한다.

사용자가 지정한 굵은 은백색 거미줄·뿌리 침식 감시성채의 인상보다 얇은 선 구조가 우세하다. 스토리별 대표물 이름은 다르지만 첫 접근에서 장소를 구별하는 효과는 약하다.

다음 담당 ART/DES: 거미줄의 연결점·두께·덩어리와 감시성채/뿌리의 실루엣을 실제 게임 카메라에서 확인한다. 회피·전투 시야를 가리는 배치는 피하고 현재 충돌/통행 계약을 유지한다.

### R05 · P2 · 대표 건축의 입구가 접근 화면에서 읽히지 않음

**시각 결함, 물리 원인은 미확정.** [HG-03](../regional-concept-map-20261113/HG-03-fixed-detail.jpg)은 촬영 방향에서 지붕과 석재 일부만 드러나 지하 통로의 입구·계단을 식별하기 어렵다. [FV-S2](../regional-concept-map-20261113/FV-S2-fixed-detail.jpg)도 낮은 상자 형태로 보이며 부두의 연결 방향이 약하다. 반면 제작 소스의 `KeeperCryptStair`에는 아치·벽·지붕·계단이 존재한다.

이 화면만으로 지형 매몰이나 실제 통행 차단을 확정하지 않는다. 카메라가 후면을 보거나 주변 지형이 전면을 가리는 경우를 나눠 확인해야 한다. 배치 코드는 목표 접근 방향 대신 구역 중심을 향하도록 회전하며, 어느 접근점에서 입구가 보이는지는 검사하지 않는다.

다음 담당 DES/ENG/QA: 실제 목표 접근 방향과 반대 방향에서 입구/계단을 촬영하고 바닥 높이·모델 하단·카메라 가림을 측정한다. 지형에 가려진 경우 접지·배치 수정, 후면만 촬영된 경우 수용 증거 보완으로 구분한다.

### R06 · P2 · 어두운 지역에서 바닥·건축·장치 대비가 약함

**Edit 화면 관찰.** GW-03/05, EC-02/07, HG-02/03/06에서 어두운 대표물과 바닥이 붙어 보이고 작은 노란 램프가 상대적으로 두드러진다. 광원 강도를 무조건 올리기보다 장소/길/상호작용 실루엣이 읽히는지 판단할 필요가 있다.

R01 때문에 실제 Play의 지역 조명이 이 화면과 다를 수 있다. 따라서 조명 수정의 첫 단계는 R01이며, 그 뒤 PC/모바일 밝기와 전투 VFX가 포함된 화면에서 재판정한다. 현재 캡처만으로 모바일 가독성 실패를 확정하지 않는다.

## 검증 결과와 한계

이번 독립 검토 결과는 **소스 판정27건 불일치 + 시각 품질 문제5종**이다. 기존 고정 빌드의 보행8방향·496목표 충돌 실패0 결과는 [기존 기록](../regional-concept-map-20261113/README.md)에 있으며 이번에 재실행하지 않았다. 시각 문제가 발견됐다는 이유로 그 결과를 통행 실패로 바꾸지 않는다.

기존 [미술 검사](../../../tests/regional-concept-art-native.luau)의 `distinct concept silhouette`은 모델 이름과 프로필 종류가 같은지 확인한다. 실제 실루엣 차이·입구 시야·장소 규모·클라이언트 지역 조명 일치는 확인하지 않는다. 검사 수를 이 항목들의 미술 수용으로 해석할 수 없다.

게시 클라이언트, 실계정/재접속, PC/터치/패드 실조작, 1~4인+AI 성능, 모든 전투 카메라, 실제 길 혼동·플레이 재미·최종 사용자 수용은 미검증이다. P0 통행 차단을 이번 리뷰에서 새로 입증한 것은 없다. G5/G7 완료 상태는 변경하지 않는다.

다음 순서: **ENG의 R01 수정 → QA 실제 Play 지역/복원 조명 확인 → DES/ART의 R02~R06 주요 접근 장면 재검토**. 사용자 지시로 철회한 DW-03 거목 작업은 이 리뷰를 근거로 다시 적용하지 않는다.
