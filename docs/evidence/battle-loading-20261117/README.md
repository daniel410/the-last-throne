# 배틀 입장 지역 지연 생성

2026-11-17 · TLT-040/087/battle-loading · ENG · 소스/격리 Studio 검증, 미게시

## 변경과 근거

사용자는 배틀 입장이 느리다고 보고했고, 입장할 에픽만 먼저 생성하는 개선을 요청했다. 기존 `previewWorld`는 에픽 N 입장 전에 1~N 지역을 순서대로 만들었다. 현재는 승인된 목적지 에픽 하나만 생성한다. 원인이 확인된 초기화 결함 수정이며 게임성·보상·입장 자격은 변경하지 않는다. [Roblox 공식 성능 안내](https://create.roblox.com/docs/performance-optimization/improve)와 [스트리밍 설명](https://create.roblox.com/docs/workspace/streaming)을 2026-11-17 확인했다. 기존 StreamingEnabled와 ServerStorage 자산 배치를 유지한다.

- 다음 에픽과 인접한 마지막 스토리 **DW-07 / GW-07 / FV-07 / EC-07**에 들어오면 다음 에픽 하나를 백그라운드로 준비한다. 현재 지역의 서버 접근 권한·실제 영역·안전 바닥·캐릭터 스폰 완료를 확인하며 입장 전송 잠금 중에는 시작하지 않는다. 경계 반경까지 걸어가거나 현재 스토리를 완료할 때까지 기다리지 않는다. 마지막 HG-07은 다음 지역을 요청하지 않는다.
- 미리 만든 지역의 진입 권한은 기존 스토리 완료 조건으로 계속 검사한다. 준비 작업은 저장 진도·보상·현재 임무·영웅 위치를 바꾸지 않는다. 파티의 중복 진입도 지역별 요청 하나로 합치고, 다음 지역이 준비됐다는 이유로 그다음 에픽까지 연쇄 생성하지 않는다.
- 이미 해금된 이전 지역은 왕복 길 쪽으로 실제 이동하여 기존 스트리밍 반경384stud에 접근할 때 준비한다. 이전 지역 준비에는 기존의 정지 스폰/캐릭터 교체/큰 순간이동 방지가 유지된다.
- 마지막 스토리 저장 확인 후의 준비 경로와 완료 지역 체크포인트의 필요 시 준비/재승인 경로는 유지한다. 선행 준비가 완료됐으면 재사용하고, 진행 중이면 동일한 직렬화 경로에서 기다린다. 공통 world 테이블·기존 스폰/노드/지역을 보존한다.
- 준비 중인 지역은 스폰 오브젝트가 일부 생겨도 진입할 수 없다. 지형 완료와 서비스 연결 완료(`readyEpics`)를 구분하고, 체크포인트·도보 접근·선행 로딩 모두 완료 상태를 확인한다. 미완성 길의 수학적 바닥은 안전 위치로 저장하지 않는다.
- 각 지역은 별도 `CampaignPreparing` 씬/테이블에서 생성하고 성공한 결과만 기존 world에 합친다. 실패 시 해당 시도의 모델·노드만 제거하며 기존 플레이 중인 지역과 동시 생성된 동료/교전 객체는 건드리지 않는다. 공유 Terrain의 결정적 쓰기는 재시도 때 다시 적용한다. 연결로 실패는 합쳐진 지역을 재생성하지 않고 미완성 연결로만 교체한다. 전역 실패 잠금을 제거하여 이미 준비된 지역은 즉시 재사용하고 실패한 지역은 다시 준비할 수 있다.
- 맵 체크포인트가 미준비 지역을 대상으로 하면 서버가 `Begin`을 보내 기존 여행 배경의 로딩 화면을 표시한다. 준비/자격 재검사 후 이동 성공 시 목적지를 전송하고, 클라이언트의 도착 위치·주변 스트리밍·바닥·외형·카메라가3프레임 안정되면 닫는다. 실패/자격 변경은 `Cancelled`, 사망·캐릭터 교체·로비 복귀도 닫고 입력 제한을 해제한다. 이미 준비된 지역에는 로딩 화면을 띄우지 않는다. 요청ID로 늦게 도착한 이전 응답을 무시한다.
- 현재 에픽의 장식/충돌/퀘스트는 완성된 뒤 입장한다. 이번에는 장식 생성 순서를 바꾸거나 캐릭터 준비·스트리밍·카메라·바닥 확인을 생략하지 않았다.

## 계측

서버 Workspace의 `TLTWorldBuildEpic`은 진행 중 에픽, `TLTEpic<N>BuildSeconds`는 지역 생성·창고·스토리 서비스 연결 시간을 기록한다. `[CampaignLoading]` 로그에도 남긴다. 실패 시 진행 중 에픽 값은 진단을 위해 남는다.

클라이언트 LocalPlayer의 `TLTArrivalDestinationSeconds`, `TLTArrivalAppearanceSeconds`, `TLTArrivalStreamedSeconds`, `TLTArrivalReadySeconds`는 로딩 덮개 설치부터 각 조건을 처음 관찰할 때까지의 누적 시간이다. 캐릭터가 교체되면 첫 관찰과 최종 Ready 사이에 재준비가 포함될 수 있다. 서버 시계와 합산하거나 Teleport 전체 시간으로 해석하지 않는다. 저장 데이터/서버 권한에 사용하지 않는 로컬 진단값이다.

## 초기 개선 검증

[측정 원본](measurements.json). 기준 소스는 `82cb6e22995775931b81f81bbdc627bb6741727f`, 동일 0.113.6 파일의 격리된 PlaceId=0 Studio 사본에서 시험했다. 원본 게시 창은 수정하지 않았다.

- 서로 다른 fresh Edit 사본에서 순차로 측정한 단일 샘플: 에픽5 입장용 기존1~5 생성 **32.099초 / 70,954인스턴스**, 에픽5 단독 **3.425초 / 10,570인스턴스**. 지역 생성 약89.3% 감소이며 네트워크·계정 읽기·클라이언트 다운로드·전체 입장 시간/P95를 측정한 수치가 아니다.
- 에픽5 생성 후4→3→2→1 역순 추가: 동일 world 테이블과 HG 스폰 유지, 최종 **70,954인스턴스**, 왕복4연결로 완성, 재생성으로 인스턴스가 증가하지 않음.
- 실제 Battle 역할 Play 서버의 `previewWorld('HG-01')` 경로: 에픽5만 준비, 스토리 Remote와 HG 창고 초기화 성공, 스크립트 오류0. 약3.312초. QA 전용 BindableFunction으로 내부 진입점을 호출했으므로 일반 계정 admission/실제 Teleport/캐릭터 입장 수용으로 간주하지 않는다. QA 훅은 종료 후 제거했고 저장소 소스에는 추가하지 않았다. PlaceId=0에서 자산 NetFail 경고가 있었으며 외형 다운로드 성공으로 보고하지 않는다.
- 전체545 Luau 소스 컴파일, 순수 Lua 접근 정책67·도착 덮개/계측326·완료 지역 체크포인트8,349·길 안내8,791검사 통과. 이 초기 개선의 엔진 테스트는 실제 admission 함수의 에픽1~5 단독 생성·동시 요청·실패와 왕복8방향의 미완성 길/지역 차단을 포함한다. 최종 엔진 검사 결과는 측정 원본에 기록한다.

후속 사용자 지시인 **인접 스토리 진입 시 선행 준비**는 [후속 검증](story-prefetch-validation.json)에 분리 기록한다. 접근 정책64·도착326·체크포인트8,349검사, 실제 RegionAccess와 비동기 스케줄러를 연결한 Studio36검사를 통과했다. 네 경계 모두 준비가 완료된 상태에서도 스토리 완료 전에는 차단되고 완료 후 통과한다. 입장 잠금·미완료 스폰에서는 준비0회, 반복 진입은1회, 대기 중에도 지역 검사 함수가 먼저 반환한다. 이36검사는 지형 생성기를 stub으로 대체했으며 새 물리 보행이나 전체 접속 성능 측정이 아니다.

재현: `lua tests/campaign-streaming.spec.lua`, `lua tests/arrival-loading.spec.lua`, `lua tests/checkpoint-travel.spec.lua`, `lua tests/campaign-navigation-route.spec.lua`. 엔진 검사는 최신 프로젝트 소스/자산이 적용된 **캠페인이 없는 격리 PlaceId=0 Edit**에서 `tests/campaign-loading-native.luau`를 실행한다. 일괄 생성은 task.spawn으로 실행하고 완료 결과를 확인한다. 후속 정책 엔진 검사는 같은 격리 환경에서 `tests/campaign-story-prefetch-native.luau`를 실행한다. 운영 Place나 사용자 작업 중인 씬에서 실행하지 않는다.

## 리뷰 결함 수정·체크포인트 로딩 화면

[후속 검증 기록](recovery-validation.json), [Studio 로딩 화면](checkpoint-loading.jpg). 코드 리뷰에서 발견한 미완성 스폰의 체크포인트 이동과 전역 실패 고착을 재현한 뒤 수정했다.

- 실제 `previewWorld` 함수: 실패 후 기존 지역 재사용, 재시도, 동시 요청 합치기9개 Lua 검사와49개 엔진 제어 검사 통과. 최초 Deepwood 시도의 실패/성공 후 모듈 캐시 정리2검사도 통과했다.
- 실제 지역 생성기 실패 주입20검사: 전체 지역 생성 후/합치기 전 오류로 부분 씬 제거, 기존 HG 스폰과 world/노드 테이블 및 동시 교전 대역 객체 보존, 연결로 실패 후 완료 지역 재생성 없이 복구. 에픽5 단독3.577초, 최종5개 지역·4연결로·기존 NPC32개,70,956인스턴스. 초기 방식과의2개 차이는 DW→GW/GW→FV 연결로의 장식 자식이다. 주요 지역/목표/활동/장식 컨테이너 수는 유지됐으며 이 수치만으로 물리 보행 수용을 대신하지 않는다.
- 체크포인트8,356검사: 스폰과 지형이 있어도 서비스 준비 전에는 대기, 대기 전 Begin, 완료 후 동일ID/목적지 Arrived, 실패/권한 변경/준비 미완료 시 Cancelled, warm 이동은 화면 이벤트0개.
- 로딩 컨트롤러17검사: 위치 복제/외형/바닥/GameplayPaused/3프레임 대기, 스트림 실패 재시도, 이전 요청 응답 무시, 사망/교체/로비/실패 정리. 기존 인접 스토리 준비64·초기 도착326검사도 통과했다.
- 실제 Battle 역할 서버의 생성기에서 에픽4 실패를 주입했다. 에픽5는 즉시 재사용됐고 에픽4 재시도 후 두 지역의 Ready 속성·기존 HG 스폰·두 창고·체크포인트 UI Remote가 정상 연결됐다. 격리 서버 내부 진입점 호출이며 실제 계정 admission을 대신하지 않는다.
- 547 Luau 소스 컴파일. 격리 Studio Client에서 실제 Remote Begin으로 승인 배경과 `LOADING...`를 표시했다. Arrived 뒤 외형 준비 false 동안 화면 유지, QA에서 true 조건을 제공한 뒤 닫힘/입력 해제, Cancelled도 닫힘, 예기치 않은 클라이언트 스크립트 오류0. 화면 시험은 실제 계정의 맵 클릭/진행을 사용하지 않은 격리 UI 시험이다.

재현: `lua tests/campaign-preparation.spec.lua`, `lua tests/checkpoint-loading.spec.lua`, 기존 체크포인트/도착/접근 정책 테스트. `tests/campaign-preparation-native.luau`는 캠페인이 없는 격리 PlaceId=0에서 실제 생성기에 오류를 주입한다. 시험 종료 시 교체한 함수는 복구한다.

## 미검증·다음 담당

빌드/Roblox 게시/태그는 이번 소스 개선 작업에서 수행하지 않았다. 게시 클라이언트의 실제 입장·재접속·4인 동시 이동·모바일 메모리·반복 측정/P95·물리 보행은 후속 QA이며 TLT-087/G7 완료로 표시하지 않는다. 서버 전체의 지역 생성 직렬화는 유지되므로 다른 지역을 생성 중인 서버에서는 새 요청이 기다릴 수 있다. 에픽1 자체 생성 시간과 캐릭터 자산 다운로드는 이번 최적화가 직접 줄이지 않는다. 다음 담당은 릴리스 및 실제 플레이 QA다.
