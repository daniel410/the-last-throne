# 몬스터 출현과 페이즈 전환 지연

2026-11-20 · TLT-040/087 · ENG → QA · 0.114.25 비공개 게시

- 첫 경로 교전은 목표가 저장돼도 32스터드 안까지 접근해야 활성화됐다. 후속 무리에 쓰는 38스터드 접근 기준을 첫 무리에도 적용했다. 서버의 원정 소속, 생존 상태, 준비된 지역, 목표 선행 조건은 계속 검사한다.
- 확인된 원정 목적지에서 아직 완료하지 않은 교전 목표 최대 두 개의 메시와 텍스처를 골라 입장 중과 플레이 중에 선행 요청한다. 같은 몬스터 리그를 생성 시에도 복제한다. 클라이언트는 메시와 이미지에 각각 맞는 참조를 사용해 12개씩 비동기로 요청하며, 요청 완료에 입장이나 전투를 연동하지 않는다. [Roblox ContentProvider](https://create.roblox.com/docs/reference/engine/classes/ContentProvider#PreloadAsync)
- 서버는 원정 처치 보상의 첫 미전송 묶음을 최대 0.65초 모은다. 그 사이 목표가 끝나면 처치ID와 목표를 같은 계정 갱신에 적용한다. 사망 페널티는 앞선 처치와 기존 순서대로 처리하고 처치 묶음 타이머를 기다리지 않는다. [선행 페이즈 개선](../story-phase-speed-20261118/README.md) · [이전 저장 묶음](../monster-spawn-latency-20261118/README.md)

## 검증

- 같은 저장 테스트에 응답 1.5초를 주입하고 실제 원정의 처치 6건을 0.1초 간격으로 등록했다. 마지막 처치부터 목표 확정까지 0.114.24 소스에서 2.60초와 2회 갱신, 0.114.25에서 1.50초와 1회 갱신을 측정했다. 느린 처치로 저장이 이미 제출된 경우에는 기존 확인 순서를 적용한다. 저장 테스트 62검사에서 중복 처치, 불명 응답 재시도, 종료 시 복구, 사망 순서를 확인했다. [저장 지연 시험](../../../tests/campaign-save-latency.spec.lua)
- 격리 Studio에서 목표가 저장될 때 영웅이 교전 지점에서 37스터드 거리에 있는 경우를 비교했다. 0.114.24에서 다음 무리가 생성되지 않았고 0.114.25는 주기 갱신 없이 생성했다. 39스터드와 여행 잠금 상태에서는 생성되지 않았다. 페이즈 349검사에 실제 리그 50종, 외형 선행 요청과 중복 제거, Roblox 메시·텍스처 표본 요청 성공을 포함했다. 교전 913검사와 에픽 선행 준비 36검사도 통과했다. [Studio 페이즈 시험](../../../tests/story-phase-speed-native.luau)
- Lua 입장 28검사, 사이드·본편 자동 시작 1,211검사, 교전 경로 77,381검사, 사망 페널티 3,575검사, 체크포인트 이동 8,356검사 및 원정·파티·부활 회귀를 통과했다. `battle-startup.spec.lua`의 지형 준비 대역과 `story-region-handoff.spec.lua`의 동기 준비 기대값은 기준 커밋 `54a35749`에서도 같은 위치에서 실패했다. 지역 준비 순서는 새 후보의 Studio 페이즈 및 에픽 선행 준비 시험에서 검증했다.
- 고정 빌드에서 변경된 런타임 소스 7개를 대조하고 Luau 소스 558개를 컴파일했다. [빌드 명령·커밋·SHA-256](build.json)
