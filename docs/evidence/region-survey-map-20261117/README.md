# 실제 월드와 게임 지도 대조

TLT-028/061~065/084 · 2026-11-17 · 지도 메뉴

0.113.0의 에픽 목록과 지역 상세에는 콘셉트 원화가 들어갔다. 상세 지도 위의 확대 건물 모형도 실제 지면을 가렸다. 로비와 전투 메뉴에서 두 요소를 제거하고 실제로 생성한 월드의 위쪽 카메라 화면을 지도 바탕으로 사용한다. 사건에 놓은 개인 핀은 해당 목표를 시작하는 위치를 가리킨다.

## 공명 광산

[월드와 상세 지도 나란히 보기](comparison.webp) · [사건을 선택한 게임 메뉴](field-menu.webp) · [44개 지역 촬영본](all-regions.webp)

왼쪽은 로컬 Studio 월드의 EC-03을 위에서 본 화면이다. 오른쪽은 로비 지도에서 같은 지역을 선택한 화면이다. 월드 화면은 캡처 직후 카메라의 모서리 좌표를 읽고 북쪽이 위로 오도록 180도 회전했다. 두 화면에서 같은 X/Z 범위를 잘랐다. 북쪽 구조 현장으로 들어가는 통로, 동쪽 승강장과 본 구역의 굽은 길을 대조할 수 있다. 오른쪽 숫자는 상호작용할 수 있는 표식이다.

## 제작과 검증

- 각 에픽을 독립 생성하고 44개 구역의 가로세로 비율, 주변 절벽과 연결로를 포함한 촬영 범위를 계산했다. Studio의 수직 하향 카메라로 실제 렌더 메시와 재질을 촬영한다. 각 지점에서 배경색을 바꿔 두 번 촬영한 뒤 빈 공간만 투명 처리한다. 도면에 시야각 10도의 원근과 촬영 시점의 조명이 반영된다.
- 확대 도면의 긴 변은 448픽셀이다. 에픽 전체도는 같은 촬영본을 축소한다. 동적 이미지 생성이 불가능한 클라이언트에서는 같은 픽셀의 색과 투명도를 읽어 축소 표시한다. 원본 지형이 바뀌면 격리 로컬 Place에서 `tools/export-atlas-relief.luau`를 실행한 뒤 `python3 tools/compile-atlas-plates.py <log>`로 촬영본을 갱신한다.
- Studio에서 새로 생성한 월드의 44개 도착점과 82개 사건 오브젝트에 대해, 화면 좌표를 월드 좌표로 역변환한 X/Z 오차가 모두 0.1스터드 미만임을 확인했다.
- 고정 빌드 0.113.1에서 지도 관련 Studio 자동 검사 10,470개와 위 좌표 검증이 통과했다. 체크포인트 메뉴 배치 36개, 파티 지도 96개, 단일 Place 역할 10개 및 도착 로딩 291개 검사도 통과했다. LFS 원본 도면 44개의 압축 데이터를 실제 빌드와 바이트 단위로 대조했다. [엔진 로그](native.log) · [빌드와 해시](build.json)
- 고정 빌드의 별도 복사본에서 자동 게임 시작을 끄고 실제 로비 지도에 시험 저널을 연결했다. Studio Play의 마우스 입력으로 Ember Caldera → EC-03 → 2번 핀을 눌렀다. Mine Rescue Staging 목표 설명과 지도 이미지 로드를 확인했다.
- 다음 담당은 QA와 플레이테스터다. 게시 클라이언트·터치/게임패드 실기기 판독성과 지역 간 식별·현장 길 찾기는 별도 수용 항목이다.
