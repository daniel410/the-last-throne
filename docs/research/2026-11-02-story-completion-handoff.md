# 스토리 완료와 다음 행동 안내

2026-11-02 · TLT-016/027/028/050/061/065/072/084 · Research/ENG → QA

사용자는 스토리 종료의 효과와 다음 진행 설명이 부족하다고 지적했다. 현재 완료 이벤트는 서버 저장 성공 뒤 도착하지만 클라이언트는8초짜리 작은 보상 알림만 보여주고 바로 목표를 바꾼다. 진행 여부·다음 위치·지원 종료를 한 화면에서 이해하기 어렵다.

## 사례와 제안 근거

- [ArenaNet, Introducing the Story Journal](https://www.guildwars2.com/en/news/introducing-the-story-journal/)의2014년 발표는 세계의 단일 목표 표식과 화면의 현재 스토리 요약·저널을 연결하고 에피소드 말미 보상을 구분한다. 2026-11-02 공식 문서를 확인했다. 역사적 UX 사례이며 현재 게임 직접 플레이나 인기/유지율의 근거가 아니다. 적용 해석: 완료 결과에서 다음 목표로 연결되는 버튼과 기존 금색 길잡이를 함께 사용한다. 다른 게임의 아트·문구를 복제하지 않는다.
- [Roblox UI animation/tweens](https://create.roblox.com/docs/ui/animation): TweenService로 크기·투명도를 전환하는 공식 방법. 2026-11-02 문서 확인. 적용: 새 효과 자산을 추가하지 않고 승인된 TD 프레임/버튼 위에 짧은 확대·금색 강조를 사용한다.

## 적용과 검증 기준

서버가 확인한 완료 이벤트에만 읽기 전용 카드를 띄운다. 완료 유형·스토리명·결과·확정XP/Gold, 다음 스토리명/지역/첫 목표와 실제 길잡이 연결을 표시한다. 에픽 끝은 별도 제목, 현재 구현된21번째스토리 끝은 후속 미구현 안내로 구분한다. 선택형 퀘스트는 메인스토리를 진행시킨 것처럼 표시하지 않는다. 셀렌느 지원권이 해당 스토리에서 활성화됐으면 종료·캠프 재초대/로비 구매를 함께 안내한다.

8초 자동 소멸 대신 사용자가 읽고 닫거나 추적 버튼을 누르게 한다. 전투 이동/메뉴·카메라를 강제로 잠그거나 자동 순간이동하지 않는다. 가로 모바일에서는 본문을 스크롤하며44px 버튼을 유지한다. 비용은 클라이언트 모듈과 이벤트 연결이며 서버 보상/저장/이동 계약은 유지한다. 위험은 전투 중 화면 점유와 긴 문구 가독성이다. 최소 시험:21스토리·2지역 경계·최종 구현 스토리·서브퀘스트·중복이벤트·지원 종료·세 화면크기의 실제 글자영역. 실제 사용자 문구 이해도와 터치/패드·전투 간섭 수용은 QA 후속이다.
