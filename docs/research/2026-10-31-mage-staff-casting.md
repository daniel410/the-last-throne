## 기존 문제와 구현

기존 `K0SwordVisual`의 Mage는 phase별 고정 어깨/지팡이 각도와 프레임 보간을 사용했다. 물/일부 광역 외의 주문이 같은 자세로 보였고, 주문 연출을 무기 관절 갱신보다 먼저 소비했다. 준비와 발사 사이 몸통·팔꿈치·손목의 연결, 주문 회복 중 다음 공격으로 이어지는 동작이 부족했다.

Blender MCP에서 오른손 WeaponSocket과 기존 나무 지팡이 치수의 편집 메시, R15 편집용 몸체를 제작했다. 다음6개 원본 Action을 만들었다.

| Action | 사용 |
| --- | --- |
| `Mage_staff_strike` | 물리 지팡이 기본 타격. 몸통을 비틀어 준비하고 앞쪽으로 휘두른 뒤 회수한다. |
| `Mage_arcane_bolt` | 마나/바람과 일반 원소 투사체·직선/연쇄 주문. 보조 손 응축과 전방 방출. |
| `Mage_water_orb` | 기본 물 구체. 더 둥글고 넓은 모으기와 양팔 방출. |
| `Mage_ground_area` | 중력·일반 지면/주변 광역. 지팡이를 높여 모은 뒤 앞/아래 방향으로 유도. |
| `Mage_ward` | 자기 보호/방벽. 지팡이를 세우고 보조 손을 펼친다. |
| `Mage_elemental_heavy` | 긴 지면 시전과 궁극기. 큰 상체 준비와 무게 이동을 사용한다. |

각 Action은12개 관절/무기 채널과 float 초점 속성,37 F-curve·259 keyframe을 가진다. 합계222곡선·1,554키다. 몸통과 목의 역회전, 어깨/팔꿈치/손목의 순차 움직임, 서 있는 경우에만 하체 무게 이동을 적용한다. 이동 중 하체 Animator는 기존대로 동작한다.

`K0MageMotion`은 Blender에서 추출한 공유 기울기의 cubic curve를 서버 승인 시작 시각으로 평가한다. 시전 종료 후 회복과 새 기본 공격은 이전 자세/각속도에서 이어지며 다른 클래스에는 적용하지 않는다. `K0MageFocus`는 지팡이 끝의 원소색 입자1개·짧은 PointLight1개만 사용하고 추가 물리 Part를 만들지 않는다. 방어·회피·사망·장비 해제·관절 소실은 충전을 지운다. 실제 마법 투사체는 기존 서버 승인 payload만 소비하며 무기를 갱신한 뒤 현재 WeaponTip 위치를 사용한다.

기존 Mage 기본 공격의 물리 판정, 기술 해금/피해/MP/쿨다운/사거리·서버 권위는 유지한다. 후반 기술은 형태별6개 가족으로 배정한 것이며32개 기술마다 독립 Action을 제작한 결과는 아니다. 모션캡처·손가락 리그·천 시뮬레이션·최종 Mage 외형 제작/수용을 완료한 것으로 보고하지 않는다.
