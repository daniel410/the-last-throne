# 모바일 메뉴·상세 상태 UI 개선 조사

2026-11-01 확인 · TLT-028/031/052/084 · DES/ENG → QA

문제: 가로 모바일은 미니맵의 UIScale이 메뉴 버튼까지 축소하고, 상태 화면은 전투 능력치·큰 초상/장비·포인트·스킬 효과를 길게 쌓는다. 기존 모바일 성장창 개선은 상단 여백을 줄였지만 정보 탐색 거리는 남아 있다. 승인 v2의 은색/금색 프레임·기존 아이콘을 유지한다.

공식 자료를 웹으로 확인했으며 직접 게임 플레이나 인기 순위 조사는 하지 않았다.

- [Roblox UI 위치·크기](https://create.roblox.com/docs/ui/position-and-size): 모바일 기본 조작이 화면 하단 모서리를 차지하며 휴대폰과 태블릿의 도달성이 다름을 설명한다. 메뉴는 상단 안전 영역 안에서 펼치고, 전투 HUD 축소에서 메뉴를 분리한다.
- [Roblox 화면 컨테이너](https://create.roblox.com/docs/ui/on-screen-containers): ScreenInsets로 안전 영역을 관리한다. 로비 메뉴에 기존 성장창과 같은 CoreUISafeInsets를 명시한다.
- [Diablo Immortal 비공개 베타 개요](https://news.blizzard.com/en-us/article/23734271/diablo-immortal-closed-beta-overview): 당시 전투 컨트롤러 지원과 메뉴 UI 지원 범위를 구분했다. 모바일 RPG의 비교 사례일 뿐, 현재 메뉴 배치나 조작을 검증한 자료로 사용하지 않는다. 우리도 네이티브 생성/배치와 실제 터치·패드 수용을 구분한다.

적용 가설: 모바일/짧은 화면의 메뉴를 2열·52px 버튼으로 배치하고 키보드 힌트를 줄인다. 상세 상태는 COMBAT / POINTS / GEAR / EFFECTS로 나누어 한 영역씩 보여 준다. 정보 선택을 초기 화면에서 바로 할 수 있고, 포인트 투자 전에 큰 초상을 지나갈 필요가 없다. 스탯 초안은 하위 탭 변경에도 유지하며 저장 중에는 중복 확정을 막고 같은 요청의 RETRY SAVE를 각 영역에서 제공한다.

비용/위험: 모바일에서 화면 구조가 달라지므로 회전·기기별 터치 수용이 필요하다. 메뉴 부모를 옮길 때 배틀 숨김과 PC 복귀를 회귀 검사한다. 280px/390px 세로, 700px 이상 가로의 영역 독립·가로 잘림·캔버스 경계·터치 크기를 엔진 검사하고 기존 스탯/메뉴/창 크기를 재검사한다. 실제 휴대폰/노치·터치 스크롤·사용자 관찰은 후속 QA다.
