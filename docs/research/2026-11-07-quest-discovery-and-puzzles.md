# 퀘스트의 탐색·퍼즐·발견 재미 개선 제안

2026-11-07 · TLT-001/050/057/061/084 · RESEARCH → 기획/디자인 → ENG → QA

상태: 사용자 실플레이 피드백에 따른 진단과 시험 제안. 채택·런타임 구현·재미 수용 완료가 아니다. 대상은 10~15세, PC/터치/패드, 솔로~4인이다.

## 문제와 확인 근거

사용자는 실제 플레이가 “네비를 따라가서 클릭”하는 반복이라 재미가 없고, 비전투 퍼즐·도중 아이템 발견·퀘스트 해결의 재미가 부족하다고 보고했다. 직접 관찰한 플레이 영상이나 사용자 수·구간별 측정값은 없다.

- `src/shared/DeepwoodQuestCatalog.luau`와 DW-01/02 시나리오에는 조사·추적·호위가 이미 있다. 활동 종류의 존재만으로 재미가 확보됐다고 판단할 수 없다.
- `src/server/Story/DeepwoodActivities.luau`의 `interactStep`은 거리·자격·단계/선택 검증 후 진행 저장을 요청한다. `update`는 trail/travel의 다음 지점에 10studs 이내로 도착하면 진행을 요청한다. 조사와 이동에서 플레이어의 판단을 요구하는 비중이 작은 구조로 해석한다. 모든 퀘스트가 동일하다는 뜻은 아니다.
- `src/client/DeepwoodNavigation.luau`는 지정 목적지까지 바닥 경로를 표시한다. 현장 정답까지 직접 안내하면 흔적을 읽을 이유가 약해질 수 있다는 가설이다. 실제 목표별 연결은 원형 제작 때 추가 확인한다.
- [기존 퀘스트 조사](2026-10-29-quest-structure.md)는 이미 단순 클릭 반복과 고정 보상 없는 선택 활동의 체감을 문제로 남겼다. 저널/목표 정리 이후에도 이번 실플레이 불만이 남았으므로 행동과 결과를 시험해야 한다.

## 추천하는 첫 시험: Deepwood DW-01/02

현재 임무의 목적과 안정 ID를 유지하면서 기존 활동을 대체하는 원형이다. 필수 클릭 수를 추가하는 방식은 피한다. 아래 장치·아이템·세계 변화는 모두 제안이다.

| 구간 | 플레이어 행동과 단서 | 피드백·결과 |
| --- | --- | --- |
| DW-01 수레 흔적 | 조사 구역에 들어가면 바퀴 자국과 부러진 가지의 방향을 보고 갈림길을 고른다. 단서는 어느 순서로 보아도 된다. | 맞는 길에서 수레 천 조각과 생존자의 목소리를 발견한다. 잘못 들어가도 짧은 거리에서 되돌아갈 수 있다. |
| DW-01 선택 옆길 | 나뭇가지에 걸린 보급대 천 조각과 상자 일부를 보고 옆길을 발견한다. 상자까지 정답 화살표를 미리 그리지 않는다. | 기존 보상과의 연결 여부를 검토해 실제 쓸 수 있는 보급품/장비 발견을 설계한다. “기록만 획득”으로 끝내지 않는다. 종류·수량·확률은 경제 검토 전 미확정이다. |
| DW-02 수레 구조 | 바퀴에 눌린 밧줄과 옆의 받침목을 보고, 받침목을 끼운 뒤 밧줄을 푼다. 잘못된 행동에는 바퀴가 기울고 생존자가 이유를 짧게 알려 준다. | 수레가 안정되고 생존자가 실제로 빠져나와 피난처로 이동한다. 클릭 순서 암기 대신 물체 상태가 이유를 보여 준다. |
| DW-02 구조 이후 | 구조한 주민이 피난처 등불을 켜고, 이동 가능한 짧은 통로를 열어 준다. | 도운 결과가 주변에 남는다. 본편의 다음 목적과 연결하고, 거대한 이야기 분기는 요구하지 않는다. |

비전투 아이템은 두 종류로 구분한다. 받침목 같은 현장 도구는 이 임무의 장치 상태이며 가방 용량을 소모하지 않는다. 전리품은 실제 소유 아이템으로 가방·미수령·저장 계약을 따른다. 기존 재료를 필수 퍼즐 비용으로 소모시키지 않는다.

다음 확장 후보는 Gloamwood의 운반대 흔적/정찰대 구조, Frozen Vale의 얼음 반사 장치, Ember Caldera의 냉각 수로, Haunted Graveyard의 비문/종소리다. 순서·보상·서사는 현재 승인본을 유지하며 첫 시험 수용 전 전 지역에 확대하지 않는다.

## 안내·입력·협동 계약 초안

- 기본 네비는 조사 구역 입구까지 유지하고, 구역 안에서는 흔적·소리·장치 상태로 유도한다. 기존 지도/바닥 안내 토글을 보존한다. 사용자가 요청한 추가 힌트에는 더 구체적인 위치/행동을 제시한다.
- 첫 원형의 문제 해결 목표 시간은 30~90초다. 30초 이상 진전이 없으면 힌트 버튼을 강조하고 자동 정답 실행은 하지 않는다. 이는 시험 기준이며 검증된 최적값이 아니다.
- 색에 더해 문양/형태와 짧은 영어 설명을 제공한다. 터치/패드는 같은 단일 상호작용으로 조작하며 정밀 드래그·동시 버튼 누르기를 필수로 하지 않는다.
- 네 클래스 모두 혼자 해결할 수 있어야 한다. 특정 클래스/유료 Selene·소모 재료가 필수 열쇠가 되어서는 안 된다.
- 파티에서는 한 명이 장치를 작동시키면 자격 있는 인근 참여자에게 결과를 함께 보여 주는 방향을 검토한다. 각자 필수 클릭을 반복시키지 않되 개인 선행·완료·보상 권리를 임의 복사하지 않는다. 현행 파티 계약 변경은 별도 설계/검증 대상이다.
- 서버가 거리·영웅·선행·장치 상태를 확정한다. 중복 입력·저장 실패·사망/재접속·동시 조작에서 진행과 아이템을 복구한다. 기존 완료 저장은 새 퍼즐 미완료로 되돌리지 않는다.

시험 영어 문구: `Find where the convoy left the road.` / `The wheel will fall. Support it first.` / `Show a hint`. 런타임 적용 시 기존 문자열 관리 방식에 맞춰 키/en-US 원문으로 등록한다.

## 보상과 비용

승인 XP/Gold·고정 아이템·기존 보유품과 진행을 보존한다. 첫 비교는 기존 보급품/보상 중 실제 연결 가능한 대상을 조사하는 것부터 시작한다. 추가 영구 아이템·재화가 필요하면 별도 보상 예산안을 작성하고, 원형에서 지급한 임시 물건을 실제 지급 완료로 보고하지 않는다. Soft Hide 신규 지급/복구는 금지한다.

제작은 흔적 탐색 하나·수레 상태 장치 하나·선택 보급품 발견 하나로 제한한다. 기존 환경 자산을 우선 검토하되 실제 적합성/사용 권한은 구현 때 확인한다. 주요 비용은 장치 상태 연출, 현장 단서의 가독성, 개인/파티 저장 복구다. 전 지역 고유 미니게임·대규모 분기·무작위 맵 생성은 보류한다.

## 검증과 다음 담당

이번 변경 범위는 이 조사 문서 한 파일이다. 문서/코드 근거와 공식 자료를 열람했으며 런타임·Studio·실기기·재미 비교 검사는 실행하지 않았다. 문서 검증은 `git diff --check`로 수행한다. 게임 버전·빌드·게시·티켓 완료 상태를 바꾸지 않는다.

다음 담당은 기획/디자인이다. 기존 활동과 일대일 대체표, 공간 단서, 보상 후보/예산, 실패·힌트/재접속 상태를 구체화한 뒤 ENG/QA에 인계한다.

초심자 5명 내외의 방향성 시험을 제안한다. 표본이 작으므로 일반화하지 않는다. 기존/개선 구간의 경험 순서를 섞고, 첫 10~15분에 다음을 관찰한다.

1. 5명 중 4명 이상이 외부 설명 없이 단서를 근거로 첫 문제를 해결한다. 힌트 사용과 소요 시간은 별도로 기록한다.
2. 최소 3명이 직접 단서로 판단한 순간 또는 선택 발견을 구체적으로 말한다. 상자 발견을 강제 목표로 바꾸어 이 기준을 맞추지 않는다.
3. 재미/반복감 5점 평가와 “다음 구간을 하고 싶은가”를 기존 흐름과 비교하고 막힌 지점을 기록한다. 시간 증가만으로 성공 판정하지 않는다.
4. 솔로/4인·터치/패드에서 조작/가독성을 확인하고, 실패/재접속·기존 완료 저장·중복 보상을 별도 검증한다.

재미가 개선되지 않으면 필수 퍼즐을 늘리지 않고, 단서의 명확성·발견 보상의 가치·행동 후 변화부터 재검토한다.
