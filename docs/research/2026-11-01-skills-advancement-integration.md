# 기술과 전직을 같은 화면으로 통합

2026-11-01 확인 · TLT-028/031/050/052/084 · RESEARCH/DES → ENG/QA

문제: 사용자가 ADVANCE 탭의 목적과 Training trial 문구를 이해하기 어려워했고, 별도 탭 제거 및 SKILLS 통합을 승인했다. 기술 미리보기와 전직 후보 선택이 분리된 기존 구현을 하나의 선택 상태로 연결한다. 기본 클래스·서버 조건·기술 데이터는 유지한다.

공식 비교: [Blizzard의 Diablo IV 플레이 방식 소개(2023)](https://news.blizzard.com/en-us/article/23938756/make-sanctuary-yoursplay-your-way-in-diablo-iv)는 클래스별 기술 선택과 플레이 스타일을 기술 트리로 설명한다. 이 역사적 소개는 최신 게임 UI나 전직 조건이 동일하다는 근거로 사용하지 않는다. 적용 판단은 기술 결과를 보면서 성장 방향을 선택하게 만드는 것이다. 우리 게임에는 두 계열과4단계의 기존 전직 규칙을 그대로 연결한다. 직접 게임 플레이·사용자 성과/유지율은 측정하지 않았다.

[Roblox TextLabel 공식 문서](https://create.roblox.com/docs/reference/engine/classes/TextLabel), [크기 조정 공식 문서](https://create.roblox.com/docs/ui/size-modifiers)는 텍스트 크기/영역 및 자동 크기 조정을 설명한다. 적용: 긴 영문 기술 이름은 글자를 무조건 축소하지 않고 TextService 측정으로 카드 높이를 확보한다. TD 아트를 유지하고 모바일은44px 버튼과 세로 스크롤을 사용한다. 네이티브 TextFits/스크롤 검사를 수용 근거로 삼고 실기기는 별도로 남긴다.

대안은 기존 ADVANCE를 설명만 보강하는 방식과 SKILLS 통합이었다. 사용자가 후자를 승인했다. 비용은 공유 선택 상태 연결·전직 카드·기존 두 탭/모바일 검사다. 위험은 단순 미리보기가 영구 계열 선택으로 오인되거나 잘못 저장되는 것이다. PREVIEW/SAVED PATH 표시와2회 확인,계열/스냅샷 변경 시 확인 해제로 대응한다. 새 서버 권한이나 무료 전직 변경권을 도입하지 않는다. 최소 검증은8계열×4단계·미달/거점 밖/저장 중 차단·실제 서버 규칙·기술 학습 표시·좁은 화면이다. 실기기와 정상 계정 저장은 다음 QA 대상이다.
