# Roblox 검격·마법 VFX 제작 조사와 적용

TLT-033/057/059 · 확인2026-11-15 · ART/ENG · 대상: 영웅128기술/기본 공격, 적146공격, 성녀3지원. PC·터치·패드, 솔로/파티를 목표로 하며 이 문서 자체는 구현·기기 수용 증거가 아니다.

사용자는 Roblox의 칼·마법 사례를 충분히 조사한 뒤 전체 전투 VFX를 다시 개선하도록 요청했다. 문제는 개별 아이콘의 주 형상을 만든 뒤에도 남은 곡선 이음새, 지나친 흰빛과 넓은 잔광, 같은 시간으로 사라지는 마법 층, 무기 잔상의 둔한 꼬리다. 새 아이콘·기술 특성·금빛 성속성/청색 번개 계약을 유지한다.

## Roblox 공식 제작 근거

모두2026-11-15 Creator Hub 본문/API를 열람했다. 문서 내용은 엔진 기능의 근거이며 아래 적용값은 우리 제작 판단이다.

| 공식 원천 | 확인 사실 | 적용 판단 |
| --- | --- | --- |
| [Trails](https://create.roblox.com/docs/effects/trails), [Trail API](https://create.roblox.com/docs/reference/engine/classes/Trail) | 두 Attachment의 이동 기록, Lifetime, WidthScale와 투명도 곡선으로 잔상을 만든다. FaceCamera는 시점별 노출을 바꾼다. | 실제 무기 소켓을 유지한다. 최신 구간은 선명하고 오래된 구간은 가늘어지게 한다. 시전/정지/중단/순간이동 때 기존 Clear 경로를 보존한다. |
| [Beams](https://create.roblox.com/docs/effects/beams), [Beam API](https://create.roblox.com/docs/reference/engine/classes/Beam) | 두 끝점과 Attachment의 축, CurveSize0/1이 cubic 곡선을 제어한다. Segments는 구간 수다. | 영웅의 연속 곡선에 접선을 붙이고 구간당3분할만 사용한다. 원래 끝점과 인스턴스 수를 유지하며 번개 꺾임/직선 조준선은 그대로 둔다. |
| [Particle emitters](https://create.roblox.com/docs/effects/particle-emitters), [ParticleEmitter API](https://create.roblox.com/docs/reference/engine/classes/ParticleEmitter) | 수명 중 크기/투명도를 바꾸고 방향·가속·Drag·Orientation을 제어한다. Emit은 버스트, Rate는 연속 방출이다. | 물은 낙하 물방울, 불은 상승 불씨, 얼음은 방향을 가진 잔편, 영혼/자연은 상승 흐름으로 나눈다. 최대 개수·속도·수명은 늘리지 않는다. |
| [Design for performance](https://create.roblox.com/docs/performance-optimization/design) | 저사양 실기기 기준을 정하고 낮음/높음 품질에서 확인해야 한다. Beam 분할 수는 낮은 품질에서도 유지된다. 에뮬레이터는 실제 메모리 측정을 대신하지 않는다. | 전역 예산을 유지하고 곡선의 추가 분할 비용을 기록한다. 넓은 반투명 잔광을 줄인다. 인스턴스 수 유지나 Studio 통과를 GPU/모바일 합격으로 보고하지 않는다. |
| [Weapons kit](https://create.roblox.com/docs/resources/weapons-kit) | 원본 무기 모델의 TipAttachment와 발사/시각 구성을 분리하는 예제를 제공한다. | 기존 실제 무기 끝 소켓과 서버 확정 발사 위치를 사용한다. 예제 전투 코드·피해·물리 구현은 도입하지 않는다. |
| [Laser beams 예제](https://create.roblox.com/docs/tutorials/use-case-tutorials/vfx/laser-traps-with-beams) | 같은 Beam을 폭/색/텍스처·움직임으로 다르게 구성하는 공식 예제다. | 같은 원시 도형이어도 재료/형상/시간이 달라야 한다는 제작 참고만 사용한다. 레이저 충돌/피해 코드나 신규 텍스처를 복제하지 않는다. |
| [Artist curriculum](https://create.roblox.com/docs/tutorials/curriculums/artist/work-with-particle-emitters) | 입자의 색·크기·속도를 조절해 같은 방출기에서 다른 외형을 제작하는 실습이다. | 원소별 움직임은 적은 입자에서 확인한다. 숫자를 늘리는 방식만으로 전체 개선을 판정하지 않는다. |

Flipbook은 프레임 패딩·메모리·기기 제약이 있다. 기존 승인 아틀라스/엔진 텍스처를 재사용하고 신규 무료 모델·플러그인·외부 스크립트는 설치/실행하지 않는다. 엔진 Explosion은 물리 영향이 있어 장식용 생성 대안에서 제외한다.

## 제작자 원본 시연과 실제 관찰

독립 ART가 여러 제작자의 칼·미사일·마법·접촉 사례를 원문 이미지/영상에서 확인했다. [사례별 출처·시각 관찰·한계](2026-11-15-roblox-vfx-artist-observations.md)와 기계 판독 기록을 정본으로 사용한다. 검색 도구가 DevForum의 JavaScript 확인 페이지를 반환할 때 정상 브라우저로 공개 원문을 열었다. 영상 정지 프레임/미리보기를 직접 게임 플레이나 성능 프로파일로 보고하지 않는다.

ENG도 [Crescent 제작자 원문](https://devforum.roblox.com/t/crecent-sword-slash-effect/1113871)의 완성 이미지와 두께·불투명도·부분 삭제에 관한 설명을 확인했다. 완성 이미지에는 빈 중심과 두께가 다른 평행한 호, 가늘게 풀리는 끝이 보인다. 정지 이미지로 발동 시점·실제 칼 궤적 동기를 판단하지 않았다. 얇은 날/넓고 옅은 잔류를 분리하는 원리만 가져온다.

## 채택·보류와 최소 실험

| 결정 | 변경 | 비용/위험·검증 |
| --- | --- | --- |
| 채택: 연속 검격/궤도 | 같은 끝점의 cubic 접선을 사용한다. Wind의 세 리본도 접선을 공유한다. 검격 주면/날과 수평 물마루도 기존 전체 면 예산 안에서 분할을 늘린다. | Beam 인스턴스는 같지만 해당 구간의 분할은1→3이다. 굵은 면은 국소 Part 수가 늘며 전역160/터치80 상한은 같다. 유한 좌표·접선 연속·원래 끝점·프레임 이력 독립성을 엔진에서 검사하고 전후 동일 시점 화면을 비교한다. |
| 채택: 원소색·빈 중심 | 주 선의 끝이 전부 백색으로 바뀌는 것을 줄이고 넓은 Hero 잔광 폭을3.8→2.6배로 줄인다. 적의 약한 잔광도 더 빨리 옅어진다. | 어두운 배경의 과도한 감쇠 위험이 있다. 낮/밤·품질 양끝과 각 아이콘의 주 형상 보존을 ART가 확인한다. |
| 채택: 접촉의 시간 층 | 작은 중심광은0.075초, 색을 가진 섬광은0.14초, 옅은 잔류는0.24초 안에 소멸한다. 실제 서버 타격 펄스 뒤 장식만 바꾼다. | 캡처 지연으로 짧은 효과를 놓칠 수 있어 yield 전 정확한 상대 시점에 기하를 동결한다. 정적 동결은 입자 전체 시간축 검증을 대신하지 않는다. |
| 채택: 무기·투사체 꼬리 | 실제 칼/도끼/적 무기와 적 마법 Trail을 선두가 선명하고 꼬리가 가는 형태로 통일한다. 기존 각 무기의 발동 구간·수명은 유지한다. | 새 소켓/타격점을 만들지 않는다. 실제 이동을 포함한 Trail 시연과 중단/돌진 회귀를 검사한다. |
| 채택: 원소별 잔편 | 불·물·냉기·영혼/자연·독/흙의 방향/Drag를 구별한다. | 개수·속도·수명은 증가하지 않는다. 적 링 위험띠의 별도 안전 반경 검증 입자는 이 공통 조정에서 제외한다. |
| 채택: 지원 흐름 | 성녀의 가는 곡선 link가 손→수신자로 흐른 뒤 짧게 사라지고 기존 회복/정화/보호 주 형상을 남긴다. 지팡이 focus 입자는 작은 생성→정점→소멸을 갖는다. | 지원 수치·라벨·범위·지속 판정은 유지한다. 수신자 이동/사망·stream-in·반복 이벤트·회수 검사는 기존 회귀와 연결한다. |
| 보류: 큰 마법진·화면 백색화·다층 구름·신규 외부 모델 | 원문에서 화려해 보여도 전체 기술에 공통으로 추가하지 않는다. | 캐릭터/바닥 가림·겹침 비용·권리/실행 범위를 키운다. 승인 원본과 절차형 형상을 사용한다. |

검증 산출물은 별도 [구현·전후·엔진/빌드 기록](../evidence/roblox-vfx-polish-20261115/README.md)에 연결한다. QA는 영웅128종/전 펄스, 적50종146공격/12링 안전 반경, 지원3종과 혼합 예산·회수를 확인한다. 게시 클라이언트·실제4인 전투·저사양 기기·사용자 최종 미술 수용은 그 환경의 증거가 있을 때만 통과시킨다. 다음 담당은 ART의 화면 재판정과 QA의 실기기/다인 수용이다.
