# 파티 공유 스토리·최종 보스 웨이브 조사

2026-11-04 · TLT-016/050/061/084 · RESEARCH/ENG → QA

사용자 관찰: 딥우드 보스를 첫 무리에서 먼저 처치하고 일반 적만 반복해서 싸우며, 멀티에서도 각자 목표를 수행한다. 요구는 선행 적 웨이브 → 마지막 보스, 파티 공동 진행과 인원별 적 수/전투력 증가다.

2026-11-04 공식 자료 열람(직접 플레이 아님):

- [Dungeon Quest 공식 Roblox 설명](https://www.roblox.com/games/2414851778/Dungeon-Quest-RPG-Adventure): 친구와 던전을 통과해 보스에 도달하는 협동 흐름을 소개한다. 공동 퀘스트 저장·정확한 스케일링 계수는 확인하지 못했다. 인기 지표 없이 비교 사례로만 사용한다.
- [Minecraft Dungeons 공식 출시 소개](https://www.minecraft.net/en-us/article/minecraft-dungeons-launching-may-26): 최대4명이 함께 적 무리와 싸우며 구간을 진행하는 구조를 설명한다. 계수/현재 실제 플레이 체감은 미검증이다.
- 기존 [인원 보정 조사](2026-10-31-party-enemy-scaling.md)의 HP 중심 접근을 재사용하되, 이번 사용자 요청으로 적 수/공격력도 증가시킨다.

적용 해석: 같은 서버에 있는 것보다 같은 검증된 원정 runId를 공유하는 것이 파티 자격에 적합하다. 한 명이 서버가 검증한 행동을 수행하면 동일 원정의 목표/조사/대화 선택/호위 체크포인트를 각 영웅의 기존 멱등 저장 경로로 전달한다. 개인 Selene 구매·동행 선택은 공유하지 않는다. 보스의 체력 단계 기믹은 유지하고 증원은 선행 웨이브로 옮겨 처치 뒤 새 일반 적이 나오지 않게 한다.

시험안: 일반 적6/8/10/12복제, 동시 수 기존 스토리 상한+0/1/2/3(최대12), 기존 HP계수 유지·공격력1/1.1/1.2/1.3배. 원래 적1개의 처치 보상을 복제 수로 분할해 개인 총XP/Gold를 보존한다. 비용/위험은 최대12개체 부하, 공유 선택의 파티 합의, 파티 내 저장 응답 지연과 도착 시간 차이다.

최소 수용: 모든 딥우드 보스가 선행 무리 소진 후 마지막에 한 번 등장, 이후 새 적0; 한 명이 끝낸 필수 스토리의 파티원 공동 완료; 타 원정 오염0·중복 지급0·저장 재시도; 동일 장비1~4인 교전 시간/사망/프레임 측정. 수치는 시험값이며 게시 클라이언트/실기기 밸런스 수용은 후속이다.
