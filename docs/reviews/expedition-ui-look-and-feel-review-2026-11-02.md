# 난이도 설정·배틀 진입 UI와 TD 룩앤필 리뷰

2026-11-02 · TLT-028/029/041/050/052/061/073/084 · DES/ENG 리뷰 · 판정: 후속0.62.5 코드 수정·격리 검증 / 실제 클라이언트 QA 후속

현재 UI는 TD 버튼 원본과 남색·금색 계열을 재사용하지만, 난이도를 판단하고 파티 상태를 확인한 뒤 출발하는 화면으로는 수용하기 어렵다. 주 행동의 위치, 출발 가능 상태, 난이도 비교 정보와 시각 위계를 먼저 고쳐야 한다. 사용자가 요청한 범위는 리뷰이므로 게임 코드를 수정하지 않았다.

기준은 최신 공통 UI 지시, [TD 공통 UI 계약](../shared-ui-and-look-and-feel.md), [승인 v2](../../assets/concepts/2026-10-27-shared-ui-v2/approved-baseline.json)의08원정/02로비/04배틀 메뉴, 실제 TD 공유 자산이다. 승인 원정 그림은 직접 열어 비교했으며 그림의 한국어·예시 레벨·수치는 런타임 사양으로 채택하지 않는다. 로비/배틀 기본 메뉴·아이콘 배치는 유지하는 범위의 상세 창 개선을 제안한다.

> 후속 수정: [0.62.5 구현·검증·한계](../evidence/expedition-entry-ui-20261102/README.md). 아래는 수정 전 발견 기록이다.

## 발견 사항

### UI-R1 / P2 — 기본 화면에서 출발 버튼이 보이지 않는다

`src/client/ExpeditionView.luau:14`, `:38`~55, `:67`~68. 난이도4행, 안내, 임무 변경, Solo, 파티/준비/출발이 하나의 세로 스크롤에 쌓인다. LobbyPanelLayout은 데스크톱 높이를510으로 제한한다.

실제 Studio 측정에서 PC scroll 높이는332인데 Solo는 y426/h48로 완전히 아래에 있었다. 모바일844×390은 scroll188이므로 처음에는 Easy와 Hard 일부만 보이고 시작 버튼은 더 멀어진다. 전원 미준비4인 파티/Hell 상태에서 Launch는y882다. 임무 목록을 펼치면 시작 버튼은 그 모든 항목 뒤로 더 밀린다. 스크롤로 접근 가능하지만 현재 선택·조건과 출발 버튼을 동시에 확인하기 어렵다.

수정: 하단에 선택 요약과 출발/준비를 고정한다. 스크롤은 임무 목록과 상세에 한정하고4난이도는 PC 가로·모바일2×2 등으로 재배치한다. 창을 키우거나 글자를 일괄 축소하는 방식으로 해결하지 않는다. 수용: PC/844×390에서 첫 화면에 현재 임무/난이도와 주 행동이 보이며 긴 임무 목록을 열어도 고정 영역이 유지된다.

### UI-R2 / P2 — 파티 입장 불가와 미준비를 출발 버튼에 반영하지 않는다

`src/client/ExpeditionView.luau:60`~68, `src/server/Network/ExpeditionService.luau:53`~62. 서버는 조회한 본인 영웅의 임무 자격만 보내고, 파티 멤버 행에는 레벨/main/ready만 있다. UI는 forming 상태의 방장이면 전원 미준비·다른 멤버 레벨 미달이어도 START PARTY ADVENTURE를 활성화한다. fixture4인/Hell/전원미준비 상태에서 Active=true를 확인했다.

서버 freeze/startRun의 최종 검사는 남아 있어 입장 우회는 아니다. 문제는 누가 어떤 조건을 충족해야 하는지 출발 전에 알 수 없고, 최종 거부 뒤에도 부족한 멤버가 표시되지 않는다는 것이다. `LobbyText.NotReady`의 “same next main story”도 선택 임무 방식과 맞지 않는다.

수정: 서버가 파티 각 멤버의 현재 선택에 대한 자격/원인과 전체 launchAllowed를 계산해 제공한다. 해당 행에 “Reach Lv80” / “Clear Insane first” / “Waiting for Ready” 등을 표시하고, 출발은 전원 자격·도착·준비 충족 시 활성화한다. 서버 최종 재검사는 유지한다.

### UI-R3 / P2 — 난이도 선택에 필요한 임무·보상·위험 요약이 없다

`src/client/ExpeditionView.luau:34`~46. 현재 요약은 `DW-01 · Easy` 같은 코드/모드와 레벨뿐이다. 임무 이름은 임무 목록을 펼쳐야 보이며, 보상은 “Gold, equipment and enhancement materials”라는 일반 문장만 있다. HP/피해 차이, 반복 보상과 초회 보상 구분, 선택한 모드의 재료/장비 상자 진도, 이전 난이도 선행을 비교할 수 없다. Hell 무제한 반복도 해당 선택의 설명에 없다.

수정: 선택된 임무의 영문 이름/지역/목표, 최소레벨·선행, 초회/반복 보상을 요약한다. 현재 시험 수치를 서버 규칙과 연결하고 미승인 최종 밸런스처럼 쓰지 않는다. 장비가 모든 난이도에서 같은 티어 성능이라는 계약도 설명한다. 임의의 “Hell 전용 고성능 장비”나 과거 컨셉 수치를 추가하지 않는다.

### UI-R4 / P2 — 빠른 난이도 변경 후 출발 입력이 응답 없이 버려질 수 있다

`src/client/ExpeditionView.luau:21`~22 및 `src/server/Network/ExpeditionService.luau:243`. 모든 action은 즉시 전송하고 버튼/pending을 잠그지 않는다. 서버는 마지막 요청으로부터0.35초 이내의 요청을 상태 응답 없이 return한다. Configure 직후 Solo/Ready/Launch를 빠르게 누르면 두 번째 요청은 실행되지 않지만 하단에는 “Please wait...”가 남을 수 있다. 평상시 GetState 갱신은10초 간격이다.

코드상의 무응답 경로를 확인했으며 실제 클라이언트 연속 탭은 미검증이다. 수정: Configure 응답까지 적용 중을 표시하고 출발을 잠그며 서버가 승인한 선택을 확인한 뒤 활성화한다. 요청 제한 거부에도 상태/Busy 응답을 주거나 클라이언트 전송을 묶어 무응답 대기를 없앤다. 단순히 서버 제한을 제거하지 않는다.

### UI-R5 / P2 — TD 자산은 있으나 원정 상세 화면의 시각 위계가 부족하다

`src/client/ExpeditionView.luau:21`, `src/client/HeroMenuChrome.luau:5`~13, `src/client/TDInventoryTheme.luau:78`~94. 실제 렌더에서 모든 주요/보조 버튼이 같은 파란 TD shellDetails를 사용했다. START PARTY ADVENTURE, LEAVE PARTY, REFRESH PARTIES의 강조가 같고, Easy 선택은 `[X]` 문자로만, 잠긴 모드는 같은 밝은 파란색과 LOCKED 문구로 표시된다. 잠긴 난이도를 눌러 이유를 확인하도록 하는 동작 자체는 허용할 수 있지만, 열린 선택과 잠긴 선택의 외형은 더 분명해야 한다.

승인 원정 화면의 지역 카드·대표 이미지·현재 목표·영웅/파티 초상·하단 녹색 출발, 공통 선택 체크/잠금/닫기 문법이 거의 없다. 전체 창은 TD panel 원본 아트 대신 코드로 만든 선/그라데이션/다이아몬드 장식이며, 승인 그림의 조형·금속 프레임과 동일하다고 평가할 수 없다. 반면 버튼 원본 아틀라스는 TD 사본과 해시가 같고 실제 로딩됐으므로 “TD 자산 미사용”은 아니다.

수정: 승인된 TD 프레임·제목판·닫기·선택 체크·잠금·영웅 초상을 우선 재사용한다. 출발만 녹색 primary 셸로 강조하고 나가기/새로고침은 보조 스타일로 낮춘다. 선택은 원본 체크/선택 테두리, 잠김은 회색/잠금 아이콘과 구체적 조건으로 표시한다. 의미 없는 난이도 새 아이콘을 임의 생성하지 않는다.
