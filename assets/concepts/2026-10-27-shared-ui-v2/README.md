## 공유 방식과 외형

- TD의 실제 status-atlas·menu-atlas·battle atlas를 먼저 시각 확인하고 공통 보드의 직접 입력으로 사용했다. 이후 모든 화면에 같은 보드를 참조 입력으로 사용했다. 메뉴용 영웅/파티 도상은 기존 TD 아이콘을 참조하고 플레이어 초상은 승인된 hero-icons4종을 우선했다.
- 은색 바깥 레일·금색 모서리 피팅·남색 내부·동일한 닫기/확인/선택/잠금/저장 상태를 일관된 방향으로 재구성했다. v1의 화면별로 다른 장식/버튼 모양을 줄였다.
- 원본 UI 이미지7개와 승인된 초상4개, 유지한 기존 이미지18개를 [출처 기록](source-manifest.json)에 모았다.29개 모두 원본과 SHA256/바이트 일치를 확인한다. 검토용 스냅샷이며 실제 런타임 원본의 분기를 뜻하지 않는다.
- 로비 초안에서 플레이어 XP초상이 장식용 메뉴 도상으로 바뀐 부분과 보라 마법사 대신 엘프가 들어간 부분을 수정했다. 배틀의 XP를 로비와 같은210/500·청색으로 맞추고, 기사 돌파베기 아이콘을 불꽃색에서 청색 검격으로 수정했다.
- 영웅5개 시트·로비/지역/스토리3개·몬스터10종은 다시 그리지 않았다. TD 모델·이미지와 동일 인물의 외형을 유지하는 기준으로 보존한다. 성녀는 지원NPC, 플레이어는4클래스다.

## 화면 규칙 검토

- 스탯 화면: 힘·민첩·지력·체력, 사용 가능4포인트, 레벨업마다4P.49/13/9/21·공격력·HP는 표시 예시이며 초기값/공식을 확정하지 않는다.
- 스킬 화면: Lv28 누적27P, 공통7P+강철8P=15P, 잔여12P. 액티브3+궁극기1과40/60/80 잠금 단계를 표시한다. 연결선·효과의 구현 기준은 기획 명세다.
- 배틀: Lv10 기사 HP/스태미나/서약과 공통3기술, Lv15 궁극기 잠금. 공통 MP 정책은 변경하지 않는다. 배틀 메뉴를 열어도 전투는 지속되며 거점 전용 재분배는 잠긴다.
- 영웅 생성: 최초4클래스 선택이며 다른 클래스로 전직하는 UI가 아니다. 원정 메뉴의 계속하기는 화면 흐름 초안으로, 모든 스토리를 포탈/별도Place로 만드는 확정이 아니다.

## 생성과 구현의 구분

생성 컨셉의 아이콘/텍스트는 원본을 참조해 재현한 그림이며 픽셀 단위로 동일한 스프라이트나 실행 가능한 UI가 아니다. 실제 구현에서는 [공유 레지스트리 스냅샷](shared-asset-registry-snapshot.json)의 기존 이미지ID·영역 정의·메시/재질 원본을 연결한다. 이번 작업은 공통 모듈 추출·UI 연결·3D 제작·Roblox 업로드/게시를 실행하지 않았다.

[전체 생성 기록](generation-manifest.json)에11회 생성 중 최종9개 선택과 참조 경로를 기록했다. 각 PNG 옆에 최종 프롬프트 `.prompt.txt`가 있다. 수정 전2개는 이력으로 보존하고 갤러리에서는 최종안만 표시한다. [최종 목록](catalog.json)은27개 파일과 해시를 제공한다.

모든 생성 결과는 시각 확인했으며 파일·해시·로컬 링크·갤러리 참조·JavaScript 문법을 정적으로 검사한다. 앱 브라우저의 로컬 file URL 정책으로 갤러리의 브라우저 렌더 검증은 수행하지 않는다. 실제 작은 기기·접근성·입력·자산 로딩·TD 회귀 검증은 후속 구현 단계다.

## 사용자 승인 기록

2026-10-27 사용자가 v2 컨셉을 승인하고 저장을 요청했다. [승인 기준 기록](approved-baseline.json)에 최종UI9개의 파일/해시와 프롬프트 위치를 고정했다. 이후 UI 제작과 수정은 이 컨셉 방향을 기준으로 비교한다. 표시 예시 수치나 실제 구현/기기 품질이 함께 확정된 것은 아니다. 이미지·프롬프트·원본 출처·ZIP은 기존 경로에 보존한다.
