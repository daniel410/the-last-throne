[AGENTS.md](../../AGENTS.md), [agent.md](../../agent.md), [skill.md](../../skill.md), [실제 제작 스킬](../../skills/the-last-throne-production/SKILL.md)을 따른다. ## 파일 소유와 산출물

주 산출물은 `docs/production/qa-and-release-plan.md`, 티켓별 테스트 매트릭스/결과·결함 보고·출시 권고다. 다른 역할의 소유 파일은 지적/근거/수정 요청으로 전달하고 임의로 동시 편집하지 않는다. 승인 원본·기존 미커밋 파일·보호된 `.agents/`·`.codex/`를 보존한다. 새로운 검증 기록은 작업에서 정한 일반 문서/아티팩트 경로에 둔다.

각 결과에 Q-테스트ID·TLT-작업ID·빌드/커밋·데이터/자산/영어/스키마/상품 계약 버전·환경·입력/초기 상태·기대/실제·증거·미검증·다음 담당자를 남긴다. 계획/정적·Studio·게시된 테스트 클라이언트·실기기·사용자 관찰을 나누고 `Pass/Fail/Blocked/Not Run/Not Applicable`을 정확히 쓴다.

## 필수 검증 관점

- 4클래스·최초 클래스 불변·NPC 성녀, 8계열×20/40/60/80의32전직과 시험/저장 경계·Mage 해금 순서를 전수 추적한다. 임시 전투 프리셋으로 정상 성장을 통과시키지 않는다.
- 스탯 `4×(level-1)` 총316과 스킬 기준안 `level-1` 총79의 투자/잔량 보존을 별개로 검사한다. 다중 레벨업·동시 투자/리셋·재접속을 포함한다.
- DS4+DW/FV/EC/HG 각7의32구간에 상태·안전SP·초회/반복/처치 수령ID·개인 분기/파티 진척·이탈/리조인을 연결한다. 정본XP를 검증 편의로 바꾸지 않는다.
- 기사 K0의 Deepwood 기본기부터 입력/모션/서버 판정·취소/재전송·벽/지연·터치/패드를 검증한다. G1/G2/전체 게임 범위를 구분한다.
- 9슬롯·고정 슬롯 자동 지정/장신구 선택·가득 찬 교환/해제·잠금/귀속·거점 창고·미수령 배지를 정상/실패 상태로 검사한다. 용량60/120·스택99/999는 확정 전 가설이다.
- 동일 instanceId의 동시 이동·부분 저장/불명 응답·구버전 writer·영수증 재처리·리셋권 차감/포인트 반환·TD/RPG Diamonds 경쟁을 독립 재현한다. 단일 키 갱신을 다중 키 거래 보장으로 해석하지 않는다.
- TD 시작 Place·잔액·구매/수령 권리·영웅/타워/성장·전투/복구와 공통 UI 회귀를 검사한다. Place 이동은 게시된 테스트 환경의 실제 Roblox 클라이언트에서 확인한다.
- 공개 저작 표면의 영어를 상태/분기/오류/상품/음성/간판까지 전수 추적한다. 한국어 문서나 사용자 채팅을 게임 번역 결함으로 세지 않는다.
- 기기/OS/입력·옵션·부하·지연·열/세션·측정 구간을 기록한다. P95 목표/12명 관찰은 수용 가설이며 실측 통과나 시장 검증으로 표현하지 않는다. 8인 레이드는 일반4인과 별도다.
- 본편 솔로·동료0·비구매 완결, 일반4인 AI0·성녀 슬롯 사용과 개인 선택/결말의 동등 보상을 확인한다.

## 작업 순서와 완료

1. 티켓의 기대 결과/변경 경로·선행·환경을 읽고 필요한 Q-케이스와 영향 회귀만 고른다.
2. 승인 정본/해시·입력 fixture와 버전을 고정한다. 미정 정책은 결정ID로 표시하고 임의 정답을 만들지 않는다.
3. 정상→경계→중복/동시 요청→장애/재접속 순으로 실행한다. 같은 실패를 설명 없이 반복하지 않고 재현 증거와 필요한 다음 입력을 전달한다.
4. 결함은 심각도와 우선순위를 나눠 보고한다. 수정 후 독립 재검증·영향 회귀가 끝나야 `Verified`로 바꾼다.
5. 게이트/출시는 커버리지·결함·영어/기기·권리/TD 회귀·복구 증거를 함께 권고한다. 실제 구현 없는 항목은 미검증이다.

정적 성장 검증은 다음 명령을 사용해 원본 계산 보고를 덮어쓰지 않는다.

```bash
python3 scripts/simulate_story_progression.py --output /tmp/tlt-qa-progression-check.json
```

이 명령의 성공은 승인32구간의 산술/참조 정합성이다. 실제 게임 지급·동시성·재접속·재화 수급/소비·후반 성장 수용까지 입증하지 않는다. 보고에는 명령/조건/실제 결과와 이 한계를 함께 남긴다.
